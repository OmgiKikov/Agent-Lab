# Agent Lab

Agent Lab прогоняет настоящего AI-агента на реальных диалогах и отвечает в понятном виде:

- какая у агента оценочная accuracy на сохранённом validation set;
- где именно он ошибается;
- какие причины повторяются;
- какие результаты не удалось измерить;
- что изменилось после следующей версии агента.

## Как это работает

```text
репозиторий + требования + реальные диалоги
  → validation set из 15 разговоров
  → запуск настоящего агента
  → accuracy + отдельные unknown/invalid
  → человеческое объяснение причин
  → сохранение и повтор после исправления
```

Ожидания берутся из требований владельца, а не из текущего кода, старых ответов агента или поля `outcome`. MVP оценивает prompt/RAG по наблюдаемому ответу; инструменты и backend state — следующий этап.

Карточки бизнес-сценариев — внутренний формат воспроизводимости. Карточка фиксирует цель, факты клиента, начальную реплику и критерий успеха. Дальше симулятор отвечает на текущие вопросы агента, а не подставляет старые реплики по порядку. Пользователю не нужно вручную вести карточки или размечать каждый результат.

До запуска исключаются полностью замаскированные реплики и случаи, которым нужны отсутствующие данные клиента. Если измеримых случаев меньше 15, Lab сохраняет меньший набор и причины исключений. Ожидания, источники и готовность видны в разделе **Сценарии**; подтверждение запуска показывает принятую ревизию, объём и бюджет. Старые scripted-наборы автоматически не переписываются: их нужно пересобрать из логов.

### Наблюдение RAG

Адаптер может вернуть вместе с `reply` фактически переданные модели фрагменты:

```json
{"reply":"Возврат оформляется через терминал.","retrievals":[{"source":"refunds.md#return","content":"Возврат оформляется через терминал.","score":0.9}],"retrievalsComplete":true}
```

`retrievalsComplete:true` означает полный контекст именно этого ответа; `retrievals:[]` — подтверждённое отсутствие фрагментов, отсутствующее поле — неизвестность. Не подставляйте сюда всю базу знаний или результаты поиска, не переданные модели. До 20 фрагментов, по 12 000 символов, суммарно до 60 000; большие контексты нельзя молча обрезать и объявлять полными.

Lab отдельно оценивает полноту и релевантность найденного, а также подтверждённость ответа контекстом — до шести дополнительных вызовов судьи на диалог в пределах бюджета. Эти диагностики не меняют основную accuracy. Без полного контекста причина «поиск или ответ» остаётся неизвестной.

## Запуск

```sh
npm ci
npm start
```

В разговоре:

> Собери validation set из 15 реальных диалогов, прогони агента и покажи accuracy и причины провалов. Логи: `dialogues.jsonl`.

Agent Lab принимает до 300 обезличенных диалогов JSON/JSONL, показывает бюджет до запуска и сам не забирает данные из внешних систем.

### Основной путь в Pi

Откройте `/agent-lab`: здесь история проверок. `n` начинает новую проверку — укажите папку агента и задачу своими словами. Новый библиотечный черновик проходит четыре раздела: **1 Логи → 2 Сценарии → 3 Прогон → 4 Результаты**.

1. **Логи:** видно, сколько источников обработано, ожидает обработки или исключено и почему. Смысловая перепроверка не выдаётся за импорт ещё не обработанных логов.
2. **Сценарии:** варианты сгруппированы по бизнес-ситуациям. Здесь показаны готовность, факты пользователя, исходная цитата, происхождение синтетических вариантов и нерешённые решения. `Space` выбирает варианты, `e` обычным текстом исправляет первую реплику, цель, ожидаемый результат, правило проверки или факт владельца, `v` добавляет целевой вариант, `m` / `s` объединяют или разделяют группы, `g` продолжает смысловую проверку. Цитата требования при таких правках сохраняется, а изменённый вариант требует новой смысловой проверки. `y` принимает выбранные варианты одной ревизией и не запускает агента.
3. **Прогон:** после принятия показаны число выбранных вариантов, ревизия, агент, число диалогов и накопительный бюджет: использовано, максимум и остаток. `b` позволяет осознанно увеличить максимум без сброса уже учтённого расхода. `r` открывает отдельное подтверждение запуска и использует свежий hash черновика, созданного после компиляции принятой ревизии.
4. **Результаты:** итог показывает оценочную accuracy, «не измерено» и главные причины. Enter ведёт к разбору провала и разговору. `y` / `n` / `s` отмечают согласие с судьёй, несогласие или сомнение.

Esc возвращает в историю, `q` закрывает только доску — начатый с доски прогон продолжается, пока открыт Pi. Для остановки нажмите `c` и подтвердите её. `r` в завершённом прогоне создаёт новый черновик принятого набора; исходный результат остаётся в истории.

`Tab` переключает разделы, `PgUp` / `PgDn` прокручивают текст, `?` открывает справку. Главное действие всегда написано внизу экрана.

История и `agent_lab_inspect` доступны и во время работы другой сессии: для чтения не нужна блокировка записи. Изменять или останавливать чужой активный прогон из этого окна нельзя; экспорт сохранённого снимка доступен.

Сохранить и повторить набор:

```sh
agent-lab save-suite --id RUN --output .evals/validation.json
agent-lab evaluate --input .evals/validation.json --yes --parallel 8
agent-lab diff --before BEFORE_RUN --after AFTER_RUN
```

`unknown`, invalid и not reached не входят в знаменатель accuracy. Автоматические решающие pass/fail не требуют ручной разметки; человек нужен только для спорных случаев или выборочного аудита.
