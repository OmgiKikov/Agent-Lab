# Agent Lab

Agent Lab помогает владельцу агента найти проблемы в записанных разговорах и проверить исправления на работающем агенте. Основной интерфейс — чат Pi.

## Что можно сделать

**Проверить разговоры по справочным статьям.** Lab сравнивает факты, которые бот действительно сообщил, с подходящими статьями. Возможное противоречие содержит две цитаты: слова бота и слова источника. Подтверждённые статьёй утверждения и то, что проверить не удалось, показываются отдельно.

Инструкция сотруднику «предложи СМС» сама по себе не делает СМС обязанностью бота. Передача оператору, пропущенная подробность, скрытое число и отсутствие нужной статьи не доказывают фактическую ошибку. Проверка фактов не оценивает полноту ответа или качество агента в целом.

**Проверить соблюдение правил самого бота.** Когда предоставлены его промпт или явно заданные владельцем правила, Lab проверяет относящиеся к ситуации требования. Выводы модели остаются предварительными до проверки человеком.

**Проверить исправленную версию.** Из подтверждённой проблемы можно сделать воспроизводимую ситуацию, подключить агента, воспроизвести проблему и сравнить результат после исправления. Это отдельный запуск настоящего агента.

## Начать

Нужны Node.js 22.19 или новее и доступ к модели в Pi.

```sh
npm ci
npm run build
node dist/cli.js chat
```

В чате можно попросить:

> Проверь факты в ответах бота по этой таблице и папке со статьями.

Lab покажет, как прочитает таблицу, какие данные попадут моделям и сколько обращений разрешено максимум. Повторы и элементы интерфейса читаются по выбору владельца. Исходные файлы не изменяются.

В одной загрузке сейчас не больше 300 разговоров; для большего файла берётся воспроизводимая выборка. По умолчанию за один раз проверяются 24 разговора. Числа выбранных и проверенных разговоров показаны в результате. Продолжение использует готовые результаты, а незавершённую проверку повторяет со своего шага.

## Проверить сам Lab

```sh
npm run typecheck
npx tsx scripts/semantic-proofs.ts
npx tsx scripts/business-case.ts
```

Эти проверки используют вымышленные случаи. Проверка живой модели на заранее размеченных случаях запускается отдельно и требует явного `--live`:

```sh
npx tsx scripts/factual-evaluation.ts --live --provider PROVIDER --model MODEL --max-calls 25
```

Она проверяет настоящие ошибки, правильные ответы, скрытые значения, инструкции сотрудникам, разные продукты и разные периоды действия условий. Успех на этих небольших примерах не является оценкой точности на всех настоящих разговорах.

Подробнее об устройстве проверки и её ограничениях: [проверка фактов](docs/factual-checking.md).
