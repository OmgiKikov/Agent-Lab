# Agent Lab

Agent Lab прогоняет настоящего AI-агента на реальных диалогах и отвечает в понятном виде:

- какая у агента оценочная accuracy на сохранённом validation set;
- где именно он ошибается;
- какие причины повторяются;
- какие результаты не удалось измерить;
- что изменилось после следующей версии агента.

## Как это работает

```text
репозиторий + требования + реальные диалоги
  → validation set из 15 разговоров
  → запуск настоящего агента
  → accuracy + отдельные unknown/invalid
  → человеческое объяснение причин
  → сохранение и повтор после исправления
```

Ожидания берутся из требований владельца, а не из текущего кода, старых ответов агента или поля `outcome`. MVP оценивает prompt/RAG по наблюдаемому ответу; инструменты и backend state — следующий этап.

Карточки бизнес-сценариев — внутренний формат воспроизводимости. Карточка фиксирует цель, факты клиента, начальную реплику и критерий успеха. Дальше симулятор отвечает на текущие вопросы агента, а не подставляет старые реплики по порядку. Пользователю не нужно вручную вести карточки или размечать каждый результат.

До запуска исключаются полностью замаскированные реплики и случаи, которым нужны отсутствующие данные клиента. Если измеримых случаев меньше 15, Lab сохраняет меньший набор и причины исключений. Ожидания и их источники показаны в общем подтверждении запуска. Старые scripted-наборы автоматически не переписываются: их нужно пересобрать из логов.

### Наблюдение RAG

Адаптер может вернуть вместе с `reply` фактически переданные модели фрагменты:

```json
{"reply":"Возврат оформляется через терминал.","retrievals":[{"source":"refunds.md#return","content":"Возврат оформляется через терминал.","score":0.9}],"retrievalsComplete":true}
```

`retrievalsComplete:true` означает полный контекст именно этого ответа; `retrievals:[]` — подтверждённое отсутствие фрагментов, отсутствующее поле — неизвестность. Не подставляйте сюда всю базу знаний или результаты поиска, не переданные модели. До 20 фрагментов, по 12 000 символов, суммарно до 60 000; большие контексты нельзя молча обрезать и объявлять полными.

Lab отдельно оценивает полноту и релевантность найденного, а также подтверждённость ответа контекстом — до шести дополнительных вызовов судьи на диалог в пределах бюджета. Эти диагностики не меняют основную accuracy. Без полного контекста причина «поиск или ответ» остаётся неизвестной.

## Запуск

```sh
npm ci
npm start
```

В разговоре:

> Собери validation set из 15 реальных диалогов, прогони агента и покажи accuracy и причины провалов. Логи: `dialogues.jsonl`.

Agent Lab принимает до 300 обезличенных диалогов JSON/JSONL, показывает бюджет до запуска и сам не забирает данные из внешних систем.

Сохранить и повторить набор:

```sh
agent-lab save-suite --id RUN --output .evals/validation.json
agent-lab evaluate --input .evals/validation.json --yes --parallel 2
agent-lab diff --before BEFORE_RUN --after AFTER_RUN
```

`unknown`, invalid и not reached не входят в знаменатель accuracy. Автоматические решающие pass/fail не требуют ручной разметки; человек нужен только для спорных случаев или выборочного аудита.
