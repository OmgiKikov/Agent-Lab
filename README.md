# Agent Lab

Проверка качества ИИ-агента: настоящие диалоги, критерии с источниками, тестовые сценарии,
разговоры с агентом и оценка судьи. Python-бэкенд и отдельный React-интерфейс.

## Запуск

Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/) и Node.js 22.19+ с npm.

    sh bin/start.sh

Открыть http://127.0.0.1:5899. Один Python-процесс обслуживает данные и собранный интерфейс.
Остановка — Ctrl+C. Скрипт завершает только те процессы, которые запустил сам.

Модели подключаются через банковский шлюз из certs/, настроенный OpenAI-совместимый endpoint
или существующий вход OpenRouter через Pi. Pi — необязательная внешняя CLI, её HTTP-мост написан на Python.
При каждом запуске bin/start.sh даёт мостам Pi и backend новый токен; мост отвечает только на 127.0.0.1 и localhost.

Для банковского шлюза положить в certs/:

- url.txt — адрес шлюза;
- сертификат и ключ или .p12/.pfx, пароль в password.txt;
- корневой сертификат ca.pem/root.pem, если он нужен шлюзу.

Когда в certs/ есть url.txt, модели работают только через шлюз. Если шлюз настроен, но не работает (пустой url.txt,
нет сертификата, неверный пароль .p12, нет openssl, файл не читается), разговоры никуда не уходят: bin/start.sh
печатает причину и не запускает Pi, приложение запускается и показывает ту же причину в «Настройках», каждая
проверка заканчивается ею. Пароль .p12 openssl получает через stdin: в командную строку и сообщения он не попадает.

Адрес агента на ИФТ, EPK и путь к его коду задаются на экране «Агент».

## Разработка

Backend:

    uv sync --project backend
    uv run --directory backend uvicorn lab.app:app --reload --host 127.0.0.1 --port 5901

Frontend в другом терминале:

    npm --prefix frontend ci
    npm --prefix frontend run dev

Vite открывается на :5900 и направляет /api в Python на :5901.

Проверки:

    sh bin/check.sh

Автоматическое исправление стиля и форматирование:

    sh bin/format.sh

Python проверяет Ruff; TypeScript — ESLint; оформление frontend — Prettier.
CI запускает те же проверки, включая форматирование и отсутствие предупреждений ESLint.

## Агенты

Продукт проверяет несколько агентов. Первый экран — «Агенты» (`/agents`): карточка на агента с итогом последней
проверки и «Новый агент». Внутри агента (`/a/<id>/…`) — весь продукт; агент переключается вверху навигации.
У каждого агента свои диалоги, правила, результаты и ответы человека: своя база `data/agents/<id>/lab.sqlite3`;
реестр агентов — `data/agents.sqlite3`. Числа разных агентов не сравниваются.

При первом запуске прежняя база `data/lab.sqlite3` становится агентом «Агент эквайринга» (`acquiring`), а сам файл
остаётся рядом как `lab.sqlite3.before-agents`. Если реестр `data/agents.sqlite3` потерян, при запуске Lab снова
находит агентов по их папкам в `data/agents/`: данные на месте, имя агента — его адрес.

## Данные

Разговоры, сценарии, настройки, результаты и оценки человека находятся в SQLite внутри data/, у каждого агента своя.
Исходные выгрузки и технические логи остаются файлами. data/ и certs/ исключены из Git.
Для отдельного набора данных задать LAB_DATA, для сертификатов — LAB_CERTS.
Относительные пути этих настроек отсчитываются от корня проекта.
Папки, которые Lab создаёт в data/, закрыты для других пользователей компьютера. С одной папкой данных работает один
Lab: второй запуск с той же LAB_DATA останавливается и называет причину.

Прежние JSON/JSONL не удаляются. Импорт выполняется явной командой при остановленном backend:

    uv run --directory backend python -m lab.migrate --source /absolute/path/to/old/data --agent <id>

Данные попадают в базу агента `<id>` — того, что открывается по адресу `/a/<id>`; поле `agent` в отчёте импорта
показывает, куда они записаны. Если агент один, `--agent` можно не указывать; если агентов несколько, команда без него
остановится и перечислит их. Пока агентов нет, импорт пишет в прежнюю `data/lab.sqlite3`, и при следующем запуске она
становится первым агентом.
Сначала сохранить копию прежней data/; проверить отчёт импорта и результаты в интерфейсе.
Агрегаты вердиктов и точность пересчитываются из сохранённых правил по исправленному смыслу PASS.
Если основной вердикт изменился, прежнее подтверждение человека сбрасывается; число сбросов указано в `resetReviews`.
Цитаты и исходные файлы сохраняются. Новые вызовы моделей при импорте не выполняются.
Повторный импорт сохраняет актуальные данные и не возвращает оценки и сценарии, очищенные после замены логов.
История внешнего Workshop в ~/.raindrop/ остаётся на компьютере и автоматически не переносится.

Настройки моделей: LAB_MODEL_URL, LAB_MODEL_KEY, LAB_MODEL, LAB_SECOND_MODEL, LAB_SECOND_URL, LAB_SECOND_KEY.
По умолчанию разговоры проверяет одна модель (GLM), как на рабочем компьютере. Вторая проверка моделью другого
вендора включается только через LAB_SECOND_MODEL; та же модель второй раз не запускается.
Вторая модель идёт по адресу LAB_SECOND_URL, а без него — туда же, куда основная (LAB_MODEL_URL); во второй мост Pi
(127.0.0.1:11437) — только когда LAB_MODEL_URL не задан. Её ключ — LAB_SECOND_KEY. LAB_MODEL_KEY уходит только
по адресу основной модели: второй модели он достаётся, лишь когда её адрес тот же.
Порт приложения: LAB_PORT (по умолчанию 5899).

Agent Lab отвечает только по адресам 127.0.0.1, localhost и [::1]: страница с другим именем, которое указывает на этот
компьютер, не прочитает разговоры (DNS rebinding). Если Lab открывают по другому имени этого компьютера, добавить его
в LAB_ALLOWED_HOSTS (через запятую). Команды (POST) принимаются только со страницы самого Lab — не с других локальных
сервисов на соседних портах. Чужая страница не покажет Lab внутри себя (X-Frame-Options, frame-ancestors): клик там
был бы кликом по самому Lab. Агент из кода запускается без ключей Lab: LAB_MODEL_KEY, LAB_SECOND_KEY, PI_PROXY_TOKEN
и настроек шлюза (AGENT_LAB_GATEWAY_*) в его окружении нет.
