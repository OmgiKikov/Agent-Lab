# LangWatch для проверки диалогов

Этот проект переходит на [LangWatch](https://github.com/langwatch/langwatch). Рабочий продукт открывается по адресу **http://localhost:5560**. Локальное пространство «Диалоги» создаётся автоматически; заполнять форму регистрации не нужно.

Новый пользовательский маршрут открывается кнопкой **«Проверка логов →»** в проекте или напрямую на [странице проверки агента](http://localhost:5560/agent-review.html): загрузка XLSX/CSV/JSONL → анализ выбранных разговоров по правилам → цитаты и подтверждение → редактируемая карточка → запуск подключённого AIGW. Анализ сохраняется между перезапусками и в наборах LangWatch; карточки и прогоны — в его библиотеке сценариев. По умолчанию разбираются 3 разговора, максимум 24 за один запуск. Это оценка выбранных ответов, а не процента качества всей выгрузки. Поиск выдержек справочника пока не откалиброван; без достаточных доказательств результат остаётся `UNKNOWN`.

## Запуск

Откройте терминал в этой папке и выполните:

```bash
./scripts/start-langwatch.sh
```

На первом запуске установка может занять несколько минут. Затем откройте http://localhost:5560. Если браузер попросит войти, команда `./scripts/show-local-login.sh` покажет данные только вашего локального пользователя. Для остановки нажмите `Ctrl+C` в терминале запуска.

Исходный код LangWatch лежит в папке `langwatch/`. Он загружается автоматически и остаётся локальной копией. Данные и секреты хранятся в `langwatch/.local/` и не отправляются в GitHub. Локальный запуск отключает отправку служебной статистики LangWatch.

Оценки запускаются через уже настроенный `pi`. Мост между ним и LangWatch слушает только `127.0.0.1` и стартует автоматически для этого пользователя macOS. `pi` здесь выполняет вызов модели OpenAI: при запуске оценки разговор и выбранные выдержки передаются ей. Остальные записи не отправляются, пока вы не запустите их проверку. Если мост больше не нужен, выполните `./scripts/stop-pi-proxy.sh`; следующая команда запуска включит его снова.

## Разговоры и проверки

### Перенос архивных находок Agent Lab

В [очереди «Проверка ошибок: перевод оператору»](http://localhost:5560/local-dev-project-se7hbx/datasets/dataset_byfJhu7TJqlssOMx2ifFr) лежат 11 **неподтверждённых** находок из последнего разбора Agent Lab. У каждой есть полный исходный разговор, цитата правила, объяснение судьи и черновик будущего сценария. Это перенос старых находок для проверки человеком; LangWatch пока не оценивает новые логи этим правилом автоматически.

Откройте строку, проверьте разговор и правило, поставьте `owner_decision` = `confirmed` или `disputed` и напишите причину в `owner_reason`. Если нужно, поправьте `draft_situation` и `draft_criterion`. После этого выполните `python3 scripts/failure-workflow.py promote --dataset dataset_byfJhu7TJqlssOMx2ifFr`: только подтверждённые строки станут сценариями LangWatch. Повторный запуск не создаёт дубликаты.

Многоходовый прогон AIGW выполнился на [сценарии QR СБП](http://localhost:5560/local-dev-project-se7hbx/simulations?drawer.open=scenarioRunDetail&drawer.scenarioRunId=local_scenariorun_0008MFbm8qsC3TgTXqeOzR5mlKKAs): сохранены шесть сообщений и вердикт `FAILED` по ответу на уточнение клиента. Это показывает, что симулятор, локальный бот и судья соединены; сам вывод о качестве ответа ещё должен проверить владелец. В текущем HTTP target видны реплики, а не внутренние вызовы инструментов бота.

Все 866 разговоров уже доступны в наборе [«Диалоги из банка — точный текст»](http://localhost:5560/local-dev-project-se7hbx/datasets/dataset_nfqYqIRfcPoA2_yA0JEdo). Для каждой записи текст и остальные поля посимвольно сверены с исходной выгрузкой. Повторяющиеся реплики и интерфейсные вставки сохранены. Для переноса использован JSONL: пробная загрузка CSV испортила 11 русских фрагментов и была удалена.

Из присланных документов получен [справочник из 178 уникальных статей](http://localhost:5560/local-dev-project-se7hbx/datasets/dataset_Pd614NaYKeaVLCwNvAfnK). Тексты сверены после загрузки. В документах также 2103 встроенных изображения; сведения, которые есть только на них, пока не входят в текстовую проверку.

Для начала создан [набор из трёх разговоров с проверенными вручную выдержками](http://localhost:5560/local-dev-project-se7hbx/datasets/dataset_xlcxjOvH7vOGcneXCOH7-) и [эксперимент с оценщиком фактов](http://localhost:5560/local-dev-project-se7hbx/experiments/workbench/pFvqv9kW). Выдержки первоначально нашёл словарный поиск по статьям, затем они были просмотрены и сокращены вручную. Это не готовый автоматический подбор источников для всех 866 разговоров.

Пилот завершён: оценщик отметил два ответа как подтверждённые и один как недостаточно подтверждённый; доказанных ошибок в этих трёх разговорах не нашёл. Отдельный искусственный пример с прямым противоречием источнику получил категорию `FACTUAL_ERROR`. Перед проверкой всей выгрузки нужно проверить подбор источников и выводы на более широкой выборке, исправить пропуски и только после этого запускать все 866.

На 20 дополнительных темах автоматический поиск статей дал явные промахи. Например, вопрос о скачивании QR СБП получил статью про оборудование, а вопрос о комиссии — про назначение платежа. Более сложный локальный поиск тоже не устранил эти промахи, поэтому его не включили. Сейчас автоматический подбор статьи не является доказательством правильности ответа.

В [новом наборе](http://localhost:5560/local-dev-project-se7hbx/datasets/dataset_LGtRVhaM5Ll8BMBtVeeRS) пять разговоров разделены на десять разных содержательных ответов бота. Повторы в исходной выгрузке сохранены. Выдержки для этого набора выбраны вручную; `pi` оценивает ответы, а не подбирает статьи. В [запуске №12](http://localhost:5560/local-dev-project-se7hbx/experiments/pFvqv9kW) один разговор подтверждён источником целиком, по четырём есть существенные части без достаточного подтверждения. Это **не означает**, что четыре разговора доказанно ошибочны. Например, в разговоре про НДС поздняя инструкция по эквайрингу подтверждается, а более ранние ответы о налоговом возврате нельзя подтвердить по предоставленному справочнику.

Первые вопросы к ответам бота: клиент просит отменить прошедшую оплату, а бот даёт путь для отмены возврата; возврат обычного платёжного поручения бот сначала направляет в «Эквайринг»; при вопросе о компенсации НДС бот сначала отвечает про налоговое возмещение и лишь после уточнения клиента переходит к акции эквайринга. Эти случаи требуют исправления маршрута ответа или уточняющего вопроса. По скачиванию QR основная инструкция подтверждена, но добавленные ботом действия и права доступа не подтверждены выбранной выдержкой — сначала нужен дополнительный источник.

Сейчас это рабочее место для просмотра разговоров и проверки небольших вручную подготовленных партий, а не готовая оценка всех 866. Следующий шаг — добиться надёжного подбора статей и честного ответа «источника нет» на разнородной контрольной выборке. После этого можно запускать партии остальных разговоров и превращать подтверждённые находки в список конкретных исправлений для бота. Самого банковского бота LangWatch не заменяет.
