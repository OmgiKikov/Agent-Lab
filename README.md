# Agent Lab

Agent Lab — пакет для Pi. Он разыгрывает с вашим AI-агентом ситуации из его настоящих разговоров и отвечает на три вопроса: насколько хорош агент, насколько можно верить этой оценке и почему агент ошибается. Агент остаётся внешней системой: Lab говорит с ним через адаптер и не меняет ни его код, ни данные, ни процессы.

```text
 Точность агента: 50% — справился в 1 из 2 ситуаций
 Вероятно, от 9% до 91% (95%) · мало данных · судью ещё не проверяли

 Почему ошибается
   1  Возврат оплаты — номер назван сразу

 Все ошибки
   ✗ 1  Возврат оплаты — номер назван сразу
      Ожидалось: А — не спрашивать номер терминала ещё раз, если клиент его уже назвал; Б —
      объяснить, как оформить возврат · Агент: «Уточните номер терминала.»
      Правило: «Если номер терминала уже указан, не запрашивайте его повторно; объясните возврат.
      Если номера нет, уточните номер терминала.»
```

Так выглядит итог учебного примера: `agent-lab demo`, затем `agent-lab summary --id RUN`; модель не нужна. На ваших логах под числом появляются ещё две строки: точность с учётом частоты тем и сверка с продом.

## Что отвечает Lab

| Вопрос | Ответ |
|---|---|
| Насколько хорош агент? | Одно число: «Точность агента: 72% — справился в 18 из 25 ситуаций». Ситуация засчитана, если во всех её разговорах агент выполнил всё, что должен. |
| Можно ли верить числу? | Строка доверия под числом: 95-процентный интервал, «мало данных» при маленькой выборке, сколько ситуаций не измерено и почему, согласны ли вы с судьёй, какие ситуации нестабильны. Ниже — «С учётом частоты тем — около N%» и «Синтетика совпадает с продом в N из M ситуаций». |
| Почему агент ошибается? | Причины, общие для нескольких ситуаций, и каждая ошибка на одном экране: что ожидалось, что агент ответил (цитата), какое правило владельца нарушено (цитата), весь разговор. |

Как считается число:

- Точность — это «справился» / («справился» + «не справился»). Ситуация, которую не удалось измерить, в знаменатель не входит и не превращается в 0%: у неё всегда есть причина — агент или стенд не ответили, клиент ушёл из ситуации, голоса судьи разошлись, у вердикта нет подтверждения в наблюдаемом канале.
- Каждый пункт «агент должен» судья оценивает отдельно, двумя голосами. Разошедшиеся голоса — «не измерено», а не успех. Ваша отметка «судья не прав» заменяет его вердикт.
- Интервал считается по Уилсону. Если контрольная ситуация не прошла или не измерена, над числом появляется «✗ Числу пока не верить».
- Повторы показывают нестабильные ситуации отдельно («нестабильно 2»), а не прячут их в среднем.
- Это точность на наборе ситуаций, а не гарантия поведения в проде. Насколько набор похож на прод, показывают покрытие тем и сверка с продом.

## Как это работает

```text
Логи ──► темы и выборка ──► ситуации ──► прогон ──► результат
         покрытие тем       ваши ответы  клиента играет Lab,  число, доверие, темы,
                                         оценивает судья      причины, сверка с продом
```

1. **Логи → темы и выборка.** Lab читает выгрузку разговоров и сразу откладывает непригодные, называя причину: нет реплик клиента или их больше 16, реплика клиента целиком скрыта обезличиванием, запись не читается. Остальные разговоры модель раскладывает по темам: сначала предлагает до 15 тем по первым словам клиентов, потом сортирует разговоры пачками по 40, а неподошедшие собирает в «Другое». В модель уходят только слова клиентов. Выборка пропорциональна частоте тем и берёт хотя бы по одному разговору из каждой темы, пока хватает числа ситуаций (по умолчанию 15). Получается строка покрытия: «15 ситуаций покрывают 9 из 11 тем — 94% диалогов». Карта тем сохраняется рядом с логами: новая подготовка по тем же логам той же моделью за неё не платит, а прерванная разметка продолжается с последнего шага.
2. **Ситуации.** Из каждого выбранного разговора получается одна ситуация — короткий бриф:
   - заголовок «тема — случай» и источник: «из диалога №17», «по вашим правилам», «добавлена вами», «похожая на №3»;
   - **Клиент:** чего хочет; что пишет первым — дословно из лога; что знает — «метка: значение — сразу / если спросят / не знает»; когда уходит; поворот, если он есть;
   - **Агент должен:** 1–3 пункта, у каждого — цитата правила владельца.

   Правила берутся только из ваших материалов: промпта агента, базы знаний (.md, .docx, .txt, .html) или того, что вы написали в чате. Ответ агента из лога правилом не становится. Код проверяет, что реплики и цитаты дословно совпадают с источником, а отдельный рецензент перечитывает разговор и правила. У ситуации один из трёх статусов: **✓ готова**, **? нужен ваш ответ** (один вопрос и 2–3 варианта ответа) или **✗ не подходит для теста**. Спорные ситуации не мешают запускать готовые.
3. **Прогон.** Прогон начинается с одного вопроса: «Принять N ситуаций и запустить?». Под ним — план: сколько ситуаций и разговоров, какой агент, сколько вызовов может потратить судья, сколько стоит сверка с продом и сколько займёт время. «Запустить» утверждает готовые ситуации (их определения запечатываются, и повтор пойдёт ровно по ним) и начинает прогон. Клиента играет Lab: программа клиента выбирает только разрешённые ходы, называет факты тогда, когда это записано в ситуации, и не может выдумать значение. Ответы агента оценивает судья.
4. **Результат.** Число, строка доверия, темы, причины и ошибки звучат одинаково в чате, в рабочем пространстве, в командной строке и в отчёте для заказчика. Ситуации из логов судья дополнительно оценивает на исходном записанном разговоре; агент и симулятор при этом не участвуют. Так видно, совпадает ли синтетика с продом. Калибровкой это называется, только когда известно, что логи записаны той же версией агента, что проверялась; иначе это сравнение, и Lab пишет, почему не калибровка. Версию агента в логах указываете вы, проверенную версию сообщает адаптер или вы.

## Быстрый старт

Нужны Node.js ≥ 22.19 и npm. Для своего агента нужна ещё модель, подключённая в Pi (`/login` или ключ провайдера): она готовит ситуации и играет клиента. Судья по умолчанию — `openai/gpt-5.6-sol` через OpenRouter. Учебному примеру модель и ключи не нужны.

```sh
npm ci
npm run build
npm link                    # команда agent-lab в PATH

agent-lab demo              # учебный пример целиком: подготовка, ответ на вопрос, прогон, итог (JSON)
agent-lab summary --id RUN  # тот же итог экраном
```

Своего агента проверяют из папки его проекта:

```sh
cd ~/my-agent
agent-lab                   # чат Pi с Agent Lab в этой папке
```

Дальше пишите обычными словами: «Проверь моего агента в этой папке. Логи и промпт лежат тут же». `npm start` открывает тот же чат в папке самого Agent Lab.

## Чат в Pi

Работайте с Lab как с Claude Code: скажите, что хотите узнать, и Lab сделает этот шаг. Каждое действие видно одной строкой `●` с одной-двумя строками `└` под ней; подробности раскрываются по `Ctrl+O` на месте. JSON, хеши и id на экран не попадают.

| Вы говорите | Что происходит |
|---|---|
| «Проверь моего агента в этой папке. Логи и промпт лежат тут же.» | Lab находит в папке логи, правила, промпт и способ запустить агента. Если логи — таблица, сначала предлагает, как её читать. Затем спрашивает одно согласие: что будет прочитано, сколько получится ситуаций, какие разговоры не войдут и почему, какой потолок расхода. |
| «Покажи, какие ситуации получились.» | Список: номер, название, статус; у ждущих ответа — вопрос с вариантами. |
| «Да, клиент знал номер терминала заранее — ответь так на вопрос ситуации.» | Ответ выбирается в диалоге, который открывает Lab; ситуация становится готовой. |
| «Пусть в этой ситуации клиент вообще не знает номер.» | Правка ситуации. Она записывается вашими словами или после того, как вы подтвердите точное изменение; изменённое Lab перепроверяет. Правка после прогона уходит в новый черновик, прошлый прогон не меняется. |
| «Запусти готовые.» | Диалог «Принять N ситуаций и запустить?». Если агент ещё не подключён, Lab предлагает найденный в папке способ его запустить. |
| «Покажи первую ошибку: что агент сказал и какое правило нарушил?» | Ожидалось → агент ответил → правило → весь разговор. Если синтетика и исходный разговор разошлись, видны оба вердикта. |
| «По первой ошибке судья прав.» | Ваша отметка о судье: «да, прав», «нет» (с причиной) или «не знаю». Из таких отметок складывается строка «с судьёй согласны X из Y». |
| «Сохрани отчёт для заказчика.» | Одностраничный HTML-отчёт в `.agent-lab/exports/`, рядом — Markdown и снимок доказательств. |
| «Прогони этот набор ещё раз.» | Повтор утверждённого набора; прошлый результат не меняется. |
| «Логи записаны той же версией агента, что мы сейчас проверяли.» | Версия агента в логах; после этого сверка с продом становится калибровкой. |

Правила разговора:

- **Решает владелец.** Согласие на расход, запуск, ответ на вопрос ситуации, отметка о судье и версия логов принимаются только в диалоге, который открывает Lab. Модель в чате не передаёт Lab ни настроек, ни согласия — их даёте вы в этом диалоге.
- **Первое число — как можно раньше.** Агента можно подключить после подготовки ситуаций: Lab спросит перед запуском. Вопросы по спорным ситуациям не задерживают прогон готовых.
- **Долгая работа не держит разговор.** Подготовка, проверка и прогон идут в фоне: над полем ввода видна одна строка прогресса, итог приходит отдельным сообщением. Чтобы остановить, скажите «стоп». Остановленная подготовка продолжается с того места, где остановилась, и уже оплаченное не повторяется.

Модели Lab показывает только инструменты текущего шага (всего их девять):

| Шаг | Инструменты |
|---|---|
| Ничего ещё нет | `agent_lab_status` — что есть в проекте; `agent_lab_prepare` — подготовить ситуации из логов, по одним правилам, из сохранённого набора или учебный пример |
| Есть ситуации | + `agent_lab_cards` — показать ситуации; `agent_lab_edit` — изменить ситуацию; `agent_lab_decide` — решения, которые ждут владельца; `agent_lab_run` — запустить, утвердить, показать ход, остановить |
| Есть результат | + `agent_lab_results` — итог, отчёт, набор для CI; `agent_lab_explain` — одна ситуация с разговором; `agent_lab_agree` — ваше слово о судье |

Инструкция модели одна — [`skills/agent-builder/SKILL.md`](skills/agent-builder/SKILL.md); она добавляется в системный промпт сессии Agent Lab.

## Рабочее пространство `/agent-lab`

Рабочее пространство нужно для работы со множеством ситуаций сразу; всё то же самое можно сказать в чате. `/agent-lab` открывается на том, что ждёт владельца: сначала решения, если они есть, иначе последний результат. В шапке — имя агента и области с числами: «Нужно ваше решение: N» (пока решения есть), «Ситуации», «Прогоны», «Проблемы». До первого результата рабочее пространство ведёт по шагам **Ситуации › Прогон › Результат**.

- **Нужно ваше решение** — только то, чего Lab не может решить сам: вопрос ситуации, ситуация, не подходящая для теста, лимит на проверку, остановленная подготовка, черновик старого формата, версия агента в логах, судья, который не ответил. Решённое исчезает само.
- **Ситуации** — брифы, их статусы и покрытие тем.
- **Прогоны** — результаты, от новых к старым; разговор, который оценил судья, открывается целиком.
- **Проблемы** — то, что повторяется: одна причина в нескольких ситуациях или ошибка, которая держится прогон за прогоном. Проблема бывает «в агенте» или «в тесте» — например, когда клиент ушёл из ситуации.

| Клавиша | Что делает |
|---|---|
| `↑` `↓` | выбрать строку; в открытой ситуации или разговоре — листать |
| `Enter` | открыть или сделать то, что написано в строке |
| `Esc` | назад; в начале — закрыть (прогон продолжится) |
| `←` `→` | области; до первого результата — шаги |
| `1` `2` `3` | действие у выбранного или ответ на вопрос |
| `a` | спросить Lab про выбранное — вопрос уходит в чат |
| `d` | как это проверяется — подробности для разработчика |
| `?` | подсказка |

`/agent-lab demo` готовит учебный пример, `/agent-lab RUN` открывает прогон, `/agent-lab ~/папка` передаёт в чат просьбу проверить агента в этой папке. Чтение не берёт блокировку записи, поэтому работа другой сессии тоже видна; менять чужой идущий прогон из этого окна нельзя.

## Логи

| Формат | Как читается |
|---|---|
| JSON, JSONL | Массив или `{"dialogues": [...]}`, в каждом разговоре `{"id": "d1", "messages": [{"role": "user", "content": "…"}, {"role": "assistant", "content": "…"}]}`. Вместо `messages` можно передать `events` с событиями `message`, `tool`, `retrieval`, `state`. Не больше 4 МБ и 300 разговоров за один импорт. |
| XLSX, CSV | Lab сам предлагает, как читать таблицу: какой лист, какая колонка — id разговора, какая — текст с метками ролей (или колонка роли у каждой строки-сообщения), как упорядочены сообщения. Чего он не может понять сам, о том задаёт один вопрос с вариантами ответа. Читает таблицу только так, как вы подтвердили. Подтверждённое чтение хранится вместе с хешем файла, поэтому тот же файл всегда даёт те же разговоры. Остальные колонки остаются при каждом разговоре. Если разговоров больше 300, берётся детерминированная выборка из 300 пригодных — по хешу содержимого, без оглядки на исходы. |

Какие разговоры оценивать — например, только разговоры одного агента из общей выгрузки, — выбирают в чате («оцени только разговоры, где agentCode — один агент»: Lab спросит, какие значения оставить) или в командной строке. Lab перечисляет 30 самых частых значений колонки и говорит, сколько ещё; любое значение можно назвать и самому:

```sh
agent-lab import --file logs.xlsx                          # как Lab прочитает таблицу; ничего не записывает
agent-lab import --file logs.xlsx --where "КОЛОНКА"        # какие значения есть в колонке
agent-lab import --file logs.xlsx --where "КОЛОНКА=ЗНАЧЕНИЕ|ЗНАЧЕНИЕ" --yes   # сохранить чтение с отбором
```

Поправить чтение помогают флаги `--sheet`, `--id-column`, `--text-column`, `--separator`, `--markers CLIENT=клиент,AGENT=агент`, `--role-column`, `--roles`, `--order-column` и `--row-order`. Сохранённое чтение затем используют и чат, и `agent-lab build --dialogues-file logs.xlsx`.

Без логов ситуации строятся по одним правилам — только если вы прямо это выбрали: по умолчанию 5, не больше 20 за раз, без выдуманных разговоров и личных данных клиента.

## Подключение агента

Lab разговаривает с агентом одним из трёх способов. Каждый разговор — отдельная сессия: агенты `command` и `module` запускаются заново на каждый разговор, HTTP-агент различает разговоры по `sessionId` и сам сбрасывает между ними состояние.

| Способ | Как устроен |
|---|---|
| `command` | Процесс на каждый разговор (например, `python3 agent.py`), по одному JSON в строке через stdin/stdout. Stdout отдан протоколу, отладочный вывод пишите в stderr. Пример: [`examples/echo-agent.py`](examples/echo-agent.py). |
| `module` | JavaScript-модуль с `createSession(input)`, у сессии есть `respond(message)`. Запускается в отдельном процессе Node на каждый разговор. Пример: [`examples/echo-agent.mjs`](examples/echo-agent.mjs). |
| `http` | `POST` с JSON `{sessionId, scenarioId, initialState, messages, message}`. Заголовки ссылаются на имена переменных окружения (`headersEnv`), значения секретов в записи не попадают. |

Ответ агента — строка JSON или объект:

| Поле | Зачем |
|---|---|
| `reply` | Ответ агента клиенту. |
| `events` | Вызовы инструментов `{tool, args, result}`. Без них пункт «агент должен» про действие не проверяется: слова агента не доказывают действие. |
| `records`, `resetConfirmed` | Состояние системы, как его сообщает адаптер, и подтверждение, что начальное состояние (`initialState.external`) применено. Без подтверждения разговор не измерен, а не засчитан. |
| `eventsComplete` | Журнал инструментов полон: только тогда вердикт по инструменту может стоять. |
| `version`, `promptHash` | Версия агента и хеш его промпта. По версии из ответов Lab понимает, что именно проверялось, и решает, калибровка ли сверка с продом. |
| `retrievals`, `retrievalsComplete`, `retrievalStage` | Фрагменты, которые получила модель агента: до 20 фрагментов, по 12 000 символов, всего до 60 000. `retrievalsComplete: true` — если это весь контекст. `retrievalStage: "retrieved"` — если видна только выдача поиска. По ним судья отдельно оценивает достаточность, релевантность и обоснованность ответа; на точность эти оценки не влияют. Подробнее: [`docs/rag-evidence-audit-2026-09-22.md`](docs/rag-evidence-audit-2026-09-22.md). |
| `measurementError` | Стенд не смог ответить: разговор не измерен, и агент не наказан. |

Как запускать агента, Lab ищет в папке проекта сам: сохранённое подключение, модуль с `createSession`, цикл JSON-строк на Python или Node, скрипт `start` в `package.json`, локальный адрес в конфиге. Один уверенный кандидат сразу попадает в план запуска, из нескольких выбираете вы. `agent-lab detect` показывает найденное и ничего не запускает; из файлов `.env` берутся только имена переменных. `agent-lab doctor --connection подключение.json --yes` делает три пробных запроса — запись, чтение и сброс — и запоминает рабочее подключение ([`examples/connection.json`](examples/connection.json)). Необязательный хук `release` разворачивает проверяемую версию перед прогоном.

## Командная строка

Все команды работают с папкой `./.agent-lab` (другую задаёт `--data-dir ПАПКА`). Чтение (`summary`, `export`, `diff`) не мешает сессии, которая сейчас пишет в эту папку. `--yes` — ваше согласие; команда, запущенная из чата Agent Lab, его не принимает: в чате согласие спрашивает сам чат.

| Команда | Что делает |
|---|---|
| `agent-lab` · `agent-lab chat [опции Pi]` | Чат Pi с Agent Lab в текущей папке. |
| `agent-lab detect [--directory ПАПКА] [--json]` | Что Lab нашёл в папке: агента, логи, материалы, промпт. Только читает. |
| `agent-lab import --file логи.xlsx [--where …] [--yes] [--json]` | Как Lab прочитает таблицу и какие разговоры возьмёт; `--yes` сохраняет это чтение. |
| `agent-lab build --input задача.json [--dialogues-file логи] [--situations N] [--connection подключение.json] [--yes]` | Подготовить ситуации без чата (`prepare` — то же самое). Без `--yes` показывает, сколько ситуаций будет (не больше N, по умолчанию 15 из логов), какие разговоры не войдут и почему, и потолок вызовов модели — и ничего не записывает; с `--yes` готовит в пределах этого потолка. В задаче — описание агента и материалы; `materialFiles`/`promptFiles` Lab читает сам. |
| `agent-lab cards --id RUN [--card N] [--json]` | Ситуации: что пишет и знает клиент, что должен агент, статус и вопрос. `--card N --choice a\|b\|c [--text «…»] --yes` — ответ на вопрос; `--input команда.json [--yes]` — правка (без `--yes` только «было → стало»); `--check`, `--resume`, `--accept` с `--yes` — проверить, продолжить подготовку, утвердить готовые; `--convert` — продолжить черновик старого формата в новом. |
| `agent-lab run --id RUN --yes [--parallel N]` | Запустить утверждённый черновик. |
| `agent-lab accept --id RUN [--yes]` | Подтвердить ожидания черновика без библиотеки ситуаций — повтора старой записи. |
| `agent-lab summary --id RUN [--json]` | Итог прогона тем же экраном, что в Pi. |
| `agent-lab export --id RUN --format html\|markdown\|json [--output файл]` | Отчёт для заказчика или машинный снимок. |
| `agent-lab logs --id RUN [--agent-version ВЕРСИЯ \| --unknown] [--yes]` | Какой версией агента записаны логи прогона. От этого зависит, будет ли сверка с продом калибровкой или сравнением. |
| `agent-lab repeat --id RUN [--case ID] [--control ID]` | Черновик повтора утверждённого набора, можно с контрольной ситуацией. |
| `agent-lab reassess --id RUN --yes \| --code-only [--input критерии.json]` | Заново оценить сохранённые разговоры. Получается новый результат; агент не запускается. |
| `agent-lab diff --before RUN --after RUN [--json]` | Сравнить два прогона одного набора, например повтор с исходным; код выхода 2, если прогоны несравнимы. |
| `agent-lab save-suite --id RUN --output .evals/набор.json [--case ID]` | Сохранить утверждённый набор для CI. Набор из логов несёт с собой логи, на которые ссылается. |
| `agent-lab evaluate --input .evals/набор.json --yes [--connection подключение.json] [--case ID] [--parallel N]` | Прогнать набор без диалогов. |
| `agent-lab suites [--directory .evals]` | Сохранённые наборы. |
| `agent-lab doctor --connection подключение.json --yes` | Пробные запросы к агенту. |
| `agent-lab status` | Какие модели доступны в Pi. |
| `agent-lab demo` | Учебный пример целиком, без модели. |

### CI

```sh
agent-lab save-suite --id RUN --output .evals/regression.json
agent-lab evaluate --input .evals/regression.json --yes --parallel 4
```

Коды выхода `evaluate`: 0 — все ситуации пройдены; 1 — есть ошибка агента; 2 — что-то не измерено, контрольная ситуация не прошла или прогон не завершился. `--yes` разрешает расход в пределах сохранённых в наборе лимитов, но не заменяет проверку ожиданий человеком. Пример workflow: [`examples/regression-ci.yml`](examples/regression-ci.yml) с набором [`examples/regression-suite.json`](examples/regression-suite.json) на SQLite, без ключей модели.

## Приватность

- Всё, что Lab записывает, лежит в папке `.agent-lab` проекта: импорты логов, подтверждённые чтения таблиц, карты тем, записи прогонов, журналы, аудиты судьи, отчёты. Файлы создаются с правами `0600`. Добавьте `.agent-lab/` в `.gitignore` своего проекта (в этом репозитории он уже там).
- С машины данные уходят только в запросах к моделям, которые вы настроили в Pi. Для карты тем — только слова клиентов. При подготовке — разговор и выбранные для него материалы владельца. Симулятор получает бриф ситуации и реплики агента. Судья получает разговор, пункты «агент должен» и правила, на которые они ссылаются; при сверке с продом — ещё и исходный разговор. Кроме этого Lab разговаривает только с вашим агентом через подключение и ничего не забирает из внешних систем.
- Предпросмотр импорта показывает только количества, без текстов сообщений. Отчёт для заказчика цитирует разговоры прогона, а исходный записанный разговор только называет, не цитируя. Отчёт — один самодостаточный файл; веб-шрифты он подгружает, только если при открытии есть сеть, и без них остаётся таким же читаемым.
- Набор для CI, сохранённый из прогона по логам, несёт эти логи внутри файла. Если логи приватные, не кладите такой набор в репозиторий.
- Секреты не попадают ни в записи, ни в материалы: заголовки HTTP ссылаются на имена переменных окружения, из `.env` Lab читает только имена.

## Старые записи

Записи прошлых версий Lab открываются, переоцениваются и повторяются без миграции: их хеши, квитанции судьи и утверждённые определения продолжают сходиться. Черновик старого формата можно продолжить в новом («Продолжить в новом формате» в очереди решений или `agent-lab cards --id RUN --convert`); сам старый черновик не меняется. Записи удалённых функций открываются и переоцениваются, но больше не запускаются.

## Разработка

```sh
npm test                    # сборка dist/ и все тесты (node:test через tsx)
npm run typecheck           # строгая проверка src/, extensions/ и тестов
npm pack --dry-run
node examples/scenario-lab-demo.mjs --verify   # учебный путь целиком на собранном dist/, без модели
```

Расширение Pi импортирует `src/` напрямую (Pi загружает TypeScript через jiti), а `dist/` нужен только бинарю `agent-lab`, так что сборка не ломает открытую сессию Pi. Проверки на настоящей модели платные и запускаются только явно, на вымышленных данных:

```sh
npx tsx test/live/product-eval.ts --run [--model provider/model]    # фразы владельца → нужный инструмент и состояние
AGENT_LAB_PROVIDER=openrouter AGENT_LAB_MODEL=openai/gpt-5.6-sol npx tsx test/live/scenario-lab.ts --run
npx tsx test/live/rag-evidence.ts --run --max-calls 13
node --import tsx test/live/simulator-stop.ts PROVIDER MODEL
```
