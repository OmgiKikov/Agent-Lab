# Agent Lab

Agent Lab читает проект AI-агента и материалы владельца, находит в реальных диалогах повторяющуюся проблему и превращает её в воспроизводимый регрессионный тест с доказательствами.

```sh
npm ci
npm start
```

Нужен Node.js 22.19+ и настроенная модель в Pi. Для команды `agent-lab` выполните `npm link`, затем запускайте её из проекта проверяемого агента.

## Основной цикл

1. Lab изучает репозиторий, точку запуска агента и требования из материалов владельца.
2. Вы передаёте деидентифицированные диалоги в JSON/JSONL: до 300 диалогов и 4 МБ. Lab сам не забирает данные из внешних систем.
3. Lab разбирает логи порциями, находит повторяющееся поведение, открывает несколько полных примеров и сверяет их с требованиями.
4. Lab показывает одну заземлённую гипотезу с точными ссылками на реплики и спрашивает: «Проверим?» Это отбор полезного теста, а не accuracy всей пачки.
5. После «да» Lab собирает ровно один редактируемый тест: ситуацию, пользователя, вход, проверки и рубрики. Вы исправляете его при необходимости и явно принимаете. Принятие теста не запускает агента.
6. Отдельное подтверждение запускает настоящего агента через `TargetSession`. В одном прогоне используется один режим пользователя.
7. Lab показывает полный диалог, автоматический вердикт и доказательства. `simulatorChecks` видны рядом с соответствующими репликами. Человек подключается только к спорным случаям или выборочной проверке автоматической оценки.
8. Полезный тест сохраняется, повторяется после изменения агента и сравнивается с прежним прогоном как `fixed`, `regressed` или `incomparable`.

Начните разговор так:

> Проверь агента в этой папке. Вот деидентифицированные диалоги: `dialogues.jsonl`.

Без логов можно построить синтетический тест по требованиям владельца, но происхождение доказательств останется синтетическим.

## CLI

```sh
# показать план discovery и верхнюю границу расходов
agent-lab discover --input dialogues.jsonl --task task.json

# выполнить discovery после подтверждения
agent-lab discover --input dialogues.jsonl --task task.json --yes

# построить один тест из принятой гипотезы
agent-lab discover-build --id DISCOVERY_RUN --yes

# показать тест, затем принять его
agent-lab accept --id TEST_RUN
agent-lab accept --id TEST_RUN --yes

# отдельно разрешить реальный запуск
agent-lab run --id TEST_RUN --yes

# сохранить и повторить тот же тест
agent-lab save-suite --id TEST_RUN --output .evals/regression.json
agent-lab evaluate --input .evals/regression.json --yes

# сравнить два совместимых прогона
agent-lab diff --before BEFORE_RUN --after AFTER_RUN
```

Команды без `--yes` ничего платного и исполняемого не запускают. Если discovery безопасно остановился между этапами, `agent-lab discover-resume --id RUN` показывает сохранённый остаток бюджета; повтор с `--yes` продолжает с checkpoint. Остановка внутри модельного вызова не возобновляется автоматически, потому что расход этого вызова неизвестен.

Сохранённый набор хранит определение теста, источники и условия измерения, но не переносит старое разрешение на запуск. Файл не перезаписывается. Для CI используйте `agent-lab evaluate`; коды завершения: `0` — все решающие проверки пройдены, `1` — найден провал агента, `2` — измерение неполно или сломана среда.

## Как читать результат

- Точные проверки кода отвечают только за наблюдаемые факты: текст, подтверждённое состояние и события инструментов.
- Заявление агента о выполненном действии не доказывает действие. Без наблюдаемого результата оно остаётся `unknown`.
- Модельный судья оценивает каждую применимую рубрику двумя независимыми вызовами и обязан цитировать события. Расхождение, противоречие или недостаток данных дают `unknown`.
- Повторяемость и reliability судьи в MVP не измеряются. Два совпавших ответа — консервативное правило решения, а не валидация судьи.
- Ручной вердикт необязателен для каждого результата. Он нужен для спора, неизвестности и выборочного контроля качества автоматической оценки.
- Сравнение допустимо только при тех же тестах, требованиях, настройках, режиме пользователя и протоколе судьи. Иначе результат — `incomparable`, без выдуманного улучшения.
