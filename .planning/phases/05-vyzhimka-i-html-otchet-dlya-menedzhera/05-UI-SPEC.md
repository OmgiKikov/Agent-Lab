# Phase 5 — UI Design Contract

> Visual and interaction contract for the customer materials of phase 5. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Five surfaces.**
> - **M1:** a plain-text summary for a messenger.
> - **M2:** a single-file HTML report for the customer's manager. This is a real web page, so the web dimensions (px, type scale, hex colors) apply to it literally.
> - **M3:** the owner's audit report, which gets a «Не пересылать» banner.
> - **M4:** the Pi command, the board key `x` and the notices.
> - **M5:** the CLI `share` and `export --format manager` commands.
>
> **This contract extends the approved `02-UI-SPEC.md`, `03-UI-SPEC.md` and `04-UI-SPEC.md`.** The following are reused **verbatim** and never reworded:
> - V1 (C-104…C-109) and V2 (C-110…C-117, C-147);
> - the phase-1 headline, small-sample, not-measured and control rows;
> - F1 detail rows (C-01…C-12; C-13 не применяется: судья остаётся на v10);
> - F6 (C-51…C-59) and F7 (C-60…C-63);
> - K1 and the change rows with their reason words (C-129, C-132);
> - the glyph words;
> - the forbidden-word lists.
>
> Where a customer file cannot carry an owner-side string (because it holds an id, a key or a Pi command), this file names the string and gives its customer variant. See the R5 table.
>
> **Autonomous run.** The user was asleep and asked for no questions. Every open choice is recorded in `## Decisions Log`.
>
> **Scope markers.** `[P5]` marks text and layout locked for this phase. `[CUST]` marks rules that hold for every customer-profile string (M1, M2).

## Typography (M2) `[P5]`

Exactly four sizes and two weights (400, 600).

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Label | 13px | 400 (600 for the brand line) | 1.5 | Header facts; rule and expectation labels (`Должен был:`, `Правило N · источник:`); `и ещё K правил`; `<summary>`; footer note; brand line `AGENT LAB · ОТЧЁТ ДЛЯ ЗАКАЗЧИКА` (600, letter-spacing .08em) |
| Body | 15px | 400; 600 for `h3` titles and the change glyph | 1.5 | All paragraphs, lists, situation titles (`h3`), blockquote |
| Heading | 20px | 600 for `h2`; 400 for the headline row | 1.25 | Section titles (`h2`); the phase-1 headline row under V1 (`.headline`) |
| Display | 28px | 600 | 1.25 | `h1` = V1 |

Rules:
- On a narrow screen (≤ 600px), `h1` drops to 20px and `.headline` to 15px. No new size is introduced.
- In print, `body` is `11pt` (≈ 14.67px). Other sizes stay in px. This is the print rendering of Body, not a fifth role.
- Long words and runs of characters without spaces wrap: `overflow-wrap:anywhere` on `h1`, `h3`, `article p` and `blockquote`.
- Quotes use `«…»`, as in phase 2. `…` inside a quote is allowed **only** where the overlap guard cut client text (R3). This is a customer-profile exception to the phase-2 rule, because the audit file keeps the full quote.
- No italic, no underline, no text links (M2 has no `<a>`).

- `:root{color-scheme:light dark}` plus `<meta name="color-scheme" content="light dark">`.
- `@media print` resets to the print column and sets `print-color-adjust:exact`, so the bar and the rules print.
- Contrast: every text color is at least 4.5:1 against `--surface` and `--bg` in its scheme (e.g. `--caution #8a5300` on `#fff` ≈ 6.3:1).

Accent reserved for:
1. the SVG bar fill (`.bar .fill`);
2. the brand line `AGENT LAB · ОТЧЁТ ДЛЯ ЗАКАЗЧИКА` in the header;
3. the 4px left rule of the first-screen card (`.first`);
4. `<summary>` text on screen (it becomes `--muted` in print).

Not accent: V1 (colored by verdict), `h2`/`h3`, the headline number, the change rows, and any label. **Color is never the only signal:**
- V1 carries its word («хорошо», «с ошибками», «плохо», «Числу пока не верить»);
- change rows carry a glyph and a word;
- the control row carries `✓`/`✗` and a word.

## M1. Summary text `[P5]` (SHARE-01)

**Format rules `[CUST]`:**
- plain UTF-8, `\n` line ends;
- no ANSI, no box drawing, no emoji; the only glyphs are `✓` `✗` `·` `—` `«»` `…`;
- no blank lines, no Markdown (`*`, `_`, `#`, backticks) and no leading `-`, because messengers restyle them;
- **≤ 15 lines and ≤ 900 characters** (`[...text].length`);
- every line goes through `plain()` and the guard.

### Line order (locked)

| # | Line | Printed when |
|---|------|--------------|
| L1 | `Agent Lab · <agent name> · <date>` | always |
| L2 | V1 verbatim (`verdictLine(view)`) | always |
| L3 | `view.headline.text` verbatim | `decided > 0` (when `decided = 0`, V1 already says «Проверенных ситуаций нет») |
| L4 | `view.headline.smallSample` verbatim | when not null |
| L5 | `Не измерено: <K> — <label>.` / `Не измерено: <K> — чаще всего <label> (<C>).` (the `resultViewLines` wording) | `notMeasured.total > 0` |
| L6 | `Главные причины провалов:` (C-14 plain form) | failures > 0 |
| L7–L9 | cause lines (below), up to 3 | failures > 0 |
| L6′ | `Провалов не зарегистрировано. Это не гарантия качества в реальном трафике.` (replaces L6–L9) | `decided > 0` and failures = 0 |
| L10 | F6 main row verbatim (C-51…C-54); no tail rows | when F6 prints it |
| L11 | control line verbatim (`Контроль: пройден ✓`, `Контроль: не пройден ✗`, `Контроль: не задан.`, …) | always |
| L12 | comparison line (below) | `view.changes` present |
| L13 | `Версия агента: <version> · ситуаций: <n>, диалогов: <m> · судья: <judge>` | always |
| L14 | `Подробности — в HTML-отчёте.` | always |

The maximum is 14 lines.

**Values:**
- `<agent name>`: `guard.text(selected revision spec.name)`, or `проверка агента` when absent.
- `<date>`: `mskDateTime(record.createdAt)`, e.g. `16 сентября 2026, 18:40 МСК` (built from `formatToParts`, `timeZone: 'Europe/Moscow'`).
- `<version>`: `record.targetVersion ?? record.targetRelease ?? 'не названа'`. M1 never prints a fingerprint.
- `<judge>`: `view.scope.judgeModel ?? 'не записан'`.

**Cause line (L7–L9):**
```
<i>. Должен был: <X> — правило <N>[ · <C> <ситуация|ситуации|ситуаций>]
```

| Part | Rule |
|------|------|
| `X` | `topCauses[i]` example expectation (`successCriteria`) → `guard.text` → lower-case first letter → shortened to ≤ 110 characters at the last space, plus `…` |
| `X`, only the rule-compliance check failed | `соблюдать правило <N>`, and the ` — правило <N>` tail is dropped |
| `X` missing or unverified | `ожидание не записано` |
| `N` | first verified rule number (phase-2 register); when there is none: ` — правило не указано` |
| `· C …` | only when the cause covers ≥ 2 situations |

- The line never contains `Сказал`, the agent quote, a rule quote, the judge's reasoning or a cause name.
- **Comparison line (L12):** `Сравнение с прошлым прогоном: исправлено <a> · сломано <b> · нестабильно <c> из <n> <сравнимой|сравнимых>.` When `n = 0`: `Сравнение с прошлым прогоном: сравнимых ситуаций нет.`
- **Budget:** while the text is over 900 characters, drop lines in this order: L12, then L4, then L9, then L8. The test uses the worst case: 99/99 counts, 494-character expectations and a 120-character agent name.

### Variants (exact, test vectors)

**A. Normal (failures, agreement, comparison):**
```
Agent Lab · Эквайринг-помощник · 16 сентября 2026, 18:40 МСК
Агент справляется с ошибками: 9 из 13 ситуаций (мало данных)
Справился в 9 из 13 проверенных ситуаций — 69%.
Мало данных: реальная доля где-то от 42% до 87%.
Не измерено: 2 — симулятор отклонился от диалога.
Главные причины провалов:
1. Должен был: объяснить порядок возврата покупки через терминал и срок зачисления — правило 7 · 2 ситуации
2. Должен был: назвать срок подключения СБП — правило 12
3. Должен был: соблюдать правило 31
Согласие с судьёй: 3 из 4 проверенных · мало проверок (провалы: 3 из 4 · успехов нет).
Контроль: пройден ✓
Сравнение с прошлым прогоном: исправлено 2 · сломано 1 · нестабильно 0 из 5 сравнимых.

Подробности — в HTML-отчёте.
```

**B. No failures:** L6–L9 are replaced by `Провалов не зарегистрировано. Это не гарантия качества в реальном трафике.`

**C. Zero decided:**
```
Agent Lab · Эквайринг-помощник · 16 сентября 2026, 18:40 МСК
Проверенных ситуаций нет
Не измерено: 13 — чаще всего сбой агента или связи (9).
Контроль: не измерен — сбой агента или связи.
Версия агента: не названа · ситуаций: 13, диалогов: 13 · судья: openai/gpt-5.6-sol
Подробности — в HTML-отчёте.
```
(With a failed or unmeasured control, V1 rules 1–3 win over rule 4; see D.)

**D. Control failed:** L2 = `Числу пока не верить: контроль не пройден`. L3–L9 print as usual; L11 = `Контроль: не пройден ✗`. The owner-side warning row (`Контроль не пройден — … проверьте судью и связь с агентом.`) is **not** printed, because it gives the owner an instruction.

**E. No agreement yet:** L10 = `Согласие с судьёй: ещё не проверено.` When F6 prints nothing (empty queue), L10 is omitted.

**F. No comparison:** L12 is omitted. There is no «сравнивать не с чем» line.

**Refused states (no file is written; notice N6/N7):**
- the run is still active (`preparing`, `evaluating`);
- the draft never ran.

## M2. Manager HTML report `[P5]` (SHARE-02, SHARE-03)

### Document rules `[CUST]`
- One file of `<!doctype html>`, `<html lang="ru">` and `<meta charset="utf-8">`, under **200 000 bytes** (target ≤ 150 000).
- Head, in this order:
  1. `viewport`;
  2. CSP `default-src 'none'; style-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none'`;
  3. `<meta name="referrer" content="no-referrer">`;
  4. `<meta name="color-scheme" content="light dark">`;
  5. `<title>Проверка агента: <V1></title>`;
  6. one `<style>` holding `MANAGER_CSS`.
- **Never present:**
  - `<script>`, `<link>`, `<img>`, `<iframe>`, `<object>`, `<embed>`, `<a>` or `<form>`;
  - `on*=` attributes;
  - `url(`, `@import`;
  - any `http(s)://` in an attribute.
- A public URL inside agent text stays as escaped **text**.
- Ids come only from counters: `id="verdict"`, `id="fails"`, `id="fail-<i>"`. They are never built from text.
- Every text value goes through `redact` → `guard` → `escape`, in that order. Only then is it placed in the template.

### Page structure (locked order)

```
<main>
  H  <header>              brand line + 5 facts
  S1 <section class="first"> V1 · headline · bar · small sample · facts · top causes
  S2 <section>             Все провалы (n)            [omitted when failures = 0]
  S3 <section>             Несогласия с судьёй (K)    [omitted when K = 0]
  S4 <section>             Сравнение с прошлым прогоном [omitted without view.changes]
  S5 <section>             Как считали
  F  <p class="note">       forwarding note
</main>
```

**H. Header.** The brand line runs across the full width. Five facts sit in a wrapping flex row, 13px, muted:

| Fact | Exact text |
|------|------------|
| brand | `AGENT LAB · ОТЧЁТ ДЛЯ ЗАКАЗЧИКА` |
| date | `Прогон: <mskDateTime(createdAt)>`; plus `, разбор: <mskDateTime(reviewedAt)>` when `reviewedAt` is set |
| version | `Версия агента: <targetVersion ?? targetRelease>`; without either: `Версия агента: не названа · метка сборки <targetFingerprint first 8>`; without a fingerprint: `Версия агента: не названа` |
| set | `Набор: <n> <ситуация\|ситуации\|ситуаций>, <m> <диалог\|диалога\|диалогов>` (`view.scope.cards`, `view.scope.dialogues`) |
| judge | `Судья: <judgeModel>` / `Судья: не записан` |
| cost | `Стоимость проверки: ≈ $<D.DD> (оценка)` / `Стоимость проверки: не записана` / `Стоимость проверки: без оплаты` (demo) |

**S1. First screen.** Nothing essential on it sits inside `<details>`. At 1024×1400 it fits above the fold with 3 causes (verified in the mockup). Row order:
1. `<h1 id="verdict" class="v-ok|v-caution|v-bad">` V1 verbatim. The class follows the phase-4 V1 tone: rule 5 → `v-ok`; rules 4, 6 → `v-caution`; rules 1–3, 7 → `v-bad`.
2. `<p class="headline">` `view.headline.text`. Omitted when `decided = 0`.
3. Bar `<svg class="bar" viewBox="0 0 100 8" preserveAspectRatio="none" role="img" aria-label="<P>%">`, with `<rect class="track" width="100" height="8" rx="4"/>` and `<rect class="fill" width="<P>" height="8" rx="4"/>`. `P = clamp(round(accuracy*100), 0, 100)`. Omitted when `accuracy === null`.
4. `<p class="muted">` smallSample. Only when not null.
5. `<div class="facts">`: one `<p>` for each of the following, in order:
   - L5 not-measured, followed by `<details><summary>Какие ситуации не измерены (<K>)</summary><ul>` with every F3 row as `<li>` (`? <guarded title> — <reason>`);
   - L11 control;
   - L10 agreement (when printed), with the F6 tail rows as `<p class="muted">`.
   - When `bundle.warnings` is non-empty, a last `<p class="muted">`: `Часть проверок не подтверждена — подробности у владельца.`
6. `<div class="causes">`: `<h2>Главные причины провалов</h2>` + `<ol class="top">` with the M1 cause lines (without the `<i>. ` prefix; the list numbers them). In the HTML, X is **not** shortened. With no failures and `decided > 0`: `<p>Провалов не зарегистрировано. Это не гарантия качества в реальном трафике.</p>` instead. With `decided = 0`: the block is omitted.

**S2. Все провалы.**
- `<h2 id="fails">Все провалы (<n>)</h2>`, then one `<article id="fail-<i>">` per failed situation, in record scenario order.
- One explanation per situation: the first failed dialogue, as in phase 2.

| Row | Markup and text |
|-----|-----------------|
| title | `<h3>` `guard.title(scenario.title, <position>)` → the guarded title or `Ситуация <position>` (1-based position in `record.scenarios`) |
| expected | `<p><span class="label">Должен был:</span> <X in full></p>`; F1 variants C-01a, C-01b, C-02, C-03 keep their wording (the label is the text before the first colon) |
| rules ≤ 2 | `<p><span class="label">Правило <N> · <source>[, строка <L>]:</span> «<quote>»</p>` (C-08); C-09 and C-10 as plain `<p>` |
| more | `<p class="label">и ещё <K> <правило\|правила\|правил></p>` (C-11) |
| violated | `<p><span class="label">Нарушено правило <N> · <source>[, строка <L>]:</span> «<quote>»</p>` (C-12) |
