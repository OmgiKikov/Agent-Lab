# Phase 3 — UI Design Contract

> Visual and interaction contract for the terminal surfaces of phase 3. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This contract extends the approved `02-UI-SPEC.md`.** Everything marked `[BASE]` there applies here without change:
> - the surfaces S1/S2/S3;
> - the spacing tokens and the hanging-indent rule;
> - the four emphasis roles and the two weights;
> - the Pi `Theme` token map;
> - the glyph registry;
> - the width, wrap and theme rules;
> - the forbidden-words list;
> - `pluralForm`.
>
> This file adds only what phase 3 needs. Where it changes a phase-2 row, it names that row and says why.
>
> **Autonomous run.** The user was asleep and asked for no questions. Every choice that the upstream artifacts left open is recorded in `## Decisions Log` with its reason.
>
> **Scope markers.**
> - `[BASE+]` is an addition to the shared base: new glyphs, keys, accent items. Phases 4–6 must keep it.
> - `[P3]` is locked for phase 3 only. Phase 4 moves the agreement block into its «Провалы» tab. It may re-lay the block out, but it must keep the wording, the row order (evidence → judge → keys → mark) and the keys.

## Spacing Scale `[BASE]` (unchanged)

The spacing tokens are the phase-2 ones. 1 column = 8 px and 1 row = 16 px (nominal, for the checker). All values are multiples of 4 px.

| Token | Terminal value | px equiv. | Phase-3 usage |
|-------|----------------|-----------|---------------|
| xs | 1 column | 8px | Gap after a glyph (`= `, `! `, `~ `, `✗ `); spaces around `·`, `—` and `→` |
| sm | 2 columns | 16px | Indent of the evidence rows, the `Причина:` row, the agreement tail rows and the disagreement detail rows |
| md | 4 columns | 32px | Wrapped continuation of an sm-indented row |
| lg | 1 blank row | 16px | After the agreement block, before today's trial rows; between two disagreement items; before and after the `НЕСОГЛАСИЯ С СУДЬЁЙ` heading |
| xl | 2 rows (blank + heading) | 32px | Between the cause section and the disagreement section (S3 section 1) |
| frame | 2 columns on each side | 16px | Unchanged |

Row columns in phase 3:
- The agreement block rows start at column 0: heading, title, lead row, `Судья:`, key hint and `Ваша отметка:`.
- Evidence rows start at column 2, as in F1.
- `Причина:` under a mark row starts at column 2.
- The agreement tail rows (F6) start at column 2.
- A disagreement item title starts at column 0, and its two detail rows at column 2.

Exceptions: none. Phase 3 adds no numbered list, so no `detailColumn` values appear.

## Typography `[BASE]` (unchanged)

The four emphasis roles and the two weights (regular, `theme.bold`) are the phase-2 ones. No italic, underline or inverse. Line height is 1 row.

| Role | Size | Weight | Line Height | Phase-3 rows |
|------|------|--------|-------------|--------------|
| Body | 1 cell | regular | 1 row | Evidence rows; the agreement row; `Судья:`; the mark row; `Причина:`; the disagreement detail rows |
| Label | 1 cell | regular, `muted` or `dim` | 1 row | The lead row («Проверьте провал…»); the agreement tail rows; the next-step row; the «изменить отметку» hint; the footer |
| Heading | 1 cell, UPPERCASE | bold, `accent` | 1 row | `ПРОВЕРКА СУДЬИ`, `НЕСОГЛАСИЯ С СУДЬЁЙ` (S3); `Несогласия с судьёй (<K>):` (S1/S2, sentence case) |
| Display | 1 cell | bold | 1 row | The situation title in the agreement block (no glyph) |

**Human reason text.** Like a quote, it is wrapped in `«…»` and shown **in full**: no `…`, `shorten`, `.slice` or `preview`. Line breaks and runs of whitespace show as one space; the stored note keeps its raw text.

## Glyph Registry `[BASE+]` (additions)

The glyphs are ASCII, so they are single-width in every font and East Asian width mode (`≠` was rejected: its width is ambiguous). Each glyph always comes with its word.

| Glyph | Meaning | Token | Introduced |
|-------|---------|-------|------------|
| `=` | The human agrees with the judge | `success` | P3 |
| `!` | The human disagrees with the judge | `warning` | P3 |
| `~` | The human could not decide | `muted` | P3 |
| `✗` / `✓` | Also used in the row `Судья: ✗ не справился` / `Судья: ✓ справился`, with the same meaning (failed / passed) | `error` / `success` | P3 reuse, same meaning |
| `→` | «was → became» between two verdicts on one row | inherits | P3 |
| `●` | Waiting for a human decision. Now also marks unmarked situations in the review queue. | `warning` | existing, scope widened |

`?` is **not** used for «не могу сказать»: in the registry it means «не измерено».

## Line Formats `[P3]`

All strings are exact. `<…>` stands for a value. Values are escaped with `safeText` (S2, S3) or `safeLine` (S1). Counts use `pluralForm` wherever a noun follows a number directly.

### F6. Agreement row in the first result block (JUDGE-05)

**Placement.** In `resultViewRows` / `resultViewLines`, it comes **after the control row and before the coverage row**. So it is part of the first block on S1, S2 and S3 section 1, and the phase-1 surface parity check covers it.

**Terms.** They come from `judgeAgreement(record)`:
- `M = checked`: current quick marks answered «согласен» or «не согласен»;
- `N = agreed`;
- `b`/`a`: the failures group (`checked`/`agreed`);
- `d`/`c`: the passes group (`checked`/`agreed`);
- `Q_fail`: failures in the review queue;
- `S`: size of the pass sample;
- `K_unsure`, `K_stale`.

**Main row.**

| Case | Exact row |
|------|-----------|
| Queue empty (`Q_fail = 0`, `S = 0`), no stale marks, no current marks | **Not printed.** |
| `M = 0` | `Согласие с судьёй: ещё не проверено.` |
| `1 ≤ M ≤ 9` | `Согласие с судьёй: <N> из <M> проверенных · мало проверок (<failPart> · <passPart>).` |
| `10 ≤ M ≤ 19` | `Согласие с судьёй: <N> из <M> проверенных — <P>% · мало проверок (<failPart> · <passPart>).` |
| `M ≥ 20` | `Согласие с судьёй: <N> из <M> проверенных — <P>% (<failPart> · <passPart>).` |

`P = Math.round(100 * N / M)`. Constants: `PERCENT_FROM = 10`; `SMALL_SAMPLE = 20` (reused from phase 1).

| Part | Condition | Text |
|------|-----------|------|
| `failPart` | `b > 0` | `провалы: <a> из <b>` |
| `failPart` | `b = 0`, `Q_fail > 0` | `провалы ещё не проверены` |
| `failPart` | `Q_fail = 0` | `провалов нет` |
| `passPart` | `d > 0` | `успехи: <c> из <d>` |
| `passPart` | `d = 0`, `S > 0` | `успехи ещё не проверены` |
| `passPart` | `d = 0`, `S = 0` | `успехов нет` |

**Tail rows.** They come under the main row, at indent 2, each only when its condition holds, in this order:

| Condition | Exact row |
|-----------|-----------|
| `M > 0` | `  Цель — согласие в 9 случаях из 10.` |
| `K_unsure > 0` | `  Человек не смог решить: <K>.` |
| `K_stale > 0` | `  Отметки устарели после смены судьи: <K>.` |

When the main row is not printed, no tail rows are printed either. If only stale marks exist and the queue is empty, print `Согласие с судьёй: ещё не проверено.` and the stale tail row.

The phrase «N из M проверенных» is kept for every M, including 1 («1 из 1 проверенных»), as CONTEXT locks it. No Wilson range is shown for agreement in phase 3.

**Examples (the acquiring runs).**
```
Согласие с судьёй: ещё не проверено.
Согласие с судьёй: 3 из 4 проверенных · мало проверок (провалы: 3 из 4 · успехов нет).
  Цель — согласие в 9 случаях из 10.
  Человек не смог решить: 1.
Согласие с судьёй: 9 из 10 проверенных — 90% · мало проверок (провалы: 8 из 9 · успехи: 1 из 1).
  Цель — согласие в 9 случаях из 10.
Согласие с судьёй: 18 из 20 проверенных — 90% (провалы: 16 из 17 · успехи: 2 из 3).
  Цель — согласие в 9 случаях из 10.
  Отметки устарели после смены судьи: 13.
```

Несогласия с судьёй (<K>):

### F10. Agreement block in the board detail pane (JUDGE-04, section 3)

The block is shown for the selected situation when all of these hold:
- the workflow is `evaluate`;
- the phase is `results_review` or `complete`;
- the situation is not a control;
- `primaryMetricId` exists and its **recorded** judge result is `pass` or `fail`.

The block comes **before** today's `trialLines` rows. The row order is locked:

```
ПРОВЕРКА СУДЬИ
<scenario.title>
Проверьте провал: сначала прочитайте доказательство.
  Должен был: <X>
  Сказал (реплика #<seq>): «<Y>»
  Правило <N> · <source>: «<quote>»
  и ещё <K> правила
  Оценено до реплики #<D>: дальше симулятор отклонился от диалога.
Судья: ✗ не справился
y — согласен · n — не согласен · s — не могу сказать
Ваша отметка: ! не согласен
  Причина: «<note>»

<today's trialLines rows>
```

| # | Row | Condition | Text |
|---|-----|-----------|------|
| 1 | heading | always | `ПРОВЕРКА СУДЬИ` |
| 2 | title | always | `<scenario.title>`. No `✗`/`✓`: the glyph would reveal the verdict before the evidence. |
| 3 | lead | judge `fail` | `Проверьте провал: сначала прочитайте доказательство.` |
| 3 | lead | judge `pass`, in the sample | `Проверьте и успех: судья мог ошибочно похвалить.` |
| 3 | lead | judge `pass`, not in the sample | `Судья счёл ситуацию успешной. Проверьте, если сомневаетесь.` |
| 4 | evidence | always | Phase-2 F1 detail rows (expected, said, rules, more, violated, cut), with **all** F1 variants. For a pass, `Сказал` is the first agent reply cited for the primary metric; otherwise C-05 (`судья не указал реплику`). A pass never shows the `Нарушено правило` row. |
| 5 | judge | always | `Судья: ✗ не справился` (`fail`) / `Судья: ✓ справился` (`pass`) |
| 6 | keys | no current mark | `y — согласен · n — не согласен · s — не могу сказать` (accent) |
| 6 | keys | current mark exists | `Изменить отметку: y согласен · n не согласен · s не могу сказать` (muted) |
| 6 | keys | stale mark and no current mark | `Ваша отметка устарела: судья сменился. Отметьте заново: y · n · s` (warning; replaces rows 6 and 7) |
| 7 | mark | current agree | `Ваша отметка: = согласен` |
| 7 | mark | current disagree | `Ваша отметка: ! не согласен`, then `  Причина: «<note>»` |
| 7 | mark | current unsure | `Ваша отметка: ~ не могу сказать` |
| 8 | spacer | always | one blank row, then today's rows |

**When the block is not shown**, the detail pane starts with today's rows, and one muted row is added at the top in place of the block:

| Situation | Row |
|-----------|-----|
| Primary metric missing, or its recorded result is `unknown` / absent | `Судья не вынес решения — отметка согласия не нужна.` |
| Control situation | `Контрольная ситуация — в согласие с судьёй не входит.` |

In both cases `y`/`n`/`s` do nothing and no notice is shown.

**Changes to today's `trialLines` (they were phase-2-era text):**
- **Replaced row.** The muted row «Вердикта человека нет. p — пройдено, n — не пройдено, v — подробно с пояснением.» becomes:
  - `Вердикта человека нет. v — оценить критерий или весь диалог.`
  - When the review is complete: `Разбор набора завершён; у этого диалога отдельного вердикта нет. v — оценить подробно.`
  - This row is omitted when the agreement block is shown, because the block already carries the keys.
- **Quick marks.** Reviews with `source: 'quick'` are **not** repeated under `ОТДЕЛЬНАЯ ПРОВЕРКА ЧЕЛОВЕКОМ`, because the block shows them. The other reviews are listed as today; phase 4 restyles them.

**Width.** Every row is wrapped with `wrapRows` (hanging indent +2), never cut. The key hint row is 52 columns. Below 52 inner columns it wraps by words at `·`, with no hanging indent (it sits at column 0 and continues at column 2).

### F11. Section-3 review header (replaces «Разбор: осталось N провал(ов)…»)

The header rows go through the frame truncation, so every text must fit its tier. There are two tiers:

| Tier | Inner width | Maximum text width |
|------|-------------|--------------------|
| wide | ≥ 48 | 48 |
| narrow | 36–47 (the board's minimum inner width is 36, at 40 columns) | 34 (2 spare columns) |

**«Проверено» means the same thing as M in F6:** only current «согласен» and «не согласен» marks count.
- `x` = queued failures with a current agree or disagree mark.
- `y` = sampled passes with a current agree or disagree mark.
- Unsure marks are **not** in `x`/`y`. They are named by the «Не решено: K» state once nothing unmarked is left, and by the F6 tail row «Человек не смог решить: K».

| State | Wide (≥ 48) | Narrow (36–47) | Token |

## Interaction Flows `[P3]`

### F13. Board: one-key mark (S3)

1. **The owner presses `y`, `n` or `s`** on a situation that shows the F10 block. The board finishes with `{ type: 'agree', answer, trialId, metricId, judgeVerdict, record, section: 'results', selected, query, pendingOnly, reviewMs }`.
2. **`y` or `s` pressed again** (the current mark already has this answer): nothing is written. The board reopens with the notice `Отметка уже стоит: <согласен|не могу сказать>.` (info). The editor is never opened for `y` or `s`.
3. **`n`, не согласен.** `n` **always** opens the editor first, even when a disagreement already exists: that is how the owner edits the reason. The editor is prefilled with the current disagreement reason, or empty if there is none. The duplicate check for `n` happens **only after** the editor closes (last row of the table below). The loop opens:
   ```
   ctx.ui.editor('Судья решил: <не справился|справился>. Почему вы не согласны? Коротко, своими словами.', <current disagreement reason or ''>)
   ```
   | Editor result | Outcome |
   |---------------|---------|
   | Cancelled (`undefined`) | Nothing saved. The board reopens on the same situation. **No notice.** |
   | Trimmed text is empty | Nothing saved. Notice `Несогласие не сохранено: напишите причину.` (error) |
   | Longer than 3000 characters | Nothing saved. Notice `Причина длиннее 3000 знаков. Сократите и попробуйте снова.` (error) |
   | Otherwise | The reason is saved verbatim as `note` (step 4) |
   | Trimmed text equals the trimmed current disagreement reason (checked last, after the rows above) | Nothing saved. Notice `Отметка уже стоит: не согласен.` (info) |
4. **Save.** `lab.addHumanReview` is called with `source: 'quick'`. The mapping is locked:
   - agree → the judge verdict;
   - disagree → the opposite verdict;
   - unsure → `unknown`.

   The lab fills the judge snapshot. The fixed notes for the other two answers are `Быстрая отметка: согласен с судьёй.` and `Быстрая отметка: не могу сказать.` These notes are never shown on screen: F10 shows the mark row instead.
5. **The board reopens** on section 3 at the same list position, which now shows the next unmarked case (F12), with one of these notices:

| Answer | Notice (kind) |
|--------|---------------|
| agree | `Отмечено: согласен с судьёй · «<title>». Проверено провалов: <x> из <Q_fail>.` (success) |
| disagree | `Отмечено: не согласен · «<title>». Итог пересчитан с учётом вашей отметки.` (success) |
| unsure | `Отмечено: не могу сказать · «<title>». В итоге остаётся оценка судьи; чтобы закрыть ситуацию, позже нажмите y или n.` (success) |
| any, on a `complete` run | the notice above + ` Разбор снова открыт: f — завершить.` |

When `Q_fail = 0`, the agree notice ends with `Проверено успехов: <y> из <S>.` instead.

6. **Errors from the lab** (the board reopens unchanged):

| Cause | Notice (error) |
|-------|----------------|
| The recorded judge verdict differs from the one the board showed | `Оценка судьи изменилась, пока вы смотрели. Проверьте ситуацию ещё раз.` |
| The judge has no pass/fail verdict (defensive; the keys are already inert there) | `Судья не вынес решения по этой ситуации — соглашаться не с чем.` |
| The metric is not the primary one (defensive) | `Отметку согласия можно поставить только на главную оценку ситуации.` |
| Any other write error | today's `inputError(error)` text |

**Autonomous change (from CONTEXT), made visible in the copy.** A quick «не могу сказать» does **not** change the headline: the judge verdict stays in the number. It is counted in «Человек не смог решить: K» and keeps the situation waiting (`●`, F11 «Не решено»). The unsure notice says this in plain words. A disagreement **does** change the number, and its notice says «Итог пересчитан».

**Forbidden (the phase-2 list applies, plus):**
- `quick`, `source`, `agree`, `disagree`, `unsure`, `stale`;
- «каппа», «метрика», «главная метрика», «версия протокола», «хеш», «TPR», «TNR»;
- any English word in a displayed string.

A unit test scans F6, F7, F10, F11 and all C-51…C-102 output for the forbidden list.

**Allowlist, so that the test can pass.** Before the scan, the test removes exactly these tokens from the text:
- single Latin key letters as whole words: `a`, `f`, `n`, `o`, `r`, `s`, `v`, `x`, `y`;
- the product name `Pi`;
- the command `/agent-lab <id8>`, where `<id8>` is 8 hexadecimal characters.

Any other Latin word left after that is a failure. Placeholder values such as `<title>` and `<note>` are record text, not our copy: the test fills them with Cyrillic fixture text.
