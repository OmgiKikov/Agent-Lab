## Flagged assumptions resolved by this plan

- **FA-LOOP-04:** acceptance — отдельный stable action; repeated accept того же hash идемпотентен, repeated run не является accept.
- **FA-LOOP-05:** acceptance не запускает и не сохраняет suite; это review metadata, которое start/save/run не читают и не требуют.
- **FA-CARD-01:** СИТУАЦИЯ, ВХОД и УСПЕХ выводят полные поля единственного Scenario; initialState показывается только непустым и необходимым.
- **FA-CARD-02:** сохранённый goal_attainment не дублируется в block: полный successCriteria уже виден под УСПЕХ.
- **FA-CARD-03:** harness rubrics не входят в вопрос принятия и не подменяют четыре обязательных поля.
- **FA-CARD-04:** НАБЛЮДЕНИЕ показывает конкретный owner-confirmed reply/tool/state channel, а не invented/generic check.
- **FA-CARD-05:** current hash version выводится после четырёх полей; CLI дожидается полного вывода current projection и только затем передаёт её full hash без reinterpretation.
- **FA-CARD-06:** единственный вопрос — `Этот тест действительно проверяет нужное поведение?`; adapter передаёт exact hash, не интерпретирует свободный текст как identity.
- **FA-DISC-06:** карточка discovery-built теста использует сохранённый provenance и тот же exact accept path.
