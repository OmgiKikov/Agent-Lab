# Phase 4 — UI Design Contract

> Visual and interaction contract for the terminal surfaces of phase 4. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This contract extends the approved `02-UI-SPEC.md` and `03-UI-SPEC.md`.** Everything marked `[BASE]` or `[BASE+]` there applies here without change:
> - the surfaces S1/S2/S3;
> - the spacing tokens, the hanging-indent rule and the `detailColumn` rule;
> - the four emphasis roles and the two weights;
> - the Pi `Theme` token map and the accent list;
> - the glyph registry;
> - the width, wrap and theme rules;
> - the key registry;
> - the forbidden-words lists and their allowlist;
> - `pluralForm`.
>
> Phase 2 `[P2]` and phase 3 `[P3]` formats keep their **wording and row order**. Phase 4 places them in tabs and in the chat block. Where this file changes an earlier string, it names the old id (C-nn) and says why.
>
> **Autonomous run.** The user was asleep and asked for no questions. Every choice that the upstream artifacts left open, including the research assumptions A3–A10, is recorded in `## Decisions Log` with its reason.
>
> **Scope markers.**
> - `[BASE+]` is an addition to the shared base: the theme module, glyphs, keys, accent items, tiers. Phases 5–6 must keep it.
> - `[P4]` is locked for phase 4 only. Phase 5 may reuse the text in HTML, but it must not reword it.
>
> **Measurements.** Every column width in this file was measured on 2026-09-17 with `visibleWidth` from the installed `@earendil-works/pi-tui@0.85.1`. Worst-case numbers use `99` (or `999` where stated) and the id `1a2b3c4d`.

## Spacing Scale `[BASE]` (unchanged)

1 column = 8 px and 1 row = 16 px (nominal, for the checker). All values are multiples of 4 px.

| Token | Terminal value | px equiv. | Phase-4 usage |
|-------|----------------|-----------|---------------|
| xs | 1 column | 8px | Gap after a glyph (`+ `, `- `, `* `, `. `, `/ `); spaces around `·` and `—` |
| sm | 2 columns | 16px | Indent of the not-measured, agreement-tail and cause detail rows (phase 2/3 rules); two spaces between the bar and «идёт» |
| md | 4 columns | 32px | Wrapped continuation of an sm-indented row |
| lg | 1 blank row | 16px | Between the block groups (B1 rows 2 → 3 → 5 → 7); between the summary group and the list on Сравнение |
| xl | 2 rows (blank + heading) | 32px | Between tab body sections (unchanged) |
| frame | 2 columns on each side | 16px | Board frame, unchanged. The entry host `Box(1, 1)` adds 1 column and 1 row of padding on each side (Pi's own chat look) |

Rules added in phase 4:
- **Comparison rows** start at column 0 with the glyph; a wrapped continuation starts at column 2 (glyph + space).
- **Tab row** separators are ` · ` (M and N tiers) or three spaces (W tier), as measured below.
- **Exceptions:** none. The `Box(1, 1)` padding is Pi's host style, not our spacing.

## Glyph Registry `[BASE+]` (additions)

All ASCII, single-width in every font and East Asian width mode. Each glyph always comes with its word, so the rows read correctly with colors off.

| Glyph | Meaning | Token | Introduced |
|-------|---------|-------|------------|
| `+` | «исправлено»: was «не справился», now «справился», agent changed | `success` | P4 |
| `-` | «сломано»: was «справился», now «не справился», agent changed | `error` | P4 |
| `*` | «нестабильно»: verdict flipped while the agent (or, for a reassessment, the answers) stayed the same | `warning` | P4 |
| `.` | «без изменений» | `muted` | P4 |
| `/` | «несравнимо — причина» | `muted` | P4 |
| `━` `─` | Progress bar fill / track (restyled: fill `accent`, track `borderMuted`) | as stated | existing, P4 restyle |
| `…` | Only as the last character of the word «оцениваю…» (P1) and in the sidebar list (existing). Never inside a word, never as a cut marker in our rows. | inherits | P4 (whitelisted) |

Not reused: `=` (agree), `!` (disagree), `~` (unsure), `?` (not measured), `●` (waiting), `◆` (control). Measured: `→ ━ ─ · — ▸ ● ◆ ✓ ✗ … «` are each 1 column in `visibleWidth`.

## Theme Module `[BASE+]` — `extensions/render/theme.ts`

One module is used by the chat block, every board tab and the progress rows. Nothing else paints.

| Export | Contract |
|--------|----------|
| `Tone` | `'text' \| 'muted' \| 'dim' \| 'accent' \| 'success' \| 'warning' \| 'error' \| 'borderMuted'` — the only foreground tokens |
| `Row` | `{ text: string; tone?: Tone; bold?: boolean; indent?: number; bg?: 'selectedBg'; anchor?: string; role?: string; segments?: { text: string; tone: Tone; bold?: boolean }[] }` |
| `PaintTheme` | `Pick<Theme, 'fg' \| 'bold' \| 'bg'>` (the test fake must implement all three and emit distinct markers per token for the light and dark fakes) |
| `GLYPH` | One const object with every glyph of the registries of phases 2–4. No literal glyph elsewhere in `extensions/render/**`. |
| `ROLE_TONE` | One map from row role (phase-2, phase-3 and phase-4 roles) to `{ tone, bold }`. Rows without an explicit tone get it from here. |
| `safeText(text)` | Moved from `cards.ts` (re-exported there). Applied to every row text and segment inside `renderRows`. |
| `wrapRows(rows, width)` | Moved from `cards.ts` (re-exported there). Word wrap with `wrapTextWithAnsi`; continuation rows start at `indent + 2`; `tone`, `bold`, `bg`, `anchor` and `role` are copied onto every continuation row. Width only through `visibleWidth`. |
| `paint(row, theme, width)` | `bold` → `fg(tone)` → for `bg` rows, pad with `truncateToWidth(styled, width, '', true)` **then** `theme.bg('selectedBg', …)`, so the background spans the full inner width. Segment rows are painted segment by segment. |
| `renderRows(rows, theme, width)` | `safeText` → `wrapRows` → `paint`. Asserts `visibleWidth(line) <= width` for every line in tests. Never emits `…`. |
| `bar(done, total, theme)` | `cells = 20`; `filled = total ? Math.min(20, Math.round(done / total * 20)) : 0`; returns segments (fill `━` accent, track `─` borderMuted). The bar is 20 columns and always sits on its own row. |
| `pickTier(texts, inner, prefix?)` | Returns the first text whose `visibleWidth` fits `inner`. With a prefix: first the first text with `w(prefix) + w(text) ≤ inner` (printed with the prefix); if none fits, the prefix is dropped and the plain rule applies (phase-3 `o`-prefix rule, generalized). The last text of every tier list is ≤ 36. |

## Chat Verdict Block `[P4]` (SCREEN-01, SCREEN-02)

### V1. Verdict line

Built by `verdictLine(view)` in `src/verdict.ts`. The first rule that matches wins.

| # | Condition | Exact text | Tone |
|---|-----------|------------|------|
| 1 | `view.control.warning !== null`, a control failed and none is unmeasured | `Числу пока не верить: контроль не пройден` | `error` |
| 2 | same, a control is unmeasured and none failed | `Числу пока не верить: контроль не измерен` | `error` |
| 3 | same, both | `Числу пока не верить: контроль не пройден или не измерен` | `error` |
| 4 | `decided === 0` or `accuracy === null` | `Проверенных ситуаций нет` | `warning` |
| 5 | `P ≥ 80` | `Агент справляется хорошо: <N> из <M> <ситуации\|ситуаций>[ (мало данных)]` | `success` |
| 6 | `50 ≤ P ≤ 79` | `Агент справляется с ошибками: <N> из <M> …[ (мало данных)]` | `warning` |
| 7 | `P < 50` | `Агент справляется плохо: <N> из <M> …[ (мало данных)]` | `error` |

- `N = headline.passed`, `M = headline.decided`, `P = Math.round(accuracy * 100)` — the **same** rounding the headline prints. So 39/49 (79.6%) reads «хорошо» next to «80%».
- The noun after «из» takes the genitive: `pluralForm(M, ['ситуации', 'ситуаций', 'ситуаций'])` → «1 из 1 ситуации», «9 из 13 ситуаций», «1 из 21 ситуации».
- ` (мало данных)` is appended when `M < SMALL_SAMPLE` (the phase-1 constant 20, exported, not re-typed).
- The thresholds `80`/`50` are named constants in `src/verdict.ts`.
- No trailing period (it is a title row). Longest measured: `Агент справляется с ошибками: 99 из 99 ситуаций (мало данных)` = 61 columns; it wraps by words below that.

### V2. «Дальше» row

Built by `nextStep(view, { runId, surface })`. `id8` = the first 8 characters of the run id. The first rule that matches wins.

| # | Condition | `surface: 'chat'` (S2a, S2b) | `surface: 'board'` (tab Итог) |
|---|-----------|------------------------------|-------------------------------|
| 1 | `view.control.warning !== null` | `Дальше: проверьте судью и связь с агентом.` | same |
| 0 | `view.pending > 0` (run not finished) | `Дальше: дождитесь конца прогона.` | same |
| 2a | the review queue has unmarked failures | `Дальше: откройте /agent-lab <id8> и отметьте согласие с провалами.` | `Дальше: откройте вкладку «Провалы» и отметьте согласие с провалами.` |
| 2b | no unmarked failures, but unmarked sampled passes | `Дальше: откройте /agent-lab <id8> и отметьте согласие с судьёй.` | `Дальше: откройте вкладку «Провалы» и отметьте согласие с судьёй.` |
| 2c | nothing unmarked, but `K > 0` queue items whose current mark is «не могу сказать» (phase-3 F11 «Не решено: K») | `Дальше: откройте /agent-lab <id8> и решите по <K> <ситуации\|ситуациям>: согласны ли вы с судьёй.` (≤ 87; wraps) | `Дальше: на вкладке «Провалы» решите по <K> <ситуации\|ситуациям>: y или n.` (≤ 61) |
| 3 | `decided === 0` | `Дальше: откройте /agent-lab <id8> и посмотрите, почему ситуации не измерены.` | `Дальше: откройте вкладку «Диалоги» и посмотрите, почему ситуации не измерены.` |
| 4 | failures (`decided − passed`) > 0 | `Дальше: повторите прогон после исправления агента.` | same |
| 5 | otherwise | `Дальше: выгрузите отчёт для заказчика.` | same |

The rules are listed in evaluation order: rule 1 (control) is checked before rule 0 (running), as CONTEXT ranks it first.

«Unmarked» = a queue item with no current mark at all (phase-3 queue). Items whose current mark is «не могу сказать» are counted separately as `K` (rule 2c). If phase 3 does not publish the counts, phase 4 adds `agreement.queue = { failures, passes, unmarkedFailures, unmarkedPasses, unsure }` (RESEARCH Open Question 1).

## Live Progress `[P4]` (SCREEN-06)

### P1. Progress text (one string, three places)

`progressView(record, now, { parallel }).text`:
```
<done> из <planned> <диалога|диалогов|диалогов> · <eta> · <money>
```

| Part | Values |
|------|--------|
| `done` / `planned` | `record.trials.length` / `plannedTrials(record)`; noun `pluralForm(planned, ['диалога', 'диалогов', 'диалогов'])` («1 из 1 диалога», «7 из 15 диалогов») |
| `eta` | `оцениваю…` while `done = 0`; `<1 мин` under 60 s; `~<N> мин` for 1–59 min (rounded, min 1); `~<H> ч` from 60 min (rounded to hours, min 1); `готово` when `done = planned` and the phase is still active (judging the last ones) |
| `money` | `$<D.DD> (оценка)` from `record.usage.costUsd` (two decimals); `цена неизвестна` when `costUsd === null`; `без оплаты` for demo runs |

- ETA = `remaining × avg(elapsedMs) / max(1, min(parallel, remaining))`. `parallel` comes from the shared `runParallel(record)`; reassess and score pass `1` (A6).
- **Width budget:** ≤ 47 columns for counts ≤ 99 and cost < $100 (measured worst: `99 из 99 диалогов · оцениваю… · $99.99 (оценка)` = 47; `… · цена неизвестна` = 47); ≤ 49 for counts ≤ 999. A test asserts ≤ 50 over the whole vector set.
- Example (CONTEXT): `7 из 15 диалогов · ~4 мин · $0.84 (оценка)`.
- `…` in `оцениваю…` is the only allowed ellipsis in our rows (glyph registry); the render-matrix «no `…` inside a word» check whitelists this exact word.

### P-rows (tool row and board header)

| Id | Row | Tone | Where |
|----|-----|------|-------|
| P0 | `bar(done, planned)` + two spaces + `идёт <M:SS>` (`<H:MM:SS>` from one hour); `now − reviewedAt` | segments (accent / borderMuted / muted) | tool row, board header |
| P1 | the progress text | `text` bold | tool row, board header, footer |
| P2 | `Сейчас: <record.message>` (escaped; wraps) | `muted` | tool row only |
| P3 | `Оценка денег: судья и симулятор, без самого агента.` (51; wraps) | `muted` | tool row, and the board header **once** under P1 |

P0 is at most 34 columns (`━…─  идёт 9:59:59`), so it fits the minimum inner width 36 without wrapping. «идёт» changes every second, so the row never looks frozen while the run is active.

**Tool row (S2c).** Rows P0, P1, P2, P3 under the call row `Проверка агента`. Partial `details`: `{ kind: 'agent-lab/progress', version: 1, progress }`. `onUpdate` fires at most once per second, and only when P0/P1/P2 text changed (P0 changes each second while active, so there is at least one update per active second). When the result arrives, the block B1 replaces these rows.

**Footer (S2d).** `ctx.ui.setStatus('agent-lab-progress', P1)` only when `ctx.hasUI && ctx.mode === 'tui'`. Same dedupe. Pi joins statuses by key order and cuts the line with `...`: to keep ours first, the older pointer key `agent-lab` is cleared when the run starts and set again after it ends (it sorts before `agent-lab-progress`). In `finally` (success, error or abort): `setStatus('agent-lab-progress', undefined)`.

**Board header (P-board).** While the phase is active, on every tab: P0, P1 (wrapped by words if the inner width is below its width), P3. Refreshed by the existing 750 ms load timer; `now` is injected through `BoardOptions`. The old row `━…  <n> / <m> диалогов · c Остановить` is removed (`c` is in footer line 1).

**After the run.** The footer status is cleared; the tool row shows B1; the board shows T1 with V1. In the preparing phase (build) the same rows are used with `planned` = the planned trials once known; before that P1 reads `Подготовка ситуаций · <eta> · <money>` with `eta = оцениваю…`.
