# Phase 2 — UI Design Contract

> Визуальный и интеракционный контракт для понимания агента и предложения одной заземлённой гипотезы. Источник решений: `02-CONTEXT.md`, `REQUIREMENTS.md` и существующие Pi/CLI-поверхности.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — новая дизайн-система не вводится |
| Preset | not applicable |
| Component library | существующие `@earendil-works/pi-tui` и нативные `ctx.ui.confirm` / `ctx.ui.editor`; CLI использует обычный stdout |
| Icon library | none; только уже принятые текстовые маркеры `✓`, `×`, `?`, `▸`, всегда вместе с подписью |
| Font | системный моноширинный шрифт терминала; приложение не задаёт гарнитуру |

Компонентный инвентарь не применяется: `Tool: none`. Исполнитель переиспользует существующие функции рендера и семантические токены `Theme`, не создаёт UI-kit, web-страницу или новый экран доски.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Theme` terminal background; fallback `#0D1117` | Общий фон разговора и CLI |
| Secondary (30%) | `text` / `muted` / `borderMuted`; fallback `#161B22` | Основной текст, ссылки на источники, рамки и вторичные пояснения |
| Accent (10%) | `accent`; fallback `#58A6FF` | Только заголовки четырёх смысловых блоков и финальный вопрос `Проверим?` |
| Destructive | `error`; fallback `#F85149` | Только ошибки чтения/валидации; разрушительных действий в фазе нет |

Accent reserved for: `ТРЕБОВАНИЯ`, `НАБЛЮДАЕМОЕ`, `НЕИЗВЕСТНО`, `ГИПОТЕЗА`, вопрос `Проверим?` и текущий фокус нативного Pi-контрола.

Статус не передаётся одним цветом: рядом всегда есть буквальная подпись `ПРОЙДЕНО`, `НЕ ПРОЙДЕНО`, `НЕЯСНО` или `ОШИБКА`. Семантические `success`, `warning` и `error` используются только для статуса, а не как декоративный акцент.

| Element | Copy |
|---------|------|

| Error state | `Не удалось прочитать записи: {причина}. Исправьте JSON/JSONL и повторите команду; агент не запускался.` |

Тон: короткий, предметный, без внутренней терминологии перед первым выводом. Использовать `тест` в разговоре; создание карточки относится к Phase 3 и здесь не обещается.

## Interaction Contract

### Primary surface and hierarchy

Главная поверхность — текущий разговор Pi. CLI `agent-lab score` и `agent_lab_build` с `mode: "score"` используют тот же offline-путь и те же смысловые заголовки. `/agent-lab`, карточки, кластеры и экспортированные артефакты остаются вторичным доказательством; пользователь не обязан открывать доску, чтобы ответить на гипотезу.

Первый полезный ответ всегда идёт в таком порядке:

```text
ТРЕБОВАНИЯ
• <ожидаемое поведение и источник владельца>

НАБЛЮДАЕМОЕ
• <конкретное наблюдение из файла/кода или диалога и ссылка на событие>

НЕИЗВЕСТНО
• <то, что доказательствами не наблюдалось>

ГИПОТЕЗА
<одна проверяемая причина конкретного сбоя>

Проверим?
```

- В каждом из первых трёх блоков показывать до трёх коротких пунктов; подробности остаются в существующем артефакте.
- `ГИПОТЕЗА` содержит ровно одну гипотезу, одно связанное требование и одно конкретное наблюдение. Несколько кандидатов не показываются списком.
- Любая ссылка на лог содержит идентификатор диалога и номер события; ссылка на репозиторий содержит путь к файлу и при наличии строку.
- Существующий код, ответ агента и сохранённый outcome подписываются как наблюдения, никогда как эталон.
- Заявленное агентом действие без наблюдаемого эффекта остаётся буквальным `НЕЯСНО`; `reply_quality` выводится отдельно от `goal_attainment`.

### Input and confirmation

1. Один раз спросить о JSON/JSONL-диалогах, если выбор ещё не дан. Пустой ответ не означает согласие продолжить без них.
2. Импорт сохраняет каждый диалог один-к-одному и исходный порядок событий; экран не сортирует события по статусу или типу.
3. `--code-only` выполняется без модельного подтверждения и явно показывает no-model copy. Платная оценка в Pi требует нативного подтверждения с лимитом вызовов; CLI требует явный `--yes`.
4. Ни score, ни подтверждение гипотезы не запускают целевого агента или симулятор.
5. Ответ «да» на `Проверим?` только передаёт принятую гипотезу следующей фазе. Ответ «нет» оставляет разговор открытым; новые материалы позволяют предложить новую одну гипотезу. Отдельный persisted workflow для гипотез не создаётся.

### Loading and feedback

- Пока читаются файлы: одна обновляемая строка `Читаю требования и записи…`.
- Пока работает судья: одна обновляемая строка `Оценено {K} из {D} диалогов…`; предыдущие progress-строки не накапливаются.
- После завершения: компактный четырёхблочный ответ и существующие пути артефактов.
- Ошибка одного файла не превращается в частичный «успех»: показать error copy, сохранить причину и предложить повтор после исправления.

### Terminal behavior and accessibility

- Все внешние тексты проходят существующий `safeText()` до рендера; ANSI, управляющие и bidi-символы из логов не исполняются.
- Основной ответ переносится по ширине терминала без горизонтальной прокрутки. Длинный фрагмент доказательства сокращается до 240 видимых символов с `…`, но рядом остаётся ссылка на полный файл/диалог/событие.
- На узкой ширине порядок блоков и вопрос не меняются; колонки не вводятся.
- Нативный фокус Pi и Enter/confirm переиспользуются. Новые горячие клавиши, модальные формы и самостоятельный экран гипотезы не добавляются.
- Цвет дополняет, но не заменяет заголовок, статус, номер события и текст ошибки.

## UI Considerations

| Category | Element(s) | Status | Resolution / Reason |

| empty | import form, evidence collection | ✅ covered | При отсутствии достаточных требований/наблюдений рендерятся задокументированные empty heading/body; гипотеза не выдумывается. |
| loading | import, score control | ✅ covered | Файловое чтение и оценка используют одну обновляемую progress-строку с фактическим счётчиком, без нового экрана. |
| error | import, score control | ✅ covered | Ошибка показывает причину и путь исправления; отдельно сказано, что агент не запускался. |
| populated | summary static content | ✅ covered | Нормальный результат содержит четыре блока в фиксированном порядке и ровно одну гипотезу с основанием. |
| partial | evidence collection | ✅ covered | Отсутствующее наблюдение выводится в `НЕИЗВЕСТНО`; слова агента не заполняют пробел доказательств. |
| overflow | summary and evidence list | ✅ covered | Блоки вертикальные, текст переносится; превью ограничено 240 видимыми символами, полный источник остаётся доступным по ссылке. |
| zero-one-many | dialogues collection | ✅ covered | Ноль записей требует явного выбора продолжить без них; одна или много записей показывают фактический `K из D`, но результат всё равно содержит одну гипотезу. |
| long-text | headings, evidence, CTA | ✅ covered | Заголовки и `Проверим?` не сокращаются; длинные данные безопасно переносятся или сокращаются только вместе со ссылкой на полный evidence. |
