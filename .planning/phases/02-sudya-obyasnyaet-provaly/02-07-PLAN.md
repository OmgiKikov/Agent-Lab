<objective>
**As a** владелец агента эквайринга, **I want to** до запуска увидеть на одном экране, что агент должен сделать в каждой ситуации и по какому правилу, подтвердить всё одним действием или поправить ожидание своими словами, **so that** проверка меряет то, что я на самом деле жду (ROADMAP Phase 2 success criterion 4; TRUST-10, TRUST-11).

This is the first TRUST plan. TRUST-10/11 are a separate, later part of the phase (02-07…02-09) so they can be cut cleanly after 02-06 if the phase runs late (CTX-23).

Decisions implemented (CTX-NN = this phase's labels):
- CTX-17 One sheet per draft: «Ситуация / Должен / Правило N: «цитата»» per situation.
- CTX-19 Confirm all in one action; `acceptDraft` covers every situation (the `acceptedTests` array already allows it).
- CTX-20 The owner's words become `successCriteria` and the goal rubric criterion verbatim; no model rewriting, no hand-edited checks.
- CTX-21 The situation is marked «ожидание изменено владельцем», the sheet says it cannot be compared with earlier runs, and the `updateDraft` guard is relaxed for judge-evaluated situations.
- CTX-22 The Pi path requires confirmed expectations through an optional `requireAccepted`; CLI `evaluate` / `run` are unchanged.
- CTX-04 / UI-D-05 The sheet uses the same rule numbers and row shape as the failure explanations.
- Pattern-map decision 7: the record-level marker copies 01-09's `positiveControlScenarioIds` pattern and is added after it.
- Pattern-map decision 8: `setExpectation` sets both `successCriteria` and the goal rubric's `passCriteria`, so confirmed one-test drafts keep `passCriteria === successCriteria`.

Assumption shift (advisory): acceptance moves from «exactly one test» to «every situation of the draft»; the whole-draft acceptance becomes primary and the one-test proposal stays as its one-situation variant (promote, not add-alongside).

Output: `expectationSheet`, all-situation acceptance, `setExpectation`, `requireAccepted`, CLI `accept` for sets.
