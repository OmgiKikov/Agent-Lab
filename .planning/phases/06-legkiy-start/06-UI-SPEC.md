# Phase 6 — UI Design Contract

> Visual and interaction contract for the terminal surfaces of phase 6 («Лёгкий старт»). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This contract extends the approved `02-UI-SPEC.md`, `03-UI-SPEC.md` and `04-UI-SPEC.md`.** Everything marked `[BASE]` or `[BASE+]` there applies here without change:
> - the spacing tokens, the hanging-indent rule and the frame padding;
> - the four emphasis roles and the two weights;
> - the Pi `Theme` token map and the accent list;
> - the glyph registry, and the rule that a glyph never gets a second meaning;
> - the theme module `extensions/render/theme.ts` (`Row`, `Tone`, `GLYPH`, `ROLE_TONE`, `safeText`, `wrapRows`, `renderRows`, `pickTier`). It stays the only painter;
> - the width, wrap and theme rules, and the render-matrix asserts;
> - the forbidden-words lists and their allowlist;
> - `pluralForm`.
>
> Phase 6 changes no phase-2/3/4 string. It adds the preparation checklist, the connection check, the start wording, the rules for what Lab says while it looks for the agent, and one row in the first result block that names the synthetic share (S7, shown only when synthetic situations exist). Where it replaces an existing string, that string is named.
>
> **Autonomous run.** The user was asleep and asked for no questions. Every choice that CONTEXT and RESEARCH left open is recorded in `## Decisions Log` with its reason. That includes research assumptions A3, A8, A9 and A10.
>
> **Revised 2026-09-17 (START-04 rewritten by the owner).** Synthetic situations built from the owner's own description, including a client's character («клиент, который матерится»), are the second, equal input of the main path next to real logs. Starting without logs is allowed and offered. `notes`, `profiles` and `withoutDialogues` are main-path inputs, not side branches, and the synthetic share is always visible. Changed here: M0, N0, N3, the Логи step rule and value, the M1 description row, the M2 logs row and its never-offered list, the M4 table and its English sentence, S5, the new S7, C-647/C-648, the forbidden list, D-14, D-15 and D-16, and the new D-24 to D-26. Where RESEARCH «START-04» (inventory rows for `profiles`, `notes`, `withoutDialogues`, and its `SIDE` regex) differs, this contract wins.
>
> **Scope markers.**
> - `[BASE+]` is an addition to the shared base: the glyph `○`, the accent item, the row roles and the allowlist words.
> - `[P6]` is locked for phase 6 only.
>
> **Measurements.** Every column width in this file was measured on 2026-09-17 with `visibleWidth` from the installed `@earendil-works/pi-tui@0.85.1`. Worst cases use counts `99`/`999`/`300` and `120 с`.

## Spacing Scale `[BASE]` (unchanged)

1 column = 8 px and 1 row = 16 px (nominal, for the checker). All values are multiples of 4 px.

| Token | Terminal value | px equiv. | Phase-6 usage |
|-------|----------------|-----------|---------------|
| xs | 1 column | 8px | Gap after a step glyph (`✓ `, `▸ `, `○ `); spaces around `·` and `—` |
| sm | 2 columns | 16px | Indent of the «Что сделать» row and of the `Текст ошибки` row; wrapped continuation of a step row (glyph + space) |
| md | 4 columns | 32px | Wrapped continuation of the «Что сделать» row (indent 2 + 2) |
| lg | 1 blank row | 16px | In S2e: between the K-rows and the checklist rows. Pi adds its own blank row above the widget area; the widget adds none. |
| xl | 2 rows | 32px | Not used in phase 6 |
| frame | 2 columns on each side | 16px | **S4 widget:** `inner = width − 4`; each line is prefixed with 2 spaces, and the right 2 columns stay empty. So a 40-column terminal gives inner 36, the same minimum as the board. |

Row columns:
- the heading and step rows start at column 0 (inside the frame);
- a wrapped step row continues at column 2, under the label (phase-4 comparison-row rule);
- the «Что сделать» row starts at column 2 and continues at column 4;
- K-rows start at column 0 and continue at column 2; `Текст ошибки` is at column 2.

Exceptions: none.

## Glyph Registry `[BASE+]` (one addition)

| Glyph | Meaning | Token | Introduced |
|-------|---------|-------|------------|
| `○` | «шаг впереди»: a preparation step that is not done and is not current | `muted` (or `error` with its failure word, role `prep-todo-failed`) | **P6 new** — `GLYPH.todo` |
| `✓` | Reused with its registry meaning «пройдено / подтверждено»: a done step | `success` | P6 reuse, same meaning |
| `▸` | Reused with its registry meaning «выбрано / вы здесь»: the current step | `accent` | P6 reuse, same meaning |

- Measured with `visibleWidth`: `○ ✓ ▸` are each 1 column.
- `○` was unused in the phase-2/3/4 registries (checked: `●` is «ждёт решения человека», `◆` is «контроль»).
- A failed connection is **not** drawn with `✗` (that glyph means «ситуация провалена»). The failure is told in words (`отказ соединения`) and color. The current step keeps `▸`, so exactly one `▸` exists.
- Every step row reads correctly with colors off. `✓ ▸ ○` are three different shapes, the heading says `шаг <k> из 6`, a done row carries its value, and the current row has «Что сделать» under it.

## Preparation Checklist `[P6]` (START-02)

### State → steps

`preparationChecklist(state)` is pure. It reads the remembered connection, the in-session check result, the last preflight result (`found`) and the last draft (`store.get(lastDraftId)`, including its `notes`, `profiles` and the `provenance` of its situations). Nothing is stored separately (CONTEXT).

Steps and order are locked: **Агент → Требования → Логи → Связь → Бюджет → Запуск**.

| # | Step (label) | Done when | Value when done |
|---|--------------|-----------|-----------------|
| 1 | `Агент` | a connection is known (remembered or just used), or the draft target is not `sandbox` | `<name>`: for a command target, the basename of the first argument that is an existing file, else the command basename; for HTTP, `<host>:<port>`; for a module, the file basename. Escaped, wrapped, never cut. |
| 2 | `Требования` | `draft.requirements.length > 0`, or `found.materials > 0` | `<N> <правило\|правила\|правил>` (from the draft), or `<N> <файл\|файла\|файлов>` (before a draft) |
| 3 | `Логи` | Real logs: `draft.dialogues.length > 0`, or `found.dialogues > 0`. **Or the owner's description instead of logs** (START-04): a draft with no dialogues whose `notes` is not empty or whose `profiles` list is not empty. `withoutDialogues` alone, with no description, never marks it done. | Logs: `<N> <диалог\|диалога\|диалогов>`, plus ` · исключено <K>` when the draft has K > 0 exclusions. Description: `по вашему описанию`. In both cases, when the draft has T > 0 situations and M > 0 of them have `provenance: 'synthetic'`, append ` · синтетических <M> из <T>` (the synthetic share is always visible). The owner's own words are never shown here. |
| 4 | `Связь` | `check.status === 'ok'` and `check.targetKey` equals the fingerprint of the current target | `агент ответил за <S> с` (S = ms / 1000, one decimal, **decimal comma**: `2,4`; `0,1` minimum) |
| 5 | `Бюджет` | a draft exists and its phase is `review` or later (the owner approved the build and its limit in the native build dialog) | `до <N> <вызова\|вызовов\|вызовов> модели` from `draft.settings.maxCalls` |
| 6 | `Запуск` | never shown as done: the widget hides once the run starts | — |

Rules:
- **Current** = the first step, in order, that is not done. There is exactly one current step while the widget is shown.
- A step **after** the current one keeps its truth: `✓` with its value if it is done (for example, the connection passed but logs are still missing), `○` otherwise.
- A failed connection that is **not** current is drawn as `○ Связь — <short>` in `error` (role `prep-todo-failed`), with no «Что сделать» row. The chat text K1–K3 carries the next step.
- **Hidden** = the last draft has started (`reviewedAt !== null`, or it has trials). A new draft (for example after «повтор») shows the widget again, because its run needs the check and the start once more.
- `k` in the heading = the number of the current step (1–6).

### Width tiers (inner = terminal width − 4)

The layout is one vertical list at every width. There is no horizontal stepper (Decision D-06). Tiers only decide what wraps.

| Tier | Terminal / inner | Behavior (measured) |
|------|------------------|---------------------|
| W | ≥ 76 / ≥ 72 | Every fixed row is on one line: heading 34; step rows ≤ 62 with worst-case counts and the synthetic share (`✓ Логи — 300 диалогов · исключено 300` = 37; `✓ Логи — по вашему описанию · синтетических 20 из 20` = 52; `✓ Логи — 300 диалогов · исключено 300 · синтетических 20 из 20` = 62); Fixed «Что сделать» rows N1, N2, N4, N6, N7, N9, N10 are ≤ 66 + indent 2 = 68, so they fit on one line. N0 (123 + 2), N3 (102 + 2) and N8 (77 + 2) wrap once. The N5 rows (K3 texts, 63–132 + 2, measured) take one or two lines. Record names wrap only if longer than the row. |

## Connection Check `[P6]` (START-03)

### What is checked

`checkConnection(target, signal)` does two things: the static `preflightTarget` checks, then **one** real agent turn with the fixed user line `Здравствуйте`. It makes no call to Lab models or OpenRouter. The agent's reply text is **never shown or stored**; only the time in ms is kept.

**The honest cost line** is used everywhere the check is announced: `бесплатно для Lab · один короткий запрос к агенту`. The agent itself may call its own model on that turn (acquiring: one GigaChat call through the mock), so the words «бесплатно» are always tied to «для Lab».

### M3. Retelling a failure in chat (model rule, locked in the skill)

After a failed check the model:
1. repeats K1, K2 and K3 **verbatim**;
2. if a start-instructions file of the agent was read in this session (`README*`, `LOCAL*`, `docs/*run*`, `docs/*start*`), adds exactly one row: `В <file name> для запуска: <command 1>; <command 2>.`. The commands are copied **verbatim** from that file, at most 3, and only the ones that start the parts named in K2 (the server, the mock, the service). Example for the acquiring agent: `В LOCAL.md для запуска: ./local/run-mocks.sh &; ./local/run-app.sh &.` (the file name and commands are record values; SKILL.md and the scan use a Cyrillic fixture such as `В ИНСТРУКЦИЯ.md для запуска: ./запуск-заглушки.sh.`);
3. if no such file was found, adds: `Инструкцию запуска в папке агента не нашёл — спросите разработчика агента, как его запустить.`;
4. ends with: `Когда исправите, напишите «проверь связь» — проверю снова, бесплатно для Lab.` (77);
5. **never** runs those commands itself, never stops or restarts the agent's services, and never proposes a paid step while the check has failed.
