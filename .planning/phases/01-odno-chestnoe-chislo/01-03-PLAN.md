<objective>
Make a repeat of an old external-agent run comparable with its source, and make a validation build survive colliding goal ids — both are identity bugs.

Decisions implemented:
- CTX-20 `goalObservation` default is normalized at comparison time (card identity in `compareRuns`), not at schema parse; the scattered defaults (`experiment.ts:69-70, 358, 369, 526, 605`; `contracts.ts:431`) collapse to one constant plus helpers in `src/normalize.ts`. Planner choice: the constant itself lives in `src/contracts.ts` next to `goalObservationSchema` (the contract layer already owns `DEFAULT_JUDGE`), because `normalize.ts` imports contracts and a value import back would create the first import cycle in the project.
- CTX-21 In the replay branch of validate, `goal.id = dialogue.id` right after extraction, before exclusions and checks.
- CTX-26 `JUDGE_PROTOCOL` unchanged.
- Research defect D1 (judge-audit completeness checked with raw sources) is fixed here; RESEARCH Pattern 3 (per-pair audit completeness) is included because one judge rejection would otherwise make the live TRUST-05 diff incomparable.

Purpose: success criterion 2 (repeat vs original through `diff` is comparable) and the first half of criterion 3 (build does not fail after paid calls).
Output: `src/normalize.ts`, fixed `compareRuns`/`verdictSummary`, collapsed defaults, harness-assigned goal ids.
</objective>
