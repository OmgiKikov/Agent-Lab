# Переработка пользовательского пути Agent Lab

Статус: **первый рабочий проход реализован в существующем расширении Pi; пользовательская приёмка остаётся открытой**.

Интерфейс остаётся в Pi. После уточнения владельца работа перенесена из отдельного прототипа в реальные `extensions/agent-lab.ts` и `extensions/cards.ts`. Новые платные прогоны не запускались; сценарий проверен штатным учебным агентом через настоящее расширение и Pi.

## Уже в рабочем расширении

- История и `agent_lab_inspect` читают без writer-lock; просмотр не помечает чужой прогон прерванным.
- Прогон с доски принадлежит сессии Pi, а не экрану: закрытие доски не отменяет работу. Остановка — отдельное действие с подтверждением. Закрытие Pi по-прежнему завершает его работу.
- Короткий уникальный id прогона разрешается в истории; неоднозначность называется словами.
- Enter последовательно ведёт по ожиданиям → подтверждению запуска → результату → объяснению → диалогу. `d` открывает технические подробности; Tab переключает разделы.
- В ожиданиях рядом с целью и критериями видна начальная реплика клиента. На первом экране нет общих формулировок рубрик вместо ожидания.
- Итог кратко перечисляет причины; полный текст и все непригодные ситуации доступны в подробностях, отдельный разговор — из разбора.
- Прогресс на доске, в инструменте и подвале использует одну функцию и данные записи. Неизвестная цена остаётся неизвестной; ненадёжная ETA не выдумывается.
- Повтор создаёт полный исходный набор, а не молча одну выбранную ситуацию.

## Проверка рабочего изменения

- Полный snapshot-run: **584/584 теста**, extension typecheck пройден. `dist/` рабочего дерева не пересобирался: изменения находятся в TS-расширении.
- В настоящем Pi, в отдельной временной папке, пройден штатный маршрут: создать учебный набор → Enter подтвердить → Enter открыть план → запуск → итог → объяснение → разговор → история → повтор.
- Получены реальные записи: исходная `results_review` с 3/3 попытками и новый `review` с теми же 3 ситуациями, без попыток. Это тест работающего пути, а не имитация его записей.
- Отдельные регрессионные тесты проверяют чтение при занятом lock, продолжение фонового прогона после ухода с доски и освобождение lock по завершении.
- Остаются задачи для следующего прохода: более удобный ввод/выбор материалов, восстановление чат-блока после переоткрытия сессии, полноценный экран сравнения. Текущий пользовательский опыт не считается принятым без проверки владельцем.

## Исходные проблемы

1. Нет очевидного следующего действия; история, текущий запуск и повтор смешаны.
2. В карточке конкретное ожидание тонет в общих рубриках и технических полях.
3. Результат смешивает итог, непригодные измерения и подробную диагностику.
4. Ошибка блокировки обещала просмотр, но обработчик `/agent-lab` вызывал `lab.init()` до `showBoard`. Чтение требовало writer-lock, хотя `ExperimentStore.get()` его не требует.
5. Уход с доски во время активного прогона предлагал остановку. Просмотр интерфейса и управление заданием теперь разделены.

## Единый путь

| Экран | Что человек понимает | Главное действие | Дополнительно |
|---|---|---|---|
| История | Что сейчас выполняется, где прошлый результат | Проверить агента / вернуться в прогон | Открыть прошлый результат |
| Подключение | Агент, материалы, диалоги, связь; что готово | Подготовить проверки | Исправить недостающий вход |
| Подготовка | Текущий этап и последняя активность | Открыть готовый набор по завершении | Уйти в историю без отмены |
| Ожидания | Вопрос клиента → конкретное ожидание → источник | Подтвердить ожидания | Изменить текст, прочитать все цитаты |
| Подтверждение запуска | Что запускаем, как считаем, лимиты и неизвестная цена | Запустить проверку | Вернуться к ожиданиям |
| Прогон | Что завершено и чего ждём; неполные данные не маскируются | Смотреть готовые диалоги | Явно остановить с подтверждением |
| Результат | Сколько измерено; сколько не измерено; что разбирать | Разобрать первый провал | Причины «не измерено», история, повтор |
| Разбор | Ожидание → фактическая реплика → цитата | Открыть разговор | Согласиться / оспорить решение |
| Повтор | Тот же набор; новый запуск сохраняется отдельно | Подготовить повтор | Проверить изменения и сравнимость |

## Контракты интерфейса

- Один главный CTA закреплён внизу и остаётся видим при прокрутке.
- Enter — главное действие, Esc — назад (из записи — в историю), `q` — закрыть доску. Выход и история не отменяют работу; закрытие самого Pi останавливает принадлежащую ему работу.
- ↑↓ выбирают ситуацию; PgUp/PgDn прокручивают её содержание.
- Разбор начинается с доказательства; служебные рубрики, журналы и идентификаторы доступны глубже.
- «Не измерено» — отдельный список с причиной и соответствующим следующим действием.
- Новую денежную оценку не выдумываем. Если цена неизвестна, пишем это и показываем лимиты.
- Процент подготовки не рисуем, когда общее количество работы неизвестно.
- Изменение ожидания снимает подтверждение. Историческую оценку под изменённое ожидание не подставляем.
- При повторе критерии сохраняются; если они изменены, несовместимость сравнения сообщается до интерпретации результата.
- Реальные цитаты, реплики и персональные данные не включаются в этот документ или коммиты.

## Как открыть рабочее изменение

Обычная команда проекта — `npm run pi`, затем `/agent-lab`. Отдельные демонстрационные скрипты и прототипы для этого пути не используются.

## Пользовательская приёмка

Согласовать с владельцем три наблюдаемых вещи:

1. Можно ли без объяснений понять, что делать следующим шагом?
2. Достаточно ли конкретна карточка на первом экране, без раскрытия рубрик?
3. Можно ли по результату найти причину, открыть реплику и вернуться, не потеряв место?

После проверки владельцем уточнить содержание первого экрана и ожиданий. Не считать прохождение автоматических тестов доказательством понятности UX человеку.
