# Разговорный UX Agent Lab

Основной интерфейс — разговор в Pi. Четыре этапа «Логи → Сценарии → Прогон → Результаты» остаются логикой продукта, но не маршрутом по экранам. Доска `/agent-lab` — дополнительный инструмент для массовой работы.

## Что мешает сейчас (проверено по коду ddff5ee)

1. `agent_lab_scenarios edit` отклоняет любую правку от модели, кроме удаления: факты, тексты и группировка правятся только через формы доски (`e`, `v`, `m`).
2. Синтетический вариант с доски — пять форм подряд; инструмент требует готовые `parentId/factId/opening/ifAsked`.
3. Каждая строка ленты называется «Проверка агента», результат — JSON с хешами.
4. `agent_lab_run` держит разговор до конца прогона (6–17 минут); Esc одновременно прерывает действие и останавливает прогон.
5. Нет инструмента «что у нас есть»: список прогонов виден только на доске.
6. Системный промпт и skill учат модель отвечать клавишами («раздел 2, `e`, `g`»).

## Изменения

1. **Операции из разговора** — те же методы `ExperimentLab`, без параллельной логики.
   - `agent_lab_status`: прогоны, активная работа, три состояния — черновик / принятый набор / выполняемый снимок.
   - `agent_lab_scenarios`: объекты называются словами (название, номер в списке, id); неоднозначная ссылка возвращает кандидатов. Правка черновика от модели допустима, только когда её основание — реальное сообщение владельца в этой сессии (расширение читает его само из `sessionManager`, модель подставить его не может). Новые значения фактов и текстов должны дословно встречаться в словах владельца или в самой карточке; иначе правка не пишется, а модель получает конкретный вопрос к владельцу. CAS по хешу библиотеки сохраняется: хеш ведёт расширение.
   - Синтетический вариант одной фразой: родитель, факт, первая реплика без значения, условие раскрытия и название отсутствующих данных выводятся из карточки; результат — «было → стало».
   - После правки смысловая проверка запускается сама в пределах согласованного бюджета; если бюджета мало — объяснение и отдельное разрешение.
   - Принятие («готовые», перечисленные) — одно native-подтверждение со списком; запуск — отдельное подтверждение показанного плана.
   - `agent_lab_run`: короткий прогон завершается в той же строке; длинный уходит в фон, разговор свободен. Esc прерывает действие, но не прогон; остановка — отдельная операция.
   - `agent_lab_inspect`: «второй провал», диалог, требование, сравнение с исходным прогоном.
2. **Лента**: строка вызова — что делается, словами; результат — краткая сводка, по `Ctrl+O` — детали (карточка, источник, диалог, было → стало). JSON и хеши остаются только в содержимом для модели. В `details` сессии — только идентификаторы (REV-01); строки пересобираются из `.agent-lab`.
3. **Прогресс**: виджет над вводом из записи прогона (завершено / запланировано / непригодные / расход); по завершении — блок-вердикт в ленте и ход модели.
4. **Промпт и skill**: разговорный цикл, запрет отвечать клавишами, уточнение при неоднозначности.
5. **Документация**: README и спецификация — намеренное изменение UX; правила измерений не меняются.

## Не меняется

Runner, оценщик, хранилище, неизменность принятых снимков, single-writer lock, отделение диагностики от метрики, происхождение фактов. Замечания прошлого ревью не считаются исправленными.

## Проверка

- Автотесты и typecheck — в снимке `git archive`/копии, `dist` живой сессии не трогается.
- Реальный Pi в tmux на учебном наборе: логи → сценарии → источник → правка сообщением → синтетический вариант → принятие → запуск → результат → провал → повтор. Отдельно: узкий терминал, длинный русский текст, вставка путей и многострочного ввода, отмена, ошибки инструментов, восстановление сессии; проверяются записи в хранилище, а не только экран.
- Автотесты, модельные вызовы и проход интерфейса отчитываются отдельно.
