# Agent Lab

## What This Is

Agent Lab — локальный помощник, который изучает репозиторий и доступные логи агента, предлагает полезную гипотезу о сбое, сам собирает проверяемый тест, запускает настоящего агента и показывает доказательства. Владелец принимает или правит сам тест, после чего тот сохраняется для повторных прогонов.

Карточки, судья, хранилище и отчёты обслуживают этот разговор. Постоянная ручная разметка каждого результата не является основным сценарием: человек подключается для принятия теста, спорных случаев и проверки качества автоматического оценивания.

## Core Value

Прочитать агента и его требования, предложить полезный тест, запустить его на настоящем агенте, показать доказательства и сохранить принятый тест как регрессию.

## Requirements

### Validated

- ✓ Ручной разбор отдельных диалогов поддерживает спорные случаи и калибровку автоматической оценки, не становясь обязательным шагом каждого прогона. — Phase 1
- ✓ Репозиторий, требования и доступные логи превращаются в заземлённое понимание ожидаемого и текущего поведения; существующий код и ответы агента не считаются эталоном. — Phase 2
- ✓ Agent Lab предлагает конкретную гипотезу о сбое и объясняет, почему её стоит проверить. — Phase 2
- ✓ Из принятой гипотезы собирается минимальный тест: ситуация, входные данные, критерий и наблюдаемое доказательство. — Phase 3
- ✓ Тест запускается на настоящем агенте, а результат показывается как короткая цепочка «диалог → проверка → доказательства». — Phase 4
- ✓ Пользователь принимает или правит сам тест; acceptance точного теста сохраняется вместе с regression suite и переживает повтор без смыслового дрейфа. — Phase 5

### Out of Scope

- Веб-интерфейс, очередь и коннекторы к лог-платформам — MVP остаётся локальным CLI/Pi-инструментом.
- Автоматическое исправление агента и развитие `agent_lab_prompt` — текущий MVP только проверяет и повторно тестирует.
- Обязательная ручная проверка каждого результата — ручной разбор нужен только для принятия теста, спорных случаев и калибровки судьи.
- Надёжность или калибровка судьи как общее обещание, статистическая значимость и обобщение малого набора на production-трафик — данных для таких утверждений нет.
- Сравнение симуляции с production — отдельное описательное исследование после MVP.
- Simulator scorecard, `modeValue`, сравнение пользовательских режимов, paired-family delta, отдельные statistics/comparison surfaces и `preset: thorough` — удалены срезом 2026-09-15.
- TUI-редактор, `preview`, `clarify`, аудит судьи и pilot-сводка — удалены; карточки правятся через `agent_lab_edit`.
- Генерация `profileId`, `persona`, `characteristics`, `cannotKnow` и `external` — поля читаются только как legacy и не возвращаются в текущую генерацию.
- Сторонние фреймворки оценивания агентов — новые зависимости для MVP не подключаются.

## Context

Проект уже существует как TypeScript-библиотека, CLI и расширение Pi. `ExperimentLab` управляет фазами и хранением, `Runtime` изолирует роли модели, `TargetSession` подключает испытуемого, а JSON/JSONL-трассы и записи являются источником доказательств.

Авторитетный технический MVP-срез задан документами от 2026-09-15. Вариант Simulator v1 от 2026-09-14 сохранён только как исторический контекст и не определяет текущий scope. Задачи исходного плана 1–18 остаются техническим backlog, но пользовательский путь теперь организован вокруг предложения, принятия и повторного запуска теста, а не вокруг ручной разметки и отчётов.

Первый пилот использует банковские команды и AIGW, но ядро остаётся предметно-независимым. Для P1 второй агент — инкассация в Sigma; для P2/P3 набор из 15 диалогов эквайринга служит источником гипотез и доказательств, а не обязательной очередью сплошной ручной разметки.

## Constraints

- **Runtime**: TypeScript ESM на Node.js >=22.19 с `strict`-проверкой — это существующая и целевая среда пакета.
- **Dependencies**: использовать текущие zod 4, typebox и Pi SDK 0.85.1; новых runtime-зависимостей не добавлять — MVP сокращает, а не расширяет стек.
- **Language**: пользовательские строки и документация на русском; код, идентификаторы и команды на английском — единый контракт источников от 2026-09-15.
- **Compatibility**: старые JSON должны открываться и переоцениваться без миграции; удаляемые поля остаются optional legacy и не отвергаются схемой.
- **Evidence**: JSON-записи, события и сохранённые материалы — источник истины; слова агента о ненаблюдавшемся действии не являются доказательством.
- **Architecture**: жизненный цикл проходит через `ExperimentLab`; существующие швы `Runtime` и `TargetSession` не меняются.
- **Quality**: после каждого изменения зелёные `node:test` через `tsx`, `npm run build` и typecheck; ошибки и частичные трассы сохраняются, а не превращаются в проход.
- **Timeline**: демонстрационная способность должна существовать после задач 1–10; целевая дата демо из спеки — 2026-09-21.
