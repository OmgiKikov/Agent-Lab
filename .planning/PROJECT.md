# Agent Lab

## What This Is

Agent Lab — пакет для Pi, который прогоняет настоящего AI-агента на реальных диалогах и отвечает понятным языком: насколько хорош агент, где и почему он ошибается и чему в этой оценке можно верить. Он для трёх людей: владельца агента, который запускает проверку сам; менеджера заказчика, которому нужен ответ «хорош ли агент»; новичка, который впервые ставит Lab на своего агента без нашей помощи.

Этот проект доводит работающий MVP до продукта топ-уровня: числу можно верить, результат понятен без объяснений, начать легко, и всё выглядит красиво.

## Core Value

Владелец агента и заказчик за 10 секунд понимают, насколько хорош агент и почему он ошибается, и верят этому числу.

## Business Context

- **Customer**: банковская команда заказчика пилота (менеджер заказчика смотрит результат) и владельцы AI-агентов, которые проверяют своих агентов.
- **Revenue model**: пилот; модель монетизации не обсуждалась.
- **Success metric**: на демо 2026-09-21 заказчик понимает результат без объяснений; человек согласен с судьёй не меньше чем в 90% проверенных случаев (цель; при малом числе проверок показывается как «N из M»).
- **Strategy notes**: обещания созвона 2026-09-14 — accuracy по карточкам, объяснение каждого провала правилом промпта; следующим шагом заказчик хочет оценить тем же судьёй прод-диалоги и сравнить с тестом.

### Active

<!-- Цели этого проекта. Гипотезы до проверки на настоящем агенте. Всё — к демо 2026-09-21. -->

**Числу можно верить**
- [ ] Повтор старого внешнего прогона остаётся сравнимым с исходным: дефолт `goalObservation` не делает карточки «изменившимися».
- [ ] Совпадение id цели у двух диалогов не роняет всю сборку `validate` после оплаченных вызовов.
- [ ] CLI `score` масштабирует бюджет по числу диалогов так же, как Pi.
- [ ] Аудит судьи не раздувает запись прогона до лимита чтения в 50 МБ.
- [ ] Повторный прогон того же набора даёт то же число; карточки, у которых результат меняется между повторами, помечены.
- [ ] До запуска владелец одним экраном видит ожидания: что агент должен сделать и по какому правилу. Одним действием подтверждает их или поправляет.
- [ ] В результате есть контрольная ситуация, с которой агент справляется, чтобы «0 из N» нельзя было принять за сломанного судью.

**Сильный судья**
- [ ] Каждый провал объясняется в виде «должен был X → сказал Y → правило N», с цитатами из диалога и требований.
- [ ] Судья реже оставляет «без решения»: решение выносится везде, где есть доказательства.
- [ ] Человек соглашается или не соглашается с провалом одной клавишей; экран показывает долю согласия (цель ≥90%).
- [ ] В проверку иногда подмешиваются случаи «справился», чтобы согласие ловило и ошибочные похвалы судьи.

**Понятный и красивый результат в Pi**
- [ ] После прогона в чате появляется блок-вердикт. В нём одна главная строка с одним знаменателем, три главные причины, понятно названное «не измерено» и следующий шаг, без внутреннего жаргона и без обрезанного текста.
- [ ] Полноэкранная доска с вкладками «Итог / Провалы / Диалоги / Сравнение»: из провала можно перейти в диалог с подсвеченной репликой и там же согласиться или не согласиться.
- [ ] Визуальный язык един для блока, доски и прогресса: цвета, полосы, выравнивание, аккуратный перенос строк.

**Для заказчика**
- [ ] Короткая текстовая выжимка, которую владелец копирует в мессенджер или почту.
- [ ] Красивый лёгкий HTML-отчёт одним файлом, понятный менеджеру без Pi.
- [ ] В версии «для заказчика» нет сырых реплик клиентов, а персональные и внутренние данные замаскированы.

**Лёгкий старт**
- [ ] Новичок пишет одну фразу («проверь агента в этой папке, логи тут»), и Lab сам находит промпт, точку входа и логи.
- [ ] Подготовка идёт по чек-листу на экране: агент → требования → логи → связь → бюджет → запуск.
- [ ] Во время прогона виден живой прогресс: пройдено диалогов, сколько осталось времени, сколько потрачено денег.
- [ ] В разговоре Lab ведёт только по основному пути; побочные ветки скрыты (код удаляется после демо, если не понадобится).

**Демо**
- [ ] Демо показывается на сохранённом прогоне эквайринга, записанном на замороженном коде, без вызовов модели.

### Out of Scope

- Агенты с инструментами и проверка итогового состояния (`tool`/`state`) — проект оценивает prompt/RAG по наблюдаемому ответу.
- Подсказка правок промпта и автоматическое исправление агента — агента сейчас не исправляем.
- Исправленная версия агента эквайринга для экрана «до и после» — не делаем: агента сейчас не исправляем. На демо показываем сохранённый прогон текущей версии.
- Прод: прогон настоящего прод-агента на том же наборе и сравнение с тестом — отложено решением пользователя 2026-09-16 («пока не нужен»). Доступ к прод-агенту, когда понадобится, — HTTP-адрес с токеном.
- Оценка записанных прод-диалогов тем же судьёй — не делаем в этом проекте.
- Реальная среда заказчика (ИФТ, авторизация IdP) — работаем локально с моками.
- Демо за минуту на встроенном примере — отложено: к 2026-09-21 не выбрано.
- Автоматическое написание адаптера к чужому агенту — отложено: репозитории слишком разные, проверить не на чем, кроме эквайринга.
- Второй агент (инкассация в Sigma) — его делает другой человек.
- Веб-приложение — интерфейс только Pi; HTML-отчёт остаётся файлом, это не приложение.
- Отдельная сессия ручной разметки — согласие человека собирается на доске, пока он смотрит провалы.
- Сторонние фреймворки оценки (GEPA, promptfoo, LangWatch Scenario) как зависимости — решение ревью 2026-09-16.
- Универсальная eval-платформа с логами и CI в центре — поправка пользователя 2026-09-09.

## Context

- **Код.** Проект — TypeScript-библиотека, CLI (`src/cli.ts`) и расширение Pi (`extensions/agent-lab.ts`, `extensions/cards.ts`). `ExperimentLab` (`src/experiment.ts`) управляет фазами, `ExperimentStore` хранит JSON-записи и JSONL-журналы, `Runtime` изолирует роли модели, `TargetSession` подключает испытуемого. Карта кода — `.planning/codebase/`.
- **Пилотный агент.** Банковский RAG эквайринга `aigw-local`: запускается локально с моками, на gigachat, baseline `27d56d6`; Lab подключается через `aigw-local-baseline/local/agent_lab_target.py`. Прогоны лежат в `lyon/.agent-lab`. Последний прогон `fae4ee59`: «цель достигнута в 0 из 9», 4 без решения, 27 диалогов исключено, $1.88, 6 мин.
- **Первый экран сейчас.** Текущий `summary` стыдно показывать. В главной строке несколько знаменателей («0 из 9», «0 из 10», «без решения 4», «разобрано 0 из 13»). Причины обрезаны на полуслове. Много внутреннего жаргона («карточки», «пометки симулятора», «судья не сверен с человеком»). Главная причина исключений скрыта за словом «прочее».
- **Подтверждённые дефекты.** См. `.planning/codebase/CONCERNS.md`: несравнимость повтора после дефолта `goalObservation`; падение `validate` при совпадении id цели; `fail` → `unknown` на каналах `tool`/`state`; CLI `score` без масштабирования бюджета; аудит судьи внутри записи; хук выпуска с фоновым сервером; stdout адаптера трактуется как протокол.
- **История.** Прежний MVP-конвейер (фазы 1–5, закрыт 2026-09-16, коммит `7821e93`) сделал тест-центричный цикл; затем основным путём стала validation accuracy (`8b3f9db`). Уроки: судья с правилом «всегда возвращай JSON» давал ложные провалы (исправлено, протокол судьи 7+); слои строгости росли вокруг неверного числа.
- **Рабочая среда.** В том же worktree могут работать другие сессии. `npm test` пересобирает и удаляет `dist/`, который импортирует живое расширение Pi, поэтому тесты для ревью гоняются из снимка `git archive HEAD`. Доказательства из `.agent-lab` копируются наружу до удаления workspace: однажды они уже пропали вместе с ним.

## Constraints

- **Interface**: только Pi — весь опыт внутри Pi; HTML-отчёт — файл для пересылки. Так решил пользователь (2026-09-08, подтверждено 2026-09-16).
- **Timeline**: всё к демо заказчику в понедельник 2026-09-21. Фазы упорядочены по важности для заказчика: при нехватке времени недоделанным остаётся хвост, а не то, что видит заказчик.
- **Evidence**: каждая фаза проверяется на настоящем агенте эквайринга, а не только unit-тестами. Работа засчитывается, только если заканчивается наблюдаемым результатом.
- **Tech stack**: TypeScript ESM, Node.js >=22.19, `strict`; zod 4, typebox, Pi SDK и `pi-tui` 0.85.1. Новые runtime-зависимости добавлять только с явной причиной.
- **Language**: строки для пользователя и документация — на русском; код, идентификаторы и команды — на английском.
- **Compatibility**: старые JSON-записи открываются и переоцениваются без миграции.
- **Truth**: источник истины — JSON-записи и события. То, что не наблюдалось, остаётся `unknown`; слова агента не доказывают действие.
- **Data**: прод-диалоги банка хранятся только локально (`.agent-lab`, права `0600`) и никогда не попадают в репозиторий.
- **Workspace**: в этом worktree могут работать другие сессии. `npm test` и `npm run build` удаляют `dist/`, который импортирует живое расширение Pi, поэтому тесты и ревью гонять из снимка `git archive HEAD`; перед правками смотреть `git status` и `git log`.
- **Agent under test**: не трогать git `aigw-local` во время прогонов. Живой прогон стоит около $2 и 6–17 минут на 15 карточек. Судья по умолчанию — `openai/gpt-5.6-sol` через OpenRouter.
