# Контракт адаптера Agent Lab

Адаптер — тонкая прослойка между Agent Lab и агентом владельца. Lab отправляет реплику клиента, адаптер вызывает
агента и возвращает его ответ — и, если может, то, что агент при этом сделал. Lab верит только тому, что адаптер
показал: слова агента («я проверил», «я оформил») не доказывают действие. Что не показано, не измеряется.

Агент — внешняя система: Lab не меняет его файлы, код, базу и процессы. Каждый разговор Lab начинает заново;
состояние живёт внутри одного разговора и не переходит в следующий.

## Способы подключения

| Способ | Что это | Когда |
|---|---|---|
| `command` | процесс на каждый разговор, запросы и ответы — строки JSON через stdin/stdout | агент запускается командой: `python3 agent.py` |
| `module` | JavaScript-модуль с `createSession`, Lab запускает его в своём процессе Node на каждый разговор | агент — код на Node |
| `http` | POST на адрес агента с телом запроса Lab | агент — сервис, и в нём можно сделать ручку под этот контракт |
| `http` с шаблоном | запрос в собственном формате агента, по curl владельца | агент — сервис со своей ручкой, менять его нельзя |

Подключение лежит в `connection.json` в папке проекта: `{ "format": "agent-lab-connection-1", "target": { … } }`.
Пути в нём — от папки файла. Общие поля `target`:

| Поле | Что значит |
|---|---|
| `timeoutMs` | сколько ждать один ответ агента, 1 000–600 000 мс; у `command` и `http` по умолчанию 60 000 (60 с), у `module` — см. ниже |
| `exam` | экзамен подключения — раздел ниже; без него процента не будет |
| `promptFile` | файл промпта, который Lab передаёт агенту в каждом запросе (`prompt`, `promptHash`) |
| `serviceReplies` | до 20 фрагментов текста, по которым видно, что ответил стенд, а не агент («нет ответа от смежной системы»): такой разговор не измеряется |
| `release` | хук выпуска: команда, которую Lab выполняет перед каждым прогоном (`command`, `args`, `cwd`, `timeoutMs` — по умолчанию 120 с). Владелец видит её дословно в окне запуска |

Подключение из чата делает Lab: команду или файл модуля он находит в папке проекта или берёт со слов владельца
(`agent_lab_run` с `agent`), адрес — только по curl владельца (`agent_lab_connect`). Проверить подключение
заранее, без модели: `agent-lab doctor --connection connection.json --yes`.

## Запрос

Один и тот же у `command`, `module` и `http` в контракте Lab:

| Поле | Что значит |
|---|---|
| `type` | только у `command`: `"respond"` — реплика клиента, `"close"` — разговор окончен |
| `sessionId` | id разговора; новый разговор — новый `sessionId` |
| `scenarioId` | id ситуации |
| `initialState` | исходное состояние: `records` (записи с простыми полями), `writableFields` (поля, которые агент может менять), `transientFailures`, необязательный `external` (данные тестового окружения). Применяйте его перед первым ответом |
| `messages` | весь разговор до этого хода, `[{ "role": "user" \| "assistant", "content": "…" }]`; последний элемент — текущая реплика клиента |
| `message` | текущая реплика клиента; если клиент нажал кнопку — её текст |
| `choice` | только когда клиент нажал кнопку прошлого ответа: `{ "index", "text", "value"? }`, `value` — то значение, которое адаптер сам дал кнопке |
| `prompt`, `promptHash` | только когда в подключении есть `promptFile`: текст промпта и его хэш |

## Ответ

Самый простой ответ — строка: это текст, который увидел клиент. Полный ответ — объект. **Лишних полей нет**:
объект с полем, которого нет в таблице, Lab не принимает, и разговор не измеряется.

| Поле | Тип и предел | Что значит |
|---|---|---|
| `reply` | строка до 20 000 знаков, обязательно | текст, который увидел клиент |
| `outcome` | `reply` · `handoff` · `no_reply` | что получил клиент за этот ход; по умолчанию `reply` (раздел ниже) |
| `status` | строка до 200 | собственный статус хода у агента («202-7»): хранится в записи, судья его не видит |
| `buttons` | до 20 × `{ "text", "value"? }`, до 300 знаков каждое | кнопки, показанные клиенту вместе с ответом; нажатие приходит в следующем запросе как `choice` |
| `events` | до 50 × `{ "tool", "args"?, "result"? }` | вызовы инструментов за этот ход, по порядку |
| `eventsComplete` | `true` / `false` | в `events` все вызовы хода, ни один не пропущен |
| `eventScope` | до 50 имён или масок `prefix*` | за какие инструменты адаптер ручается |
| `retrievals` | до 20 × `{ "source", "content", "chunkId"?, "score"?, "documentId"?, "version"?, "section"? }`; `content` до 12 000 знаков, все вместе до 60 000 | фрагменты базы знаний, которые получила модель агента |
| `retrievalsComplete` | `true` / `false` | в `retrievals` весь найденный контекст ответа |
| `retrievalStage` | `retrieved` · `model_context` | фрагменты — ещё только найденное или уже то, что ушло в модель |
| `records` | до 30 записей × простые поля; id записей и полей — латиница, цифры, `_`, `-` | состояние после хода: заменяет состояние разговора перед проверками |
| `resetConfirmed` | `true` / `false` | адаптер действительно применил `initialState` к новой сессии; читается из первого ответа |
| `version` | строка до 200 | версия агента: сборка, коммит, хэш промпта. Одна и та же во всём разговоре и во всём прогоне |
| `promptHash` | 64 hex-знака | при `promptFile` — в каждом ответе: верните тот `promptHash`, что пришёл в запросе, после того как применили `prompt`. Нет или другой — разговор не измерен |
| `usage` | `{ "calls", "inputTokens", "outputTokens", "costUsd" }`, `costUsd` может быть `null` | расход модели агента за ход |
| `measurementError` | строка до 2 000 | ход не измерен: адаптер не смог получить нужные данные |
| `sessionId`, `turn` | строка; число с 1 | для сверки: `sessionId` — тот, что пришёл в запросе, `turn` — номер хода в разговоре. Не совпали — разговор не измерен |

Ответ — не больше 2 МБ. Пустой `reply` без `handoff` — пустой ответ агента: разговор не измеряется.

### Исход хода и честность числа

- `outcome: "reply"` — клиент получил ответ. Так по умолчанию.
- `outcome: "handoff"` — агент передал разговор человеку. Разговор на этом заканчивается и оценивается как есть:
  судья видит, что агент передал разговор.
- `outcome: "no_reply"` — клиент за этот ход **ничего не получил**: служебный статус, сбой генерации, внутренняя
  ошибка. Диагностику положите в `reply`, статус — в `status`: Lab сохранит их в записи, но клиенту Lab не передаст.
  Разговор на этом заканчивается и считается неизмеренным.

Решение `no_reply` принимает адаптер, а неизмеренный разговор выпадает из процента. Поэтому правило одно:
**`no_reply` — только когда клиент действительно ничего не увидел.** Отдать `no_reply` на ответ, который клиент
получил (плохой, неловкий, неверный), — значит спрятать ошибку агента и подогнать число, а не измерить его. Владелец
видит каждый такой разговор отдельно, в строке «Работоспособность» («клиент не получил ответа агента»), а если
неизмеренных набирается пятая часть ситуаций и больше, итог помечается «✗ Числу пока не верить».

Если разговор оборвался на стороне агента — ошибка, обрыв, таймаут, `measurementError`, — Lab повторяет его один раз
с начала, в новой сессии; повтор отмечается в итоге.

## `command`: процесс на разговор, JSON-строки

Lab запускает `command` с `args` в папке `cwd` один раз на разговор, с окружением Pi, и обменивается с процессом
строками JSON:

```
stdin  → {"type": "respond", "sessionId", "scenarioId", "initialState", "messages", "message", "choice"?, "prompt"?, "promptHash"?}
stdout ← ответ — ровно одна строка JSON на один запрос
stdin  → {"type": "close", "sessionId"}, после чего stdin закрывается
```

- **Ровно одна строка JSON на запрос.** Прогресс, логи и отладку пишите в stderr. Строка stdout, которая не JSON
  (забытый `print`, баннер библиотеки), — диагностика: Lab покажет её, если ответ не придёт. Но любая строка JSON,
  пока Lab ждёт ответа, будет принята за ответ — не пишите в stdout JSON-логи.
- После каждой строки сбрасывайте буфер (`flush=True`, `sys.stdout.flush()`).
- Не ответили за `timeoutMs` (по умолчанию 60 с) — Lab завершает процесс вместе с его группой процессов.
- Процесс завершился раньше — Lab показывает код выхода и хвост stderr.
- После `close` у процесса 2 секунды, чтобы выйти; потом Lab его завершает.
- Ответ одного хода — до 2 МБ вывода.

```python
#!/usr/bin/env python3
import json
import sys


def log(*values):
    """Диагностика — только в stderr: stdout занят протоколом."""
    print(*values, file=sys.stderr, flush=True)


terminal = None  # состояние одного разговора: на каждый разговор Lab запускает новый процесс
for line in sys.stdin:
    request = json.loads(line)
    if request["type"] == "close":
        break
    digits = "".join(ch for ch in request["message"] if ch.isdigit())
    if len(digits) >= 4:
        terminal = digits
    reply = f"Терминал {terminal}: ставка 1,5%." if terminal else "Назовите номер терминала."
    log("ход", len(request["messages"]))
    sys.stdout.write(json.dumps({"reply": reply}, ensure_ascii=False) + "\n")
    sys.stdout.flush()
```

```json
{ "format": "agent-lab-connection-1",
  "target": { "kind": "command", "command": "python3", "args": ["agent.py"], "cwd": ".", "timeoutMs": 30000,
    "exam": [
      { "name": "Помнит номер терминала", "steps": [
        { "say": "Мой терминал 12345678", "expect": "reply", "contains": "12345678" },
        { "say": "Какая ставка?", "expect": "reply", "contains": "12345678" } ] },
      { "name": "Новый разговор начинается с чистого листа", "steps": [
        { "say": "Какая ставка?", "expect": "reply", "contains": "Назовите номер" } ] } ] } }
```

Если у проекта своё окружение Python, укажите его в `command`: `".venv/bin/python"`.

## `module`: `createSession` в своём процессе

Lab запускает модуль (`path`, файл `.mjs` или `.js`) в отдельном процессе Node на каждый разговор и вызывает
экспортированную функцию `exportName` (по умолчанию `createSession`):

- `createSession({ sessionId, scenarioId, initialState, prompt, promptHash })` возвращает (можно через `await`)
  сессию с методом `respond(message, messages, choice)` и, если нужно, `close()`.
- `respond` возвращает тот же ответ, что и `command`: строку или объект; можно асинхронно.
- `console.*` модуля уходит в stderr; в `process.stdout` не пишите — он занят протоколом.
- **Задайте `timeoutMs`.** Без него ответ ждут столько же, сколько один вызов модели: 60 с на экзамене и в
  `agent-lab doctor`, а в прогоне — сколько задано на вызов модели (2 мин по умолчанию, 10 мин у ситуаций,
  подготовленных в чате по логам).

```js
export function createSession({ sessionId, initialState }) {
  let terminal = null; // состояние одного разговора
  return {
    async respond(message, messages, choice) {
      const digits = [...message].filter(char => char >= '0' && char <= '9').join('');
      if (digits.length >= 4) terminal = digits;
      return { reply: terminal ? `Терминал ${terminal}: ставка 1,5%.` : 'Назовите номер терминала.' };
    },
    async close() {},
  };
}
```

```json
{ "format": "agent-lab-connection-1",
  "target": { "kind": "module", "path": "agent.mjs", "timeoutMs": 30000, "exam": [ … как у command … ] } }
```

## `http` в контракте Lab: POST на каждую реплику

Lab шлёт `POST url` с телом запроса (все поля таблицы «Запрос», кроме `type`) и заголовками `content-type` и
`accept: application/json`. Ответ — тело JSON того же вида, что у `command`, до 2 МБ, за `timeoutMs` (по умолчанию
60 с). Код ответа не 2xx — разговор не измерен.

- Адрес — `http://` или `https://`, без логина и пароля в нём.
- Секреты — только из переменных окружения: `"headersEnv": { "Authorization": "AGENT_TOKEN" }` — Lab прочтёт
  `AGENT_TOKEN` в момент запроса; значение не попадает ни в файл, ни в записи, ни к модели.
- Разговор различайте по `sessionId`: новый `sessionId` — новый разговор с чистым состоянием.

```js
import { createServer } from 'node:http';

const conversations = new Map(); // sessionId → состояние разговора; новый разговор — новый sessionId

createServer(async (request, response) => {
  let body = '';
  for await (const chunk of request) body += chunk;
  const { sessionId, message } = JSON.parse(body);
  const state = conversations.get(sessionId) ?? { terminal: null };
  const digits = [...message].filter(char => char >= '0' && char <= '9').join('');
  if (digits.length >= 4) state.terminal = digits;
  conversations.set(sessionId, state);
  const reply = state.terminal ? `Терминал ${state.terminal}: ставка 1,5%.` : 'Назовите номер терминала.';
  response.writeHead(200, { 'content-type': 'application/json' });
  response.end(JSON.stringify({ reply }));
}).listen(8787, '127.0.0.1');
```

```json
{ "format": "agent-lab-connection-1",
  "target": { "kind": "http", "url": "http://127.0.0.1:8787/agent-lab", "timeoutMs": 30000, "exam": [ … как у command … ] } }
```

## `http` в собственном формате агента: по curl

Если у агента своя ручка и менять её нельзя, адаптер не нужен: владелец присылает в чат рабочую команду curl, а
модель передаёт её целиком в `agent_lab_connect`. Lab разбирает запрос, спрашивает владельца, какое поле — слова
клиента и какие поля — разговор (или, по его слову, предлагает модель), отправляет агенту два тестовых сообщения и
сохраняет `connection.json` с шаблоном запроса (`target.request`):

- `{{message}}` — слова клиента; `{{conversation}}` (`{{conversation:number}}`) — новый id разговора от Lab;
  `{{session}}` — id разговора, который назвал сам агент в прошлом ответе; `{{history}}` — вся история, если запрос
  несёт реплики с ролями; `{{uuid}}`, `{{now}}` — новый id и время в каждом запросе; `{{env:NAME}}` — значение
  переменной окружения в момент запроса.
- Секреты из curl — заголовки кроме безобидных (`Content-Type`, `Accept`…), поля и параметры адреса с именами вроде
  `password`, `pass`, `token`, `jwt`, `secret`, `api_key`, `pin` — в файл не пишутся: Lab заменяет их переменными
  окружения `AGENT_LAB_…` и говорит владельцу, какие задать.
- Текст ответа Lab читает по пути в JSON (`request.reply`); где он, владелец подтверждает на тестовом сообщении.
- Такой агент показывает Lab только текст: инструменты, состояние и сброс не видны, и его оценивают по ответам.

Кнопки и исход хода (`handoff`, `no_reply`) агент в собственном формате показывает, только если в шаблоне
подключения задано, где они в его ответе; без этого Lab видит один текст.

## Экзамен подключения

Прежде чем что-то измерять, Lab проверяет сам канал: помнит ли агент разговор, показывает ли и принимает ли кнопки,
отвечает ли клиенту, а не служебным статусом. Для этого в `target` подключения пишется `exam` — несколько коротких
многоходовых путей именно для этого агента, составленных по его коду.

```json
"exam": [
  { "name": "Помнит номер терминала",
    "steps": [{ "say": "Мой терминал 12345678", "expect": "reply" },
              { "say": "Какая ставка по нему?", "expect": "reply", "contains": "12345678" }] },
  { "name": "Ставка по одной из двух касс",
    "steps": [{ "say": "Какая у меня ставка?", "expect": "buttons" },
              { "press": "Касса №1", "expect": "reply", "contains": "12345678" }] },
  { "name": "Просит оператора", "steps": [{ "say": "Позовите оператора", "expect": "handoff" }] }
]
```

- Путь — `name` (до 200 знаков) и 1–8 шагов; путей 1–10. Каждый путь — новый разговор.
- Шаг — **либо** `say` (слова клиента, до 3 000 знаков), **либо** `press` (текст кнопки из прошлого ответа агента,
  до 300 знаков). Путь начинается со слов.
- `expect` — каким должен быть ход агента: `reply` — ответ клиенту (ответ с кнопками тоже подходит), `buttons` —
  ответ с кнопками, `handoff` — передача человеку.
- `contains` — слово или значение, которое должно быть в ответе (сравнение без учёта регистра и лишних пробелов,
  целыми словами). Так путь показывает память разговора: значение сказано раньше, и знать его агент может только
  из разговора.
- `initialState` — исходное состояние пути в форме карточки (`records`, `writableFields`); без него — пустое. Нужно
  только адаптеру, который принимает `initialState` Lab.

**Экзамен засчитывается, только если в нём есть хотя бы один путь из двух шагов и больше, где поздний шаг
проверяет `contains` то, что клиент сказал раньше.** Экзамен без такого пути процента не даёт.

Lab проходит экзамен перед каждым прогоном, сразу после хука выпуска, без моделей:

- не пройден — прогон не запускается, и Lab называет путь, шаг и причину;
- экзамена нет или он слишком слабый — прогон идёт, итог показывает, в скольких ситуациях агент справился, но
  процента нет; окно запуска говорит об этом заранее.

Экзамен не оценивает смысл ответов — это работа судьи. Он проверяет, что через подключение вообще можно честно
измерять.

Экзамен пишется в `target.exam` файла подключения вместе с адаптером: пути — по коду агента, так, чтобы они проверяли
именно его память, кнопки и отказы. Проверить экзамен без прогона и без модели:
`agent-lab doctor --connection connection.json --yes`.

## Что Lab видит

То, что адаптер не показал, Lab не засчитывает ни как успех, ни как провал: такая проверка не измеряется.

| Уровень | Адаптер отдаёт | Становится измеримым |
|---|---|---|
| 0 | `reply` | фразы в ответе, значения эталона, рубрики по тексту ответа |
| 1 | + `events`, `eventsComplete` (и `eventScope`) | вызовы инструментов |
| 2 | + `retrievals` со стабильным `source`, `retrievalsComplete` | найдена ли нужная статья, проверки по базе знаний |
| 3 | + `records`, `resetConfirmed` | итоговое состояние |

## Правила

1. **Флаг полноты — только когда полнота доказана кодом.** `eventsComplete`, `retrievalsComplete` и
   `resetConfirmed` ставятся, если адаптер читает полный журнал хода, а не «скорее всего всё». Сомневаетесь — не
   ставьте: Lab честно не измерит проверку, и это лучше ложного «справился».
2. **`source` — стабильный id статьи**, тот же, которым её называют эталоны. Не URL, не заголовок, не номер в выдаче.
3. **Всё найденное в базе знаний — в `retrievals`**, даже если агент получил это через инструмент; сам вызов
   поиска — ещё и в `events`. Все фрагменты хода, а не только последнего поиска; если их больше 20 или они не
   влезают в 60 000 знаков, отдайте самые важные и не ставьте `retrievalsComplete`.
4. **Новая изолированная сессия на каждый разговор.** Состояние прошлого разговора не должно протекать в следующий.
5. **Служебный ответ — не ответ клиенту**, а ответ клиенту — никогда не `no_reply` (раздел «Исход хода»).
6. **Кнопки — в `buttons`, не в тексте `reply`**: иначе нажатие кнопки не отличить от свободного текста.
7. **Никаких секретов и персональных данных** в `records`, `events`, `retrievals`: запись хранится в `.agent-lab` и
   попадает в отчёт.

## Типичные ошибки

| Ошибка | Последствие |
|---|---|
| `print` отладки или JSON-лог в stdout у `command` | строка JSON принимается за ответ; ответ сдвигается на ход |
| нет `flush` после ответа | Lab не дождётся ответа, разговор не измерен по таймауту |
| лишнее поле в объекте ответа | ответ не по контракту, разговор не измерен |
| `sessionId` или `turn` не те, что в запросе | разговор не измерен |
| `module` без `timeoutMs` | зависший агент держит прогон до 10 минут на ход |
| `eventsComplete: true` без журнала вызовов | пропущенный вызов превращается в ложный провал или ложный успех |
| `source` — заголовок статьи | эталон со стабильным id никогда не совпадёт |
| `resetConfirmed: true` без применения `initialState` | проверки состояния сравнивают с чужим состоянием |
| `no_reply` на ответ, который клиент получил | ошибка агента пропадает из процента — число подогнано |
| служебный статус отдаётся как обычный `reply` | клиент Lab принимает диагностику за ответ агента, судья оценивает её как ответ |
