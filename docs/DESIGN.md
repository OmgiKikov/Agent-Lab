# Agent Lab — дизайн

Договор о том, как выглядит и как говорит Agent Lab — весь фронтенд, включая трейсы Workshop: это один продукт.
Его читают все, кто меняет интерфейс: люди и агенты.
Код дизайн-системы: `workshop/app/src/lab/ui.tsx` (компоненты), `workshop/app/src/index.css` и
`workshop/app/tailwind.config.js` (токены), `components/NavSidebar.tsx` (меню Raindrop), `lab/Shell.tsx` (детали Raindrop для
разделов Lab), `lab/Conversation.tsx` (диалог),
`lab/criteria.ts` (строки вердиктов судьи, сгруппированные по критерию). Логика и числа — в сервисе (`lab/*.py`),
фронт их только показывает: см. «Откуда каждое число» (раздел 7).

## 1. Продукт человеческими словами

Agent Lab показывает, **сколько диалогов версия ИИ-агента проходит без нарушений, какие критерии она нарушает и можно ли верить судье.**
Критерии берутся из промптов, инструментов и базы знаний самого агента, у каждого есть цитата-первоисточник.
Судья читает диалоги (реальные из логов и сыгранные симулятором клиента) и подтверждает каждое нарушение цитатой агента.

Кто смотрит:

- **Стейкхолдер** открывает раз в неделю: за 10 секунд — доля диалогов без нарушений рядом с прошлой версией, что нарушается,
  можно ли верить судье. Ему — верх страницы «Версия».
- **Разработчик агента** — каждый день: от числа к критерию, от критерия к диалогу с цитатой, правит агента, проверяет снова.
  Ему — списки, клавиатура и скорость.

## 2. Парадигма: Raindrop как он есть, Agent Lab внутри

Agent Lab — это Raindrop Workshop как он есть, с разделами Agent Lab внутри. Raindrop не перекрашивается и не перестраивается:
его меню, трейсы, поиск, сохранённые, настройки и плашка «Спросить Claude Code» — как в upstream. От продукта в Raindrop только
русский текст и шрифты с кириллицей. Разделы Lab собраны из тех же деталей Raindrop (`lab/Shell.tsx`). Семь правил:

1. **Числа сервиса, потом доказательство.** Экран открывается числами, которые посчитал сервис (`lab/*.py`), ниже — то,
   из чего они сложены; каждое число ведёт к диалогам за ним. Интерфейс не придумывает выводов, которых нет в сервисе:
   `lab/metric.py` не сравнивает версии, поэтому экран не пишет «лучше» или «хуже» — числа двух версий стоят рядом.
2. **Тихо, когда хорошо. Громко — только проблема.** Выполненное серое и свёрнуто, нарушенное красное и наверху.
   Пустой список нарушений — это хороший результат, а не пустой экран.
3. **Одна раскладка — раскладка Raindrop: меню → список → деталь.** Проверки версий устроены как трейсы: список слева,
   проверка справа с шапкой трейса (заголовок, кнопки, метки) и вкладками. Подготовка устроена как настройки Raindrop.
4. **Инструмент, а не дашборд.** Чёрный холст, волосяные линии, моноширинные метки капсом над значениями, табличные цифры.
   Нет карточек в карточках, градиентов, стекла и теней (кроме всплывающего). **Одно крупное число на экран** (`Hero`) —
   то, что сервис ставит первым; остальные числа — мелкими фактами рядом (`Facts`), никогда не рядом равных по размеру.
5. **Цвет — это смысл.** Красный — нарушение, зелёный — без нарушений, янтарный — не уверены
   (нет данных, судьи расходятся), синий — фокус, выбор, то, что идёт сейчас. Жёлтый маркер — цитата судьи
   в словах агента. Статус никогда не передаётся только цветом: всегда ещё знак (✓ ✕ ?) и слово. Число прошлой версии — серое.
6. **Кнопки — как в шапке трейса Raindrop:** мелкие, с обводкой, значок и слово. У проверки — «Переоценить» и «Проверить
   версию»; своё действие вкладки или шага — такой же кнопкой над содержимым. Светлая — только плашка «Спросить Claude Code».
7. **Интерфейс не объясняет сам себя.** Никаких «Здесь показаны…» и абзацев под каждым заголовком.
   Метка, число, одна фраза вывода; подсказка — в `title`/`Tip`, одно предложение.

Ориентиры те же, что у Raindrop: «Four hundred traces. One thing to fix.» — много данных, один ответ, что чинить.

## 3. Объекты и словарь

```
Агент ──▶ Версия (проверка версии = прогон симулятора) ──▶ Диалог (сценарий × тип клиента × повтор) ──▶ Вердикт по критерию (цитата агента)
                                                                                                          ▲
Источник (промпт / инструменты / база знаний) ──▶ Критерий (цитата-первоисточник) ─────────────────────────┘
Логи: реальные диалоги агента в проде, без версии. Доверие: судья ↔ человек, судья ↔ второй судья, повторы, n.
```

Одно слово на понятие. В интерфейсе:

| Говорим | Не говорим |
|---|---|
| версия, проверка версии | прогон, run, эксперимент |
| критерий | правило, контракт, rule |
| диалог | разговор (допустимо в тексте), трейс, conversation |
| сценарий | карточка, набор проверок, card |
| тип клиента | персона, persona |
| реальные диалоги, логи | выгрузка (только на шаге «Логи»), prod |
| судья, второй судья | LLM-judge, модель-оценщик |
| сверить судью (с человеком) | разметка, annotation, review |
| без нарушений / нарушено | pass rate, accuracy, точность |
| судьи расходятся, спорный | disagreement, κ |
| передал оператору | статус 202, handoff |

Внутреннее — во вторичном: модель (`z-ai/glm-5.3`), id, пути, JSON, трейсы. Моноширинным, мелко, в конце.

## 4. Навигация

**Меню Raindrop** слева (`components/NavSidebar.tsx`, shadcn `Sidebar`, как upstream): логотип, пункты-иконки, настройки внизу.
Agent Lab добавляет в него два пункта, перед пунктами Raindrop:

```
◆  raindrop                          → raindrop.ai, как upstream
⚗  agent lab    /lab/overview        — проверки версий: список слева, проверка справа (Обзор · Диалоги · Карта · Судья)
☰  подготовка   /lab/agent|logs|checks — шаги сервиса раскладкой «Настроек»: 1. Агент · 2. Логи · 3. Сценарии
〰  трейсы       /runs                — Raindrop
⌕  поиск        /search              — Raindrop
⌑  сохранённые  /saved               — Raindrop
⚙  настройки    /settings            — Raindrop, внизу
>_ «Спросить Claude Code»            — плашка справа внизу, как в Raindrop
```

**agent lab** (`pages/LabPage.tsx` → `ChecksSection`): колонка списка 248 px, как у трейсов — «● на связи · проверить версию»,
поиск, проверки («Версия 2.14 · что изменили», под ней «76% без нарушений · 22 ч назад», точка пульсирует у идущей).
Справа — шапка трейса Raindrop: «Версия 2.14», кнопки «Переоценить» и «Проверить версию», строка меток (АГЕНТ, ЧТО ИЗМЕНИЛИ,
ДИАЛОГОВ, ДАТА), вкладки «Обзор · Диалоги · Карта · Судья». Критерий открывается внутри «Обзора» («← Обзор»), диалог — внутри
«Диалогов», сверка — внутри «Судьи». Выбор в списке меняет проверку и оставляет открытую вкладку.

**подготовка** (`SetupSection`): слева заголовок «подготовка» и три шага с галочкой у выполненных, справа шаг.

Страница Lab внутри раздела не рисует своей шапки (`EmbedContext`): только «← назад» и свои кнопки над содержимым.
Критериев и точек-сигналов в меню нет.

## 5. Экраны (что отвечает каждый)

**Обзор** `/lab/overview` — одна проверка версии (запись прогона `/api/runs/{id}`; «что изменили», дата, агент, статус — в шапке
проверки) → **одно крупное число** — `metric.accuracy`
(«the one quality number» в `metric.py`), под ним `passed` из `measured` и `unmeasured`, строкой ниже — то же число прошлой проверки;
справа мелко — насколько ему верить: второй судья (`secondJudge`), сверка с человеком (`human`), повторы (`repeats`) →
**критерии**: «Нарушается» (по числу диалогов этой
проверки, где судья вынес FAIL) и «Выполняется» (свёрнуто) → сводка оценки логов одной строкой. Ни вердикта версии, ни групп
«сломалось / исправлено»: сервис версии не сравнивает. Пока проверок нет — шаги сервиса по порядку и «Проверить версию».
Строка критерия: что агент обязан делать, откуда (промпт / инструменты / база знаний и цитата), «нарушен в k из n» и под ним
тот же счёт прошлой проверки.

**Критерий** `/lab/criteria/:key` — как issue в Raindrop: **слева утверждение**, справа доказательство. Слева: нарушается / выполняется,
заголовок, откуда он (цитата и путь к файлу источника), счёт вердиктов судьи (симулятор, реальные, прошлая проверка),
нарушения по проверкам, по типам клиентов. Справа: «Нарушено · Выполнено», диалог с цитатой судьи жёлтым маркером прямо в словах
агента и причиной под ней, «Судья прав? 1 Верно · 2 Неверно», ←/→ — соседний диалог. Главное действие — «Перепроверить N сценариев».

**Диалоги** `/lab/dialogs[/:key]` — диалоги этой проверки: слева список (поиск, фильтры Нарушения · Спорные · Нет данных ·
Без нарушений; «спорный» — второй судья вынес другой вердикт), справа диалог: заголовок, факты (`Meta`), тот же сценарий
с другими клиентами, вердикт, реплики, все критерии судьи, внизу «Вердикт верный?» (`/api/review`). Реальные диалоги —
не часть проверки: они на шаге «Логи» и в трейсах Raindrop (папка «Agent Lab · Логи» в сохранённых).

**Карта** `/lab/dialogs?view=map` — сценарий × тип клиента; над столбцом — `metric.personas` сервиса.

**Судья** `/lab/judge` — то, что `metric.py` называет доверием, числами без уровней и порогов. Крупное число — судья прав по сверке
с человеком (`human.agree` из `human.reviewed`); мелко рядом — второй судья (`secondJudge`), повторы (`repeats`), сколько ещё не сверено;
списки диалогов «Судьи расходятся» и «Человек не согласен с судьёй»; модели одной строкой внизу.
Главное действие — «Сверить судью».

**Сверка** `/lab/judge/check` — внутри вкладки «Судья»: прогресс сверху, один диалог, внизу «Вердикт верный? 1 Верно · 2 Неверно ·
→ Пропустить».

**Подготовка** — шаги сервиса слева, как вкладки настроек Raindrop, в том порядке, в каком его задачи нужны друг другу: **Агент** (подключение, источники
из кода — `/api/sources`, агенты, модели; критерии у источников появляются после оценки логов), **Логи** (загрузка, оценка —
`/api/discover`: сводка, нарушения из `summary.patterns`, темы), **Сценарии** (`/api/cards`, список, а не плитки).
Каждый шаг: вывод, форма или загрузка, «Дальше: … →».

## 6. Визуальная система

Токены — только через Tailwind-классы `lab-*` и именованные размеры. **Без inline hex, без `text-[Npx]`, моноширинный — только метки
(`Label`, класс `lab-label`), id, пути, модели, JSON.** Константы `C` в `utils/colors.ts` — те же значения для inline-стилей Workshop.

Палитра — Raindrop. Поверхности (светлее = выше): `bg-lab-canvas` #000 холст · `bg-lab-panel` #0a0a0a колонки списков, списки, полосы ·
`bg-lab-card` #111 · `bg-lab-raised` #18191a наведение, поповеры · `bg-lab-active` #212325 выбранное. Тонкие заливки поверх холста —
`bg-white/[0.04]` поле, `/[0.06]` наведение, `/[0.08]` выбранное. Линии: `border-lab-line` 6% белого, `border-lab-edge` 10%, `border-lab-strong` 16%.

Текст — холодная сталь Raindrop, пять ступеней: `text-lab-ink` #f2f5f7 заголовки и числа · `text-lab-text` #c8d5dc основной ·
`text-lab-soft` #a0acb2 вторичный · `text-lab-mute` #7d8a90 метки и мета · `text-lab-faint` #5a6a72 только плейсхолдеры, оси, неактивное.

Смысл: `lab-bad` #f04444 · `lab-ok` #60e36d · `lab-warn` #f0ad4e · `lab-accent` #5b8def · `lab-mark` #f2ff66 (маркер цитаты, класс `lab-marker`) ·
`lab-user` #0d3442 (пузырь клиента). Тинты: `bg-lab-bad/10` и т.п.

**Шрифты.** У Raindrop — Barlow и Space Mono, но в них нет кириллицы. Поэтому: **Commissioner** — гротеск, ближайший к Barlow
по характеру (компактный, «инструментальный»), с кириллицей; **Geist Mono** — то, чем сам Raindrop набирает метки и id.
AlphaLyrae (дисплейный Raindrop, класс `font-display`) — только латиница бренда; русский текст в нём падает на Commissioner.

| Класс | Размер | Для чего |
|---|---|---|
| `lab-label` / `Label` | 10/14, моно, капс, +6% | метки над значением, колонкой, группой; 1–3 слова |
| `text-caption` | 12/16 | мета, вторая строка строки списка |
| `text-body` | 13/20 | интерфейс, кнопки, списки |
| `text-reading` | 14/22 | реплики, цитаты, заголовки строк |
| `text-lead` | 16/24 | фраза под выводом, заголовок диалога |
| `text-title` | 20/26 | заголовок критерия |
| `text-display` | 30/36 | вывод страницы |
| `text-metric` | 30/34 | главное число критерия |
| `text-hero` | 56/56 | одно главное число страницы (`Hero`) |

Веса 400 и 500 (`font-medium`), 600 — только названия страниц в шапке. Числа — `tabular-nums`. Сетка 4 px.
Радиусы: 4 px метки и чипы вердикта · 6 px кнопки и поля · 8 px (`rounded-lg`) списки, полосы, поповеры. Тени — только `shadow-pop`.
Фокус — `lab-focus` / `lab-focus-inset`. Движение: 100 мс наведение, 180–240 мс панели; `prefers-reduced-motion` отключает всё.

Точечная сетка Raindrop (`lab-dots`) и пиксельный знак (`LabMark`) — только в брендовых местах: первый запуск, пустые состояния,
загрузка файла, «сервис не отвечает». Никогда за данными.

**Компоненты** (`ui.tsx`): `Page` (шапка; `fill` — список+деталь на всю высоту; `primary` — своя главная кнопка) · `Section`
(метка + счётчик + точка состояния) · `Label` · `Numbers` = `Hero` + `Facts` (одно число и факты рядом) · `Verdict` (чип вердикта капсом) · `Panel`/`Row` ·
`Button` (primary светлая, secondary обводка, ghost, danger; `kbd`) · `IconButton` · `LinkButton` · `Kbd` · `Input`/`TextArea`/`Field` ·
`Segmented` · `Tabs` · `Chip` · `Meta` (метка-чип + значение, как в шапке трейса) · `Badge` · `StatusMark`/`StatusIcon`/`Dot` ·
`TrendBars` (столбики по версиям) · `Delta` · `IntervalBar` · `Meter` · `StackBar` · `Progress` · `Skeleton` · `Quote` · `Bubble` ·
`EmptyState` · `Tip` · `LabMark` · `PersonaIcon`/`PersonaTag`/`PersonaCard`. Диалог — `Conversation`, `AgentMessage`, `CustomerMessage`,
`VerdictLine`, `RulesList` (`lab/Conversation.tsx`). Нужен новый — сначала проверить, нельзя ли собрать из этих.

**Анти-паттерны** (не делать):
- карточки вокруг каждого числа и абзаца; рамка внутри рамки с той же обводкой;
- дашборд по умолчанию: сетка плиток и графиков вместо ответа на вопрос;
- всё одинаково громкое: несколько светлых кнопок, крупные заголовки у каждого блока;
- мелкий серый текст, чтобы втиснуть лишнее, — лучше убрать лишнее;
- объяснение экрана вместо вывода; повтор одного и того же числа в двух местах одного экрана;
- цвет «для красоты»: акцент на обычном тексте;
- вывод, которого не считает сервис: «лучше / хуже», «в пределах шума», погрешности, тесты и пороги, придуманные во фронте.

## 7. Числа и честность

- Источник чисел — сервис: `lab/metric.py` для проверки версии (без нарушений = пройденные / измеренные, второй судья, повторы,
  типы клиентов, сверка с человеком), сводка аудита для логов. Фронт группирует и считает штуки, но не добавляет статистику,
  которой нет в сервисе (интервалы, тесты, пороги значимости). Новое число — сначала в `lab/*.py`, потом на экран.
- Доля: целые проценты, «76%». Рядом с долей — n: «37 из 49 диалогов».
- Две версии — два числа рядом («Без нарушений 76%», «В 2.13 58%»), без стрелок, окраски и слов «лучше / хуже».
- Никаких своих уровней, порогов и целей («условно надёжна», «нужно 10 сверок», «80% — хорошо»): их нет в сервисе.
- **Откуда каждое число:** проверка версии — `run.metric` (`lab/metric.py`); логи — `discover.summary` (`lab/discover.py`,
  вместе с `patterns`); источники и их критерии — `state.sources`; сценарии — `state.cards`; вердикты по критериям — строки
  `rules` судьи (`lab/judge.py`), фронт лишь считает их по тексту критерия; «спорный» — `second.status ≠ status`, как в
  `metric.py`; отметка на карте «обычный проходит, этот тип нет» — прочтение, которое даёт `lab/personas.py`.
- Нет данных — «—», не «0». Счётчики со склонениями (`format.plural`, `format.count`). Даты: «29 сентября, 10:35» (`format.whenLong`)
  в выводах, «29.09, 10:35» (`format.when`) моноширинным в списках.

## 8. Текст

- Порядок: вывод → детали → диагностика. Вывод — законченная фраза с точкой, только из фактов сервиса: «Версия агента ещё не
  проверялась.»
- Метки — одно-три слова без точки: «Без нарушений», «С нарушениями», «Что изменили».
- Пустое состояние: что отсутствует, зачем, одна кнопка. Ошибка: что случилось и что делать, без обвинений.
- Кнопки: глагол + объект («Проверить версию», «Сверить судью», «Загрузить логи»). Без «ОК», «Готово», «Продолжить».
- Нельзя: описывать экран, пересказывать README, объяснять внутреннее устройство на рабочем экране, английские слова, где есть русские.

## 9. Состояния

Для каждого экрана: загрузка (скелет той же формы) · пусто (следующий шаг) · мало данных · ошибка · идёт работа
(точка у проверки в списке + строка с ходом работы и «Остановить») · длинный текст (перенос, `line-clamp`, полный текст в `title`) ·
узкий экран — вторично: меню Raindrop открывается кнопкой сверху, список и деталь идут по очереди.

## 10. Клавиатура

⌘K — поиск и команды везде · J/K (или ↓/↑) — соседний диалог в списке · ←/→ — соседний диалог критерия · 1/2 — «Верно»/«Неверно»
(сверка, критерий) · `/` — поиск в списке диалогов · Esc — закрыть. Подсказки клавиш — рядом с действием (`Kbd`), а не в справке.
