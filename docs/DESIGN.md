# Agent Lab — дизайн

Договор о том, как выглядит и как говорит Agent Lab — весь фронтенд, включая просмотр трейсов Workshop: это один продукт.
Его читают все, кто меняет интерфейс: люди и агенты.
Код дизайн-системы: `workshop/app/src/lab/ui.tsx` (компоненты), `workshop/app/src/index.css` и
`workshop/app/tailwind.config.js` (токены), `lab/story.ts` (тексты-выводы), `lab/stats.ts` (честность чисел).

## 1. Продукт человеческими словами

Agent Lab отвечает на вопрос: **стала ли новая версия ИИ-агента лучше, что именно он нарушает и можно ли этому верить.**
Критерии берутся из промптов, инструментов и базы знаний самого агента, у каждого есть цитата-первоисточник.
Судья читает диалоги (реальные из логов и сыгранные симулятором клиента) и подтверждает каждое нарушение цитатой агента.

Кто смотрит:

- **Стейкхолдер** (владелец продукта, руководитель): открывает раз в неделю, за 10 секунд должен понять «лучше / хуже / что сломано / можно ли верить».
  По умолчанию интерфейс сделан для него.
- **Разработчик агента**: каждый день, идёт от числа к критерию, от критерия к диалогу с цитатой, правит агента, проверяет снова.
  Для него — глубина, клавиатура и скорость.

## 2. Парадигма: ответ → доказательство → доверие

1. **Сначала ответ.** Каждый экран открывается выводом: одна фраза и одно число. Интерфейс рассказывает данные, а не себя.
   Не «Здесь показаны критерии…», а «Версия 2.14, похоже, лучше 2.13».
2. **Любое утверждение — в одном клике от доказательства.** Число → критерий → диалог с выделенной цитатой → строка промпта, откуда критерий.
3. **Доверие — свойство числа, а не отдельная страница.** Рядом с числом всегда: сколько диалогов (n), интервал, согласие судей,
   сверка с человеком. Изменение в пределах шума не красится в зелёный или красный.
4. **Цвет — это смысл.** Интерфейс монохромный. Красный — нарушение и ухудшение, зелёный — исправлено и улучшение,
   янтарный — не уверены (нет данных, судьи расходятся, мало проверок). Акцентный индиго — только фокус, выбор, ссылки и текущая версия
   на графике. Статус никогда не передаётся только цветом: всегда ещё знак (✓ ✕ ?) и слово.
5. **Одно главное действие.** Главный цикл продукта — «поправил агента → проверил версию → сравнил». У него одна кнопка
   «Проверить версию», она светлая и всегда в правом углу шапки. На экране не больше одной primary-кнопки в регионе.
6. **Решения вместо настроек.** Вердикт версии считается по симулятору (он зависит от версии), сравнение — всегда с предыдущей версией,
   логи — отдельная строка «реальные диалоги». Не выносить эти выборы в переключатели на главном пути.
7. **Спокойствие по умолчанию.** Хром приглушён, контент ведёт. Нет рамок вокруг всего подряд, нет моноширинных кнопок,
   нет капса, нет градиентов и стекла. Один громкий элемент на регион.
8. **Скорость — функция.** ⌘K, J/K, 1/2, стрелки. Переходы мгновенные; анимируется только смена числа и появление панелей.
9. **Прогрессивное раскрытие.** Четыре уровня: вывод → критерии → диалоги → цитата и первоисточник. Технические детали
   (модели, id, JSON, трейсы) — в самом конце и приглушённо.
10. **Детали — это продукт.** Табличные цифры, настоящий минус «−», «п.п.», склонения, «ёлочки», неразрывный пробел перед единицами.

## 3. Объекты и словарь

```
Агент ──▶ Версия (проверка версии = прогон симулятора) ──▶ Диалог (сценарий × тип клиента × повтор) ──▶ Вердикт по критерию (цитата агента)
                                                                                                          ▲
Источник (промпт / инструменты / база знаний) ──▶ Критерий (цитата-первоисточник) ─────────────────────────┘
Логи: реальные диалоги агента в проде, без версии. Доверие: судья ↔ человек, судья ↔ второй судья, повторы, n.
```

Одно слово на понятие. В интерфейсе:

| Говорим | Не говорим |
|---|---|
| критерий | правило, контракт, rule |
| диалог | разговор (допустимо в тексте), трейс, conversation |
| версия, проверка версии | прогон, run, эксперимент |
| сценарий | карточка, набор проверок, card |
| тип клиента | персона, persona |
| реальные диалоги, логи | выгрузка (только на шаге «Логи»), prod |
| судья, второй судья | LLM-judge, модель-оценщик |
| сверить судью (с человеком) | разметка, annotation, review |
| без нарушений / нарушено | pass rate, accuracy, точность |
| судьи расходятся | disagreement, κ |
| передал оператору | статус 202, handoff |

Внутреннее — во вторичном: модель (`z-ai/glm-5.3`), id, хэши, пути к файлам, JSON, трейсы Workshop. Моноширинным, мелко, в конце.

## 4. Навигация

Одна колонка слева (232 px) на всех страницах, шапка страницы 56 px, контент до 1080 px (1200 для таблиц, 800 для чтения диалога).

```
Agent Lab                          ● сервис на связи
Проверяем: Агент эквайринга · СберБизнес · чат поддержки
[Поиск и команды ⌘K]
  Сводка            /lab/overview   — вердикт версии (главный экран)
  Критерии     8    /lab/criteria   — что агент обязан делать и как справляется
  Диалоги           /lab/dialogs    — доказательства: список, карта, диалог
  Доверие      •    /lab/judge      — насколько верить; сверка судьи /lab/judge/check
Подготовка   3 из 3
  ① Агент           /lab/agent      — подключение, модели, источники критериев
  ② Логи            /lab/logs       — выгрузка реальных диалогов и их оценка
  ③ Сценарии        /lab/checks     — сценарии для симулятора
Трейсы (Workshop)
  Все трейсы        /runs           — трейсы разговоров: обзор, спаны, диалог
  Поиск             /search         — поиск по трейсам в Raindrop
  Сохранённые       /saved
[карточка идущей работы: что делает, n/N, «Остановить»]
Спросить ассистента · Настройки /settings · ● Lab ● Workshop · модель
```

Колонка одна на всё приложение (`lab/Sidebar.tsx`, в `router.tsx`), ⌘K и «Проверить версию» работают на любой странице
(`lab/LabContext.tsx`). Ассистент открывается из колонки, ничего не плавает поверх контента. На узком экране колонка уходит в меню.

Шапка любой страницы результатов: заголовок слева; справа — действия страницы, **переключатель версии** («Версия 2.14 против 2.13»)
и **«Проверить версию»**. Страницы подготовки (`Page bare`) показывают свои действия и шаг «Дальше →».
Детальные страницы: хлебная крошка «Критерии / …» вместо кнопки «Назад».

## 5. Экраны (что отвечает каждый)

**Сводка** — «Стала ли версия лучше?». Сверху вниз: строка контекста (агент · дата · что изменили) → заголовок-вердикт
(`story.verdictOf`) → одно предложение деталей → число (72 px) с интервалом и изменением → график по версиям с полосой интервала →
полоса доверия (уровень словами + факты) → «Что важно в этой версии» (наблюдения `story.observationsOf`, у каждого — куда смотреть) →
«Что нарушается» (топ-6 критериев) → «По типам клиентов» → «Реальные диалоги». Первый запуск — «три шага до первой оценки».

**Критерии** — «Что агент обязан делать и где проваливается?». Таблица, а не карточки. Строка: критерий (заголовок) + цитата-источник
одной строкой, метка источника (промпт / инструменты / база знаний), «нарушено k из n» с полоской, изменение к прошлой версии (новое /
исправлено / осталось), спарклайн по версиям, отдельно логи. Сверху — вывод одной фразой и фильтры: Нарушаются · Новые · Исправлено ·
Выполняются · Все. Выполняющиеся критерии свёрнуты.

**Критерий** — «Где и почему он нарушается?». Заголовок = критерий. Сразу под ним — **откуда он** (цитата промпта с меткой источника):
это главная особенность продукта. Потом: «нарушено k из n в симуляторе · k из n в логах · новое в 2.14». Потом разделённый вид:
слева список диалогов (Нарушено / Выполнено), справа диалог с выделенной цитатой агента и причиной судьи, кнопки «Судья прав / ошибся»,
навигация ←/→ (и клавиши). Ниже: по типам клиентов, по версиям, «После правки: перепроверить эти N сценариев».

**Диалоги** — «Покажи доказательства». Два вида: **Список** (фильтры: С нарушениями · Без нарушений · Нет данных · Судьи расходятся;
источник: Симулятор · Реальные; поиск) и **Карта** (сценарий × тип клиента, тихий «✓», громкий «✕», сравнение с прошлой версией).
Диалог симулятора — разделённый вид: слева сценарии версии с их типами клиентов, справа диалог: вердикт сверху, реплики,
вызванные инструменты, «передал оператору», цитата нарушения прямо в ответе агента, затем все критерии судьи. J/K — сценарии, ←/→ — типы.

**Доверие** — «Можно ли верить числу?». Заголовок-вывод: «Оценка предварительная / условно надёжна / можно верить» и почему.
Три меры в виде полос с целью: судья сверен с человеком (прав в X% на N, цель 30), второй судья согласен, устойчивость на повторах.
«Где судья ошибается» по критериям. Главная кнопка — «Сверить судью · осталось N». Ниже, приглушённо: похож ли симулятор на клиентов,
кто оценивал (модели).

**Сверка судьи** (`/lab/judge/check`) — режим фокуса: прогресс сверху, один диалог в центре, внизу панель «Вердикт верный? 1 Верно · 2 Неверно ·
→ Пропустить». Спорные (судьи расходятся) идут первыми.

**Подготовка** — пошаговый поток. Каждый экран: номер шага и что он даёт, форма или загрузка, результат шага одной фразой, «Дальше: … →».

## 6. Визуальная система

Токены — только через Tailwind-классы `lab-*` и именованные размеры. **Без inline hex, без `text-[Npx]`, без `font-mono` вне кода и id.**

Поверхности (светлее = выше): `bg-lab-canvas` #0a0b0d фон · `bg-lab-panel` #0f1012 боковая колонка, карточки ·
`bg-lab-card` #141519 выделенная карточка · `bg-lab-raised` #1a1c21 наведение, поля, поповеры · `bg-lab-active` #22242a выбрано.
Линии: `border-lab-line` 6% белого (разделители), `border-lab-edge` 10% (поля, кнопки), `border-lab-strong` 16% (наведение, выбранное).

Текст, четыре ступени: `text-lab-ink` #f2f3f5 заголовки и числа · `text-lab-text` #c5c9d0 основной ·
`text-lab-mute` #8d929c подписи · `text-lab-faint` #5f646d только плейсхолдеры и неактивное.

Смысл: `lab-bad` #ec5b62 · `lab-ok` #5dd39e · `lab-warn` #e6ac45 · `lab-accent` #7b8bff (фокус, выбор, ссылки) ·
`lab-accent-solid` #5864f0. Тинты статусов: `bg-lab-bad/10` и т.п. (шаги прозрачности кратны 5). Пузырь клиента: `bg-lab-user`.

Типографика: Inter Variable (кириллица, оптический размер), Geist Mono Variable — только id, пути, JSON, модели.

| Класс | Размер | Для чего |
|---|---|---|
| `text-micro` | 11/14 | только подписи осей графиков |
| `text-caption` | 12/16 | подписи, мета, метки |
| `text-body` | 13/20 | основной текст интерфейса, кнопки, таблицы |
| `text-reading` | 14/22 | реплики диалогов, цитаты, длинный текст |
| `text-lead` | 16/24 | заголовки секций, вводная фраза |
| `text-title` | 20/28 | заголовки страниц-состояний, числа второго плана |
| `text-display` | 28/34 | заголовок-вывод, крупные числа |
| `text-metric` | 40/44 | число блока |
| `text-hero` | 72/72 | одно главное число экрана |

Веса: 400, 500 (`font-medium`), 600 (`font-semibold`). Числа — всегда `tabular-nums`. Заголовки — `text-balance`, абзацы — `text-pretty`.
Сетка 4 px. Радиусы: 6 px (`rounded-md`) кнопки, поля, метки · 8 px (`rounded-lg`) мелкие карточки · 12 px (`rounded-xl`) панели.
Тени только у всплывающего (`shadow-pop`). Фокус — класс `lab-focus` (кольцо акцента с зазором) или `lab-focus-inset` в списках.
Движение: наведение 100 мс, панели 180–240 мс, `ease-out`. Не анимировать навигацию с клавиатуры. `prefers-reduced-motion` уважаем.

Компоненты (`ui.tsx`): `Page` (шапка + колонка) · `Section` · `Panel`/`Card` · `Row` · `Button` (primary светлая, secondary, ghost, danger;
`kbd`) · `IconButton` (обязательный `label`) · `LinkButton` · `Kbd` · `Input`/`TextArea`/`Field` · `Segmented` · `Tabs` · `Chip` (фильтр) ·
`Badge`/`Tag` (только для чтения, не похожи на кнопки) · `StatusMark`/`StatusIcon`/`StatusBadge`/`Dot` · `Delta` (цвет только при
реальном изменении) · `IntervalBar` · `Meter` · `StackBar` · `Progress` · `Stat` · `Quote` · `Bubble` · `EmptyState` · `Skeleton` · `Tip` ·
`PersonaIcon`/`PersonaTag`/`PersonaCard` · `LabMark`. Нужен новый — сначала проверить, нельзя ли собрать из этих.

## 7. Числа и честность

- Доля: целые проценты, «70%». Изменение: «+15 п.п.», «−4 п.п.» (`format.points`), настоящий минус.
- Рядом с долей — n: «19 из 27 диалогов». Для главного числа — 95%-й интервал Вильсона (`stats.wilson`): «скорее всего от 52 до 84%».
- Сравнение версий — `stats.compareOutcomes`: парный тест по одинаковым диалогам (сценарий × тип × повтор).
  `better`/`worse` — изменение реальное, красится; `likely-*` — сдвиг ≥ 5 п.п., но может быть случайным, серый, и текст говорит об этом;
  `same` — «на уровне».
- Нет данных — «—», не «0». Счётчики со склонениями (`format.plural`, `format.count`). Даты: «28 сентября, 09:05» (`format.whenLong`)
  в заголовках, «28.09, 09:05» (`format.when`) в таблицах.

## 8. Текст

- Порядок: вывод → детали → диагностика. Заголовок экрана — существительное («Критерии»), первая строка контента — вывод со числом.
- Пустое состояние: что отсутствует, зачем оно, одна кнопка. Ошибка: что случилось, что делать; без слов-обвинений.
- Кнопки: глагол + объект («Проверить версию», «Сверить судью», «Загрузить логи»). Без «ОК», «Готово», «Продолжить».
- Нельзя: описывать экран («Здесь показаны…», «Откройте любой: там…»), пересказывать README, объяснять внутреннее устройство
  на рабочем экране, капс, английские слова там, где есть русские.
- Подсказка (`Tip`, `title`) — не больше двух предложений: что значит элемент.

## 9. Состояния

Для каждого экрана: загрузка (скелет той же формы, не спиннер) · пусто (следующий шаг) · мало данных · ошибка · идёт работа
(карточка работы в боковой колонке + локальный статус, где уместно) · очень длинный текст (перенос, `line-clamp`, полный текст в `title`) ·
узкий экран (боковая колонка уходит в меню, таблицы теряют второстепенные колонки, главное действие остаётся).

## 10. Клавиатура

⌘K — поиск и команды везде · J/K — соседний сценарий/диалог · ←/→ — тип клиента, соседний диалог в критерии · 1/2 — «Верно»/«Неверно»
при сверке судьи · Esc — закрыть. Подсказки клавиш — рядом с действием (`Kbd`), а не в справке.

## 11. Трейсы Workshop — тот же продукт

Workshop (форк Raindrop Workshop) — инструмент внутри Agent Lab: трейсы разговоров, поиск, сохранённые, настройки, ассистент.
Он живёт в той же боковой колонке (группа «Трейсы», «Настройки» внизу), на тех же токенах, шрифтах, компонентах и по-русски.

- Компоненты — из `@/lab/ui` (`Button`, `Tabs`, `Meta`, `Badge`, `Input`, `Kbd`, `EmptyState`, `Skeleton`, `Tip`, `IconButton`, `Segmented`, `Chip`, `Panel`),
  цвета — классы `lab-*`. Константы `C` из `utils/colors.ts` уже переведены на те же значения; для inline-стилей и SVG можно,
  для нового кода — классы.
- Раскладка «список + деталь»: колонка списка 280–320 px (`border-r border-lab-line`), деталь с шапкой 56 px: заголовок, под ним факты
  (`Meta`: подпись приглушённо + значение), справа действия (secondary/ghost, одна primary при необходимости). Вкладки — `Tabs`.
- Моноширинный — только то, что является кодом: имена спанов и инструментов в дереве и таймлайне, id, JSON, модели, аргументы вызовов.
  Подписи, заголовки таблиц, кнопки, метки — обычным шрифтом, без капса («Траектория», а не `TRAJECTORY`).
- Категориальные цвета (типы спанов) — только в таймлайне и дереве спанов; ошибка — всегда `lab-bad` со знаком.
- Время и длительности — `utils/helpers.ts`: `ago` («5 мес. назад»), `fmt` («410 мс», «2,7 с»). Токены: «216 вход / 22 выход».
