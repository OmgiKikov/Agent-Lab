# Контракт продукта

Инструмент внутри банка, который проверяет ИИ-агента поддержки: цепочка блоков, у каждого свой результат.
Подробная спека: `docs/superpowers/specs/2026-09-30-agent-lab-unified-product-design.md` (§6 визуальная система, §7 честность чисел).

## Блоки (порядок в рейке и порядок работы)

| Блок | Адрес | Что показывает | Главное действие |
|---|---|---|---|
| **Агент** | `/agent` | Одна страница из трёх карточек (Подключение, Промпты и инструменты, Критерии): раскладка одна и та же в первый раз и потом, меняется только содержимое; подключение и прочитанный код открываются панелью справа (`?sources=1`); `/agent/criteria` — критерии из кода с цитатой и счётами (логи и симуляция отдельно) | «Подключить агента», «Прочитать код»; «Извлечь заново» (на странице критериев) |
| **Логи** | `/logs` | Реальные диалоги, оценённые по критериям без запуска агента: «Нарушения · Диалоги · Проверка». Первый результат | «Оценить логи»; вторично «Загрузить логи» |
| **Сценарии** | `/scenarios` | Карточки бизнес-сценариев из оценённых логов, для синтетических клиентов | «Собрать сценарии» |
| **Прогоны** | `/simulations` | Синтетические клиенты играют сценарии с агентом; трейсы прогонов | «Запустить прогон» |
| **Результаты** | `/results` | Оценка прогонов: «Нарушения · Диалоги · Проверка» по выбранному прогону (`?run=`). Другой результат, чем у логов | нет (читается) |

Настройки (`/settings`) внизу рейки: модели, ключи, ассистент, повтор. Трейсы Workshop (`/runs`, `/search`, `/saved`) остаются как есть.

## Словарь

- **критерий** — то, что агент обязан делать; цитата из его кода. Не «правило».
- **нарушение** — критерий, не выполненный хотя бы в одном диалоге стороны (логи или прогон).
- **сценарий** — карточка бизнес-сценария; **прогон** — одна игра сценариев; **результаты** — оценка прогона.
- **вердикт** — решение судьи по одному критерию в одном диалоге; «Верно / неверно» — решение человека.
- **второй судья** — вторая модель, проверяет вердикты первой.

## Оболочка и маршруты

- Рейка слева (`shell/Rail.tsx`): иконки с подсказками в порядке блоков, внизу кольцо идущей задачи и «Настройки». Бейджи: Логи = число нарушений в логах, Результаты = число нарушений последнего завершённого прогона.
- `/` ведёт в `/logs`. Старые адреса переезжают: `/problems*` → `/logs`, `/rules*` → `/agent/criteria`, `/review` → `/logs?tab=review`, `/dialogs*` → `/logs?tab=dialogs`, `/lab*` → блоки (`router.tsx`).
- Все ссылки идут через `shell/links.ts` (`LINKS`, `viewLink`) и `lab/dialogs.ts` (`dialogOf`, `dialogLink`); задачи сервиса и их блоки — `shell/jobs.ts`.
- ⌘K (`shell/CommandPalette.tsx`): блоки, нарушения логов, критерии, прогоны, сценарии, действия, которые только открывают место. ⌘J — ассистент.
- Выбранное хранится в адресе: `?tab=`, `?p=` нарушение, `?d=` диалог, `?c=` критерий, `?s=` сценарий, `?run=` прогон. J/K и стрелки листают список; на ≥1024 px первый элемент выбирается сам.
- Один вид на источник: `ProblemsView`, `DialogsView`, `ReviewView` (`source="log" | "sim"`, `runId`) живут во вкладках «Логи» и «Результаты».

## Плотность

- Как у оригинального Raindrop Workshop: шрифт Commissioner, мелкая шкала (`micro` 10 … `page` 16 px), кнопки 11 px моно.
- Никаких абзацев-объяснений: метки и числа. Одно главное действие на экран (светлая кнопка), остальное с обводкой или без.
- Один ряд управления списком: фильтр (`Menu`) и поиск в одной строке.
- Список слева, объект справа (`ui/Split`); ниже 1024 px показывается одно из двух.
- Сводка блока — одна строка `ui/Facts` (метка капсом + значение), каждый факт открывает то, из чего сложен.
- Цвет только для статуса: нарушение красный, без нарушений зелёный, не оценён / спорно жёлтый, идёт сейчас синий. Иначе монохром.

## Токены и компоненты

- Токены: `workshop/app/tailwind.config.js` (`fontSize`, цвета `lab-*` из CSS-переменных).
- `workshop/app/src/ui/`: `Button`, `Facts`, `Tabs`, `Segmented`, `Menu`, `Split`, `ListRow`, `Quote`, `Conversation`, `Drawer`, `Modal`, `EmptyState`, `Kbd`, `Label`, `toast`.
- `workshop/app/src/shell/`: `Rail`, `SectionHeader`, `Activity` (`JobStrip`), `CommandPalette`, `LabProvider` (`useLabState`), `keys` (`useKeys` по `KeyboardEvent.code`).
- Данные: `lab/problems.ts` (`useProblems`, у критерия стороны `log` и `sim`), `lab/dialogs.ts`, `lab/verdicts.ts`. Сервис — `lab/api.py`.

## Честность чисел

1. Итог со знаменателем: «N из M». Процент только рядом со счётом.
2. Логи и симуляция никогда не складываются и не сравниваются как версии.
3. «Без обнаруженных нарушений», а не «пройден»; «не оценён» — отдельное число.
4. Знаменатель критерия — диалоги, где его удалось проверить.
5. Никаких «исправлено», «лучше / хуже», порогов, уровней доверия и меток тяжести, которых нет в сервисе.
6. Любое число открывает диалоги, из которых сложено.

## Чего не делать

- Не писать «правило» в интерфейсе: «критерий».
- Не смешивать источники в одном списке, счёте или переключателе «логи / симуляция».
- Не добавлять экран или вкладку вне цепочки блоков; результат живёт в своём блоке.
- Не выводить пояснительных абзацев там, где хватает метки и числа.
- Не делать действий вне интерфейса: всё кнопкой, без CLI.
- Не вызывать модели при просмотре: чтение и навигация бесплатны.
