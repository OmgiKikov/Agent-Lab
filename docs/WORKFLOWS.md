# Рабочий цикл Agent Lab

Ниже — один поддерживаемый путь от проекта и логов до регрессионного теста. Контракты файлов и адаптера описаны в [REFERENCE.md](REFERENCE.md).

## 1. Открыть проект агента

```sh
cd /path/to/agent
agent-lab
```

В разговоре попросите проверить агента и укажите деидентифицированный JSON/JSONL. Lab читает разрешённые файлы проекта, находит точку входа, изучает материалы владельца и готовит подключение. Пустой ответ на вопрос о логах не означает согласие идти без них: нужно передать файл либо явно сказать «начать без логов».

Эквивалентный CLI-вход:

```sh
agent-lab discover --input dialogues.jsonl --task task.json
```

Первый вызов только показывает:

- сколько диалогов принято и сколько исключено по размеру;
- число порций;
- максимальное число модельных вызовов;
- общий предел времени.

Запуск начинается только после повторной команды с `--yes`:

```sh
agent-lab discover --input dialogues.jsonl --task task.json --yes
```

## 2. Принять или поправить гипотезу

Результат discovery имеет форму:

```text
ТРЕБОВАНИЕ: заявку можно считать созданной только после появления номера.
НАБЛЮДЕНИЕ: в нескольких диалогах агент подтвердил создание без номера.
ДОКАЗАТЕЛЬСТВА: dialogue_17#1, dialogue_42#3, dialogue_91#2.
ГИПОТЕЗА: при неполных данных агент выдаёт действие за выполненное.
Проверим?
```

«Да» разрешает построить именно эту проверку. Поправка владельца заменяет ошибочное ожидание до построения; отказ ничего не создаёт.

CLI:

```sh
agent-lab discover-build --id DISCOVERY_RUN
agent-lab discover-build --id DISCOVERY_RUN --yes
```

Если discovery остановился на безопасной границе:

```sh
agent-lab discover-resume --id DISCOVERY_RUN
agent-lab discover-resume --id DISCOVERY_RUN --yes
```

Первая команда снова показывает сохранённый остаток бюджета. Запись, оборванная внутри модельного вызова, намеренно не возобновляется: нельзя честно определить уже потраченный вызов.

## 3. Проверить и принять один тест

Lab показывает весь тест до исполнения: пользователя, исходный мир, ожидаемое поведение, точные проверки, рубрики и цитату требования. В этот момент тест можно поправить. После любой правки перечитайте его: hash изменился.

```sh
agent-lab accept --id TEST_RUN
agent-lab accept --id TEST_RUN --yes
```

`accept` фиксирует решение о показанном определении. Он не запускает агента, не создаёт результат и не означает, что человек уже согласился с будущим автоматическим вердиктом.

## 4. Запустить настоящего агента

```sh
agent-lab run --id TEST_RUN --yes
```

Подтверждение запуска отдельно показывает испытуемую версию, один выбранный режим пользователя, число диалогов и лимиты. Каждая попытка открывает новую `TargetSession`; внешнее состояние должно быть сброшено и подтверждено адаптером.

После запуска вывод содержит:

1. полный диалог пользователя и агента;
2. события инструментов и доступное итоговое состояние;
3. результат каждой точной проверки;
4. `pass`, `fail` или `unknown` каждой рубрики с цитатами;
5. `simulatorChecks` у реплик, к которым они относятся;
6. общий вывод и ограничения доказательств.

Если действие нельзя проверить по состоянию или событию, слова агента не заменяют доказательство и результат остаётся `unknown`.

## 5. Разобрать спорный случай

Человек не обязан размечать каждый диалог. Ручной вердикт нужен, когда:

- судья вернул `unknown`;
- автоматический вывод выглядит неверным;
- `simulatorChecks` ставят под сомнение сам тестовый диалог;
- проводится выборочный контроль качества автоматической оценки.

Ручная запись прикрепляется к конкретному диалогу и критерию, не переписывая исходный ответ, трассу или автоматическую оценку.

## 6. Сохранить регрессию

```sh
agent-lab save-suite --id TEST_RUN --output .evals/regression.json
git add .evals/regression.json
```

Сохраняйте тест после того, как его определение действительно проверяет нужное поведение. Сохранение не переносит старые результаты и не разрешает будущий запуск автоматически.

Повтор после изменения агента:

```sh
agent-lab evaluate --input .evals/regression.json --yes
```

При необходимости выберите один тест повторяемым `--case ID` и подставьте подключение текущей машины через `--connection connection.json`.

Для CI:

```sh
npm ci
npm run build
node dist/cli.js evaluate --input .evals/regression.json --yes
```

Код `0` означает решающий pass всех попыток, `1` — решающий провал агента, `2` — неполное или невалидное измерение. Каталог `.agent-lab/exports` стоит сохранять как артефакт.

## 7. Сравнить версии

```sh
agent-lab diff --before BEFORE_RUN --after AFTER_RUN
```

Сравнение сообщает конкретные `fixed` и `regressed` тесты. Если изменились тест, требования, режим пользователя, настройки или протокол судьи, результат становится `incomparable`. Невалидные и пропущенные пары перечисляются отдельно и не засчитываются как исправления.

## Критерий готовности цикла

Цикл завершён, когда можно показать непрерывную цепочку:

```text
repo + owner requirements + logs
  → повторяющееся наблюдение
  → «Проверим?»
  → один принятый тест
  → реальный TargetSession
  → диалог + автоматический вердикт + доказательства
  → необязательный ручной разбор
  → сохранение + повтор + fixed/regressed/incomparable
```

Это проверяет конкретное поведение агента. Оно не устанавливает accuracy всех пользовательских обращений и не измеряет repeatability или reliability модели-судьи.
