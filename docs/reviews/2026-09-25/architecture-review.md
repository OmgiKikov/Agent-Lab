# Agent Lab: архитектура и качество кода, 25 сентября 2026

**Вердикт: сильное доменное ядро, но новые возможности интегрируются неравномерно.** Происхождение правил, согласование изменений, неизменность принятых сценариев и доказательства вердиктов сделаны хорошо. Самый слабый участок сейчас — переход от управляемого клиента к клиенту со свободными репликами. Он изменил предпосылки выполнения, а несколько потребителей продолжают жить по старым правилам.

Это аудит текущей рабочей копии, включая изменения, существовавшие до начала проверки. Оценки относятся к подсистемам и их связям; это не утверждение о построчной проверке всех файлов. Найденные ошибки ниже отделены от пожеланий к архитектуре. Исходники продукта не изменены.

**Проверено:** `npm test` — 994 теста, 0 ошибок; `tsc -p tsconfig.check.json` — успешно; `node examples/scenario-lab-demo.mjs --verify` — 1/2 на сломанном учебном агенте, 2/2 на исправленном, исходная запись не изменилась. Дополнительно выполнены четыре локальных воспроизведения. Модели и внешние агенты не вызывались; интерактивный UX Pi и качество реальных модельных ответов не оценивались.

## Подтверждённые ошибки

**F1 · P1 · Ситуация может считаться пройденной без обязательного поворота клиента.**

В [evaluation.ts](../../../src/evaluation.ts#L258) ветка `free` при достижении `maxTurns` выставляет `stopped = true`. Это нормальное завершение, даже если обязательный `change_intent` не произошёл. Более того, `free.turned` меняется до проверки наличия места для доставки сообщения: на последнем ходе можно зарегистрировать поворот, которого агент не получил. Проверка запрета раннего `leave` внутри `customerReplyProblem` не защищает завершение по лимиту. [simulator.ts](../../../src/simulator.ts#L36) пропускает дополнительные проверки для всех современных карточек, исходя из уже неверной предпосылки, что клиент всегда говорит текстом контроллера.

Воспроизведение: карточка требует «Тогда лучше отмените покупку», `maxTurns = 2`, клиент выбирает `clarify`. Агент получает только исходный запрос и уточнение. Детерминированный судья возвращает положительные оценки обязанностей агента; `automaticTrialResult` выдаёт `pass`, обязательная отмена не была проверена. Это доказывает пропуск проверки пути, а не частоту ошибки живой модели.

Исправление: единый критерий завершения клиента, общий для обоих режимов. Лимит до выполнения обязательного пути должен означать невалидный тест. Фиксировать доставленные действия после доставки. Проверить также раннюю ветку завершения по `scenario.user.maxFollowUps`.

**F2 · P1 · Свободный клиент теряет доказательство состояния, которое сохраняет управляемый.**

[evaluation.ts:240](../../../src/evaluation.ts#L240) записывает событие `observation` только при `controlled && observesBeyondReply`. Для `free` переменная `controlled` отсутствует. Адаптер может корректно вернуть `records`, но без инструментальных событий с полем `state` в трассе не остаётся свидетельства, на которое вправе сослаться оценщик ожидания `observation: 'state'`.

Воспроизведение: один локальный адаптер возвращает `records.order.status = 'done'`, подтверждённый сброс и никаких вызовов инструментов. При управляемом клиенте: одно событие наблюдения, итог `pass`. При свободном: ноль событий наблюдения, то же конечное состояние, итог `unknown`. Оценки тестового судьи одинаково положительные.

Исправление: наблюдение состояния зависит от требований карточки и ответа адаптера, а не от способа генерации клиента. Обязателен интеграционный тест `режим клиента × канал reply/tool/state`.

**F3 · P2 · Сверка с логами не понимает события нового клиента.**

[calibration-view.ts:111](../../../src/card/calibration-view.ts#L111) извлекает только `result.decision.actionId`. Новый клиент пишет `{ protocol: 'card-customer-free-v1', move, message }`, поэтому его путь становится пустым. В [customer-moves.ts](../../../src/customer-moves.ts) уже есть обработка обоих форматов, но калибровка разбирает их независимо.

Воспроизведение на синтетической записи с расхождением оценок: одинаковая последовательность «назвал номер → ушёл» в старом формате даёт `path.same = true`; после замены только метаданных действий на новый формат — `synthetic = []`, `path.same = false`, подсказка обвиняет симулятор в дрейфе. Число совпавших вердиктов этим примером не опровергается: сломано объяснение причины расхождения.

Исправление: один версионированный декодер событий клиента. Новый протокол должен сохранять достаточно данных для сравнения фактов. Если факты неизвестны, возвращать «путь не удалось сопоставить», а не уверенное объяснение дрейфа.

**F4 · P2 · Неудачное восстановление оставляет lock живого процесса.**

В [store.ts:102](../../../src/store.ts#L102) после захвата lock у завершившегося процесса выполняется `recoverPublications()`. При ошибке `finally` удаляет только `.recovery`, новый `.lock` остаётся. В ветке первого открытия без старого lock очистка уже есть. [ExperimentLab.initialize](../../../src/experiment.ts#L53) вызывает `store.init()` до своего блока `try`, поэтому этот путь там тоже не компенсируется.

Воспроизведение: старый lock с несуществующим PID и повреждённый JSON публикации. Открытие падает, но `.lock` уже содержит PID текущего процесса. После исправления публикации повторное открытие другим объектом в том же процессе отвечает «already open». В долгоживущей сессии это мешает повторной попытке; завершение процесса или явное закрытие исходного store снимает проблему.

Исправление: единая очистка захваченного lock при любой неуспешной инициализации, сохраняя исходную ошибку. Отдельный тест восстановления с отказом после `acquire`.

Воспроизводящий скрипт: [reproduce.mjs](reproduce.mjs). Сохранённый вывод: [reproductions.jsonl](reproductions.jsonl).

```sh
node --import tsx docs/reviews/2026-09-25/reproduce.mjs
```

Скрипт использует существующие тестовые фикстуры, создаёт временный локальный адаптер и удаляет временную папку. Он выводит фактическое поведение; код выхода 0 означает успешное выполнение воспроизведений, а не отсутствие дефектов.

## Что менять первым

1. **Общий контракт исполнения клиента.** Явно выбрать режим; определить доставленный ход, завершение, обязательные действия и свидетельства независимо от способа генерации текста. Исправить F1–F3 и покрыть их сквозными тестами. Это важнее косметического дробления файлов.
2. **Очистка ресурсов и единая отмена.** Исправить F4; проверить запуск, ошибку начального checkpoint, восстановление и закрытие. Привести длительную проверку судьи к тому же механизму, что прогон и подготовка.
3. **Слой совместимости.** Читать прежние записи в их исходном виде, сохранять прежние хеши и правила подсчёта, но выдавать остальному коду нормализованное представление через адаптеры. Не переписывать исторические результаты миграцией ради красоты типов.
4. **Более узкие границы модулей.** Убрать цикл compile/checks, вынести хеширование и общие примитивы из `contracts.ts`, отделить выбор Pi runtime от лаборатории. Потом уменьшать знание внутренних стадий в CLI и Pi.
5. **Ограничить инфраструктурный долг.** Изолировать парсеры файлов, добавить недостающие пределы чтения и понятные ошибки. Изменять файловую БД только после замера реальных размеров и задержек.

Большой переписки продукт не требует. Лучшее здесь — проверяемые доменные инварианты; худшее — места, где новая возможность получает свою ветку и свои исключения, но остальные подсистемы об этом не узнают.
