# Решение о переносе на LangWatch — 27 сентября 2026

Рекомендация: использовать LangWatch как платформу и развивать нужный путь внутри неё. Хранение данных, подключение HTTP-агентов, сценарии, очереди, симуляции и просмотр результатов уже есть. Архив Agent Lab сохраняет важные наработки по критериям и проверке доказательств; поддерживать второй исполняющий движок сейчас не требуется.

Это не означает, что сам перенос доказал качество судьи, клиента или итоговой метрики.

| Блок | Что работает в текущей установке | Чего пока нельзя утверждать |
|---|---|---|
| Логи | Наборы LangWatch, импорт XLSX, сохранённый точный текст банковской выгрузки; разбор текстовых и JSON-ролей | Произвольный формат выгрузки может потребовать выбора колонок; inline CLIENT/AGENT неоднозначен, если метки входят в сам текст |
| Материалы и правила | Правила с цитатами; проверка дословности; обязательные источники закреплены в запросе судьи | Поиск статей остаётся словарным; наличие цитаты не доказывает логическое следование всего требования |
| Анализ логов | Оценка выбранных разговоров, UNKNOWN, примеры и отдельные решения владельца | Частота на выборке не равна частоте ошибок на всём трафике; нет независимой человеческой калибровки |
| Ситуации | Создаются из исходных клиентских реплик; критерии и источники отдельно от текста клиента; сохраняются в Scenarios | Извлечение скрытых фактов и реакций пока упрощено; автоматически созданная ситуация не является экспертным эталоном |
| Подключение | Локальный мост AIGW и родной HTTP target | По репликам нельзя проверить внутренние инструменты, состояние или все случаи изоляции сессий |
| Синтетический клиент | Исполнитель LangWatch Scenario ведёт многоходовой разговор | Правдоподобие клиента и отсутствие подсказок агенту требуют контрольной выборки реальных диалогов |
| Судья | Настроенная модель LangWatch и сохранённые оценки; источники правил доступны при проверке | Мнение модели не является подтверждённой истиной; согласие моделей не заменяет экспертную разметку |
| Итог | Сохраняется конкретный набор, модели и все повторы; успех, провал, технический сбой, неизвестная отправка учитываются отдельно | Нельзя обещать общий процент качества банка или доказанную причинность исправления по одной попытке |
| Ведение задачи | Один запрос автоматически запускает разбор, сбор ситуаций и native suite; состояние доступно после закрытия вкладки | Это ещё не универсальный копилот, который читает любой репозиторий и сам пишет надёжный адаптер |

## Изменения этой итерации

- Родной экран проекта получил выбор агента и повторов до запуска.
- Подготовка сама передаёт готовые ситуации в один native suite.
- Сохраняются все попытки, включая незапущенные или с неподтверждённой отправкой; техническая ошибка не превращается в ошибку агента.
- Установка исправляет подтверждение отправки в родной очереди LangWatch 3.17.0: при отказе одной команды нельзя обещать полный запуск или автоматически повторять потенциально принятую работу.
- Все записи одного разбора изменяются последовательно, чтобы два запуска не перезаписали историю друг друга.
- Исправлены обработка ролей, потеря источника правила, остановка обновления экрана до получения ссылок на прогоны и повторная блокировка при принятии карточки.

## Проверки и границы

Команды воспроизводимых проверок: `npm test`; после установки `npm run test:native-queue`. Последняя вызывает настоящий метод установленного LangWatch с отказом одной очереди, без моделей и пользовательских данных.

Сборка клиента и сервера выполняется `python3 scripts/install-native-agent-lab.py`, с отдельным каталогом сборки клиента до замены активных файлов. Полный typecheck production-дистрибутива пока не зелёный: в нём отсутствуют часть тестовых/типовых зависимостей upstream. Его нельзя выдавать за пройденный.

Официальные источники о готовой платформе: [Scenario](https://github.com/langwatch/scenario), [просмотр симуляций](https://scenario-docs.langwatch.ai/visualizations/), [оценщики сценариев](https://scenario-docs.langwatch.ai/advanced/evaluators/). Вывод о целесообразности переноса — инженерная оценка по локальному коду и проверкам, не гарантия от LangWatch.

## Наблюдаемый проход на реальном AIGW

27 сентября: один исходный разговор → план правил → три карточки (одна готовая ситуация и два неподтверждённых замечания) → один native suite → шесть сообщений → сохранённый вердикт `FAILED` с объяснением судьи. Дублирующее нажатие `/run-all` вернуло тот же batch ID. Это проверка связности процесса, а не независимая оценка точности судьи.

Первый запуск того же набора завершился `ERROR` при параллельном перезапуске worker и не был засчитан как провал агента. Повтор после обновления дошёл до оценки. Результаты доступны в локальном LangWatch; исходные банковские тексты в этот документ не копируются.
