# Сверка с prototype 2.html

7 октября 2026. Проверена текущая рабочая ветка `codex/prototype-ux-current` от `origin/master` (`93603dd7`) вместе с незакоммиченными UX-доработками.

**Вердикт: полное содержание HTML ещё не реализовано.** Сделан отдельный этап UX, а несколько функциональных сценариев прототипа остались открытыми. Предыдущее сообщение «готово» не должно было восприниматься как завершение всего прототипа.

Метод: прочитаны экраны, формы, обработчики действий и модель состояния HTML; сопоставлены с React-экранами, HTTP-командами и хранением текущего приложения. Это проверка покрытия по коду, а не новый сквозной прогон реального агента и моделей. Исходный HTML содержит имитации загрузки, генерации и оценивания; наличие его кнопок рассматривается как продуктовый сценарий, а не как готовая backend-реализация.

## Основные незакрытые сценарии

1. **Библиотека датасетов.** Два файла должны сосуществовать; пользователь выбирает один для проверки и сценариев; старые результаты продолжают ссылаться на свои данные. Нужны хранение, привязки запусков и UI выбора, не только новая таблица.
2. **Наборы правил судьи.** Несколько именованных наборов с версиями, выбор перед запуском, ручное редактирование критериев, сохранение точного снимка в результате, экспорт правил.
3. **Живые вопросы из датасета.** Самостоятельный режим воспроизведения исходных вопросов на стенде с оценкой новых ответов. Нельзя подменять его симуляцией клиента.
4. **Контекст и метаданные.** Настройка IDP, изменение имени/описания, формат версии агента для выгрузки; отдельное решение по URL репозитория и форматам CSV/JSON.

IDP — реальная интеграция: для неё нужен контракт сервиса и способ подключения. Одно поле с индексом без чтения базы не закрывает функцию.

## Что стоит сохранить из master

Конкретные цитаты и исходные диалоги; ответы людей и их влияние на итог; серьёзность ошибок; историю со снимками критериев; продолжение остановленной работы; проверку воспроизводимости в симуляциях; текущую визуальную систему и изоляцию агентов.

Несопоставимые результаты не следует усреднять. Если объединять режимы одним запуском, в отчёте нужны отдельные итоги каждого режима и корректные условия сравнения.

## Что подтверждают прежние 445 тестов

Они подтверждают работоспособность реализованного кода и регрессии текущего проекта. Они **не подтверждают**, что все сценарии HTML перенесены. Новый реальный прогон модели и агента при этой сверке не выполнялся.

## Опорные места реализации

- `frontend/src/sections/data/DataPage.tsx`, `backend/lab/flows/inputs.py::replace_export` — одна текущая выгрузка.
- `backend/lab/api/agents.py`, `backend/lab/api/agent.py::SettingsCommand` — создание/удаление агента и настройки подключения, без редактирования имени/IDP.
- `frontend/src/sections/tone/Criteria.tsx`, `backend/lab/api/tone.py` — текущие критерии, выбор, генерация и уточнение; нет CRUD списка и библиотеки наборов.
- `frontend/src/sections/simulations/PlayDialog.tsx`, `backend/lab/api/runs.py::RunCommand` — запуск сценариев; нет режима прямых вопросов из выгрузки.
- `backend/lab/agents/knowledge.py` — локальная база и обращения к инструментам, не интеграция с произвольным индексом IDP.
- `backend/lab/domain/export.py::read_export` — только XLSX/JSONL.
