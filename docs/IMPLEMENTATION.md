# Agent Lab MVP: фактический статус

**Проверено:** 2026-09-16
**Авторитетный срез:** `docs/superpowers/specs/2026-09-15-mvp-cut-design.md`

Agent Lab реализует основной цикл: читает требования и обезличенные логи, предлагает одну проверяемую гипотезу, собирает один тест, запускает подключённого агента, показывает полный диалог и основания автоматического вердикта, сохраняет принятую версию теста и повторяет её после изменения агента.

Кодовая готовность не заменяет живую проверку обещаний. P1–P3 ниже не переформулированы: если нужный прогон не был выполнен в текущем протоколе, обещание отмечено невыполненным.

## Что подтверждено кодом

- JSON/JSONL импорт не запускает целевого агента; discovery принимает до 300 диалогов и сохраняет canonical evidence.
- Coarse discovery работает пакетами, выбирает повторяющийся сигнал, представителей и контроли, затем передаёт подтверждённую гипотезу в один тест.
- Принятие теста сохраняет стабильные `testId`, `definitionHash` и `acceptedAt`; изменение определения делает acceptance устаревшим. Это метаданные, а не gate для существующих multi-test наборов.
- Запуск использует реальный `TargetSession`; результат хранит полный диалог, технический outcome, автоматический verdict и ссылки на доказательства отдельно.
- Сохранённый suite несёт исходные попытки для переносимого before/after diff даже в новом data directory.
- Ненаблюдавшееся действие не становится успехом из-за слов агента; канал `reply` допустим только для информационной цели.

## Границы

- Agent Lab не забирает логи из внешних систем сам: владелец передаёт обезличенный JSON/JSONL.
- Надёжность судьи, статистическая значимость и перенос результата на production traffic в MVP не измеряются.
- Старые исследовательские отчёты не являются доказательством P1–P3 текущего среза; инженерный контекст AIGW сохранён отдельно в [`AIGW-PILOT.md`](AIGW-PILOT.md), прочие материалы — в [`archive/`](archive/README.md).

## Проверка репозитория

Финальный фактический результат команд `npm test`, `npm run typecheck`, `npm run build` и `npm pack --dry-run --json` фиксируется в phase verification и истории коммита; этот документ не хранит быстро устаревающее число тестов.
