# Проверка агента внутри LangWatch

Пользователь поручил самостоятельно довести существующий LangWatch до рабочего процесса Agent Lab; отдельный сайт не нужен. Результат должен быть понятен по исходным разговорам, правилам, симуляциям и наблюдаемым ответам. Новая панель использует существующий DashboardLayout, Datasets, Scenarios, Suites и Simulations LangWatch.

Выбрано: расширить установленную родную интеграцию. Отдельная страница воспроизводит уже отвергнутый продукт; переписывание LangWatch или возврат движка Agent Lab дублирует готовую инфраструктуру.

Один запрос задаёт логи, материалы, задачу и при желании подключённого агента. Сервер планирует и оценивает разговоры, собирает ситуации и запускает один native suite. Режим только разбора логов остаётся доступен. Количество повторов задаётся до запуска. Прогресс и результаты переживают закрытие вкладки. Повтор запроса во время активного запуска не создаёт новые платные разговоры; неопределённый исход отправки требует сверки, не слепого повтора.

Ситуации по найденным нарушениям остаются неподтверждёнными до решения владельца. В автоматический запуск входят наблюдаемые проверки по исходным обращениям. Все применимые ожидания и их точные источники сохраняются; реплики не доказывают действия инструментов. Контекст для судьи всегда содержит источник каждого проверяемого правила. UNKNOWN не превращается в PASS или FAIL. Итог показывает выбранный набор, повторы, незапущенные/неизмеренные попытки и ограничения, без обещания точности на всём трафике.

Граница этой итерации: работающий путь и честный учёт внутри LangWatch. Независимая калибровка судьи, правдоподобия клиента и поиска знаний требуют размеченных данных; наличие функций платформы этого не доказывает. Банковские логи и ключи остаются вне Git. Сам агент не изменяется.
