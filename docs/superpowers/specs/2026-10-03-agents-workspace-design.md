# Несколько агентов: список агентов, а внутри каждого — продукт как сейчас

Дата: 2026-10-03. Решения владельца в разговоре: у каждого агента свои диалоги, правила и результаты, без общих правил
и без копирования между агентами («Не согласен с шарингом тон оф войс»); «как делают все — воркспейсы с агентами, а
внутри то, что сейчас»; дальше «делай красиво… утром гляну результат» — спека и план идут без отдельного согласования.

## Что получает человек

- **«Агенты» — первый экран.** Карточка на агента: имя, описание, итог последней проверки («78 из 92 разговоров с
  ошибкой · Tone of voice · 3 октября») или «Ещё не проверялся». Без рейтинга и сравнения: у агентов разные выгрузки и
  правила (DESIGN.md, честность 2). Кнопка «Новый агент»: имя и одна строка описания.
- **Внутри агента — всё как сейчас**: старт, обзор, диалоги, проверка, настройки. Вверху навигации — имя агента со
  стрелкой: список агентов с отметкой текущего, «Все агенты», «Новый агент».
- **Адрес содержит агента**: `/a/<id>/overview`. `/` открывает последнего открытого агента (или единственного), иначе
  список. Старые адреса без агента (`/overview`, `/logs/…`) ведут в того же агента.
- **Ваш агент эквайринга** при первом запуске становится первым агентом со всеми данными; прежний файл базы остаётся
  резервной копией рядом.

## Как устроено

- **Своя база у агента**: `data/agents/<id>/lab.sqlite3`. Реестр агентов — `data/agents.sqlite3` (id, имя, описание,
  время создания). Существующий код хранения не меняется: `store` берёт путь базы из контекста запроса
  (`store.AGENT`), без агента — прежний `data/lab.sqlite3` (тесты, импорт старых JSON).
- **Текущий агент запроса** — заголовок `X-Agent`; фронт ставит его на каждый вызов API. Без заголовка — первый агент
  реестра. Неизвестный агент — 404 «Агент не найден». Контекст переходит в фоновые задания (asyncio копирует его в
  задачу).
- **Задания по агенту**: у каждого агента своё задание; проверки разных агентов идут параллельно, каждый видит только
  своё. Общий лимит обращений к модели остаётся один.
- **API агентов** (вне агента): `GET /api/agents` — список с итогом последней проверки из базы каждого;
  `POST /api/agents {name, description}` — новый агент, id — латиница из имени (уникальная).
- **Перенос**: при старте, если реестр пуст и есть `data/lab.sqlite3`, — агент `acquiring` «Агент эквайринга» /
  «СберБизнес · чат поддержки»; база копируется через SQLite backup (безопасно с WAL), старый файл переименовывается в
  `lab.sqlite3.before-agents`.
- **Фронт**: адрес `/a/<id>` задаёт `basename` роутера, поэтому все внутренние ссылки остаются внутри агента без правок.
  Переключение агента — переход на его адрес (чистое состояние). Имя и описание агента — из реестра, а не из констант.

## Не делаем

Команды, вход и права (воркспейс как организация); удаление и переименование агента (позже, по запросу); копирование
правил между агентами; сравнение агентов.

## Проверка

Бэкенд: тесты на реестр, изоляцию данных двух агентов, перенос существующей базы, задания по агенту, 404. Фронт:
lint, build, скриншоты на копии живых данных (1440 и 390 px): список, создание агента, переключатель, обзор внутри.
`bin/check.sh` зелёный, независимое ревью ветки перед слиянием.
