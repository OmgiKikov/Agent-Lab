# Сценарий — это тест: спека

Дата: 3 октября 2026. Статус: выбран владельцем («сценарий = тест»). Меняет экран «Симуляции · Сценарии» и
`docs/DESIGN.md` («Разделы и адреса», «Словарь», «Честность чисел»).

## 1. Что было не так

- Карточка не говорила, какую ошибку она воспроизводит: только «из ошибки в диалоге».
- Результата на карточке не было: сыграл ли агент сценарий без ошибок, было видно только в матрице одного прогона.
- Ситуация — инструкция для синтетического клиента, а не описание для человека.
- «Что проверят» перечисляло одни и те же 8 критериев на каждой карточке, ни один не первый.

## 2. Решение: сценарий читается как тест ошибки, из которой он собран

**Список** (`/simulations/scenarios`, слева; на телефоне — над сценарием, как раньше):

- Строка: название; «Воспроизводит: <критерий>» (несколько — первый и «+N») или у сценария из разговора без найденной
  ошибки «Контроль: в настоящем разговоре ошибок не нашли» («…проверить не удалось», если его не удалось проверить);
  итог последнего прогона, сыгравшего сценарий, — точки по типам клиентов (красная — ошибка, зелёная — без ошибок,
  пунктир — не удалось проверить, серая — «не играли»); под ним «в прошлом прогоне» и точки прогона перед ним, если
  сценарий в нём играл. Повторявшейся строки «Tone of voice · из ошибки в диалоге» нет: проверку называет шапка.
- Над списком отбор по итогу последнего прогона: «Все · С ошибкой в последнем прогоне · Без ошибок · Не играли»
  (`?v=fail|pass|unplayed`; «Не удалось проверить», `?v=none`, — только когда такие есть). Сценарий «с ошибкой», если
  хоть один тип клиента ошибся в его последнем прогоне. «Сыграть с ошибкой» открывает «Сыграть» с этими сценариями
  (`?play=<id>,<id>…`).

**Сценарий** (справа): «из ошибки в диалоге · по критериям <проверки>», название, «Сыграть этот сценарий» (чёрная),
«Настоящий разговор, откуда он»; затем

1. «Что воспроизводит» — критерии, по которым агент ошибся в настоящем разговоре, с его словами оттуда (жёлтая
   подсветка, как у находок). У контроля — что показал настоящий разговор.
2. «Результаты» — строка на каждый прогон проверки, сыгравший сценарий, новые сверху: подпись и время прогона, по
   каждому типу клиента точка и слово (ошибка / без ошибок / не удалось проверить), у ошибки — названия критериев;
   каждая ячейка открывает этот разговор в прогоне. Не играли — «Ещё не играли» и «Сыграть этот сценарий».
3. «Клиент» — первое предложение ситуации; вся инструкция — под «Как это играет синтетический клиент».
4. «Клиент начинает так» — как было.
5. «Что проверят» — воспроизводимые критерии первыми, с пометкой «ошибка в настоящем разговоре»; остальные — под
   «и ещё N критериев».
6. «Тестовые данные» — как было.

## 3. Честность

Сценарий показывает свой итог в каждом прогоне рядом: это наблюдения, а не вывод об агенте — без «исправлено»,
«лучше / хуже», стрелок и меток. Счета прогонов по-прежнему не сравниваются. «Без ошибок» — без найденных ошибок;
«не удалось проверить» не входит ни в «с ошибкой», ни в «без ошибок». Поэтому и контроль говорит «ошибок не нашли»,
а не «ошибок не было»: сценарии из разговоров, которые не удалось проверить, тоже бывают контролем (`cards.pick`).

## 4. Данные

- Карточка из ошибки хранит `reproduces` — id критериев со статусом FAIL в строке её настоящего разговора в итоге
  проверки, в порядке строки и только тех, что карточка проверяет (критерий о состоянии систем стенд не наблюдает).
  У контроля `reproduces: []`. id карточки — по-прежнему хэш её содержимого, теперь вместе с `reproduces`.
- `GET /api/scenarios` — только чтение, модели не вызываются (`backend/lab/scenarios.py`):

  ```json
  {
    "check": "tone",
    "cards": [{
      "id": "b9d9124f3f49",
      "sourceStatus": "FAIL",
      "reproduces": [{"ruleId": "t1r1", "name": "Обращение на «вы»", "text": "…", "agentQuote": "Открой приложение…"}],
      "history": [{"run": "20261003-160034-48e03701", "label": "После правки промпта", "startedAt": "…",
                   "persona": "impatient", "attempt": 1, "status": "FAIL", "index": 6,
                   "failed": [{"ruleId": "t1r1", "name": "Обращение на «вы»"}]}]
    }]
  }
  ```

  - `cards` — в порядке колоды; без колоды — `{"check": null, "cards": []}`.
  - `sourceStatus` — итог настоящего разговора в текущем итоге проверки колоды; `null`, если его там нет.
  - `reproduces`: `name` — короткое название критерия карточки (без него — текст критерия), `text` — текст критерия,
    `agentQuote` — слова агента из строки настоящего разговора, пока по этому критерию там ошибка (иначе пусто).
    Колода, собранная до `reproduces`: критерии карточки со статусом FAIL в строке её разговора в текущем итоге; у
    контроля ничего; разговора в итоге нет — пусто.
  - `history` — законченные разговоры сценария (PASS, FAIL, UNMEASURED; идущие — нет) во всех прогонах проверки
    колоды, новые прогоны сверху, внутри прогона — в его порядке. `index` — место разговора в прогоне (ссылка
    `dialogOf({source: "sim", runId, index})`), `attempt` — повтор, `failed` — критерии со статусом FAIL с названиями
    из критериев, замороженных в разговоре.
  - Прогоны читаются целиком: итоги сценария разбросаны по разговорам всех прогонов, в сводке прогона разговоров нет.
    Для локальной Lab с десятками прогонов это допустимо.
- Экран (`frontend/src/lab/scenarios.ts`, `useScenarios`) запрашивает его снова, когда меняются колода, итог её
  проверки или любой прогон (его `revision` и статус).

## 5. Не делаем

Сравнение прогонов и вывод об агенте; общий счёт сценариев; подбор типов клиентов для «Сыграть с ошибкой» (они
выбираются в окне, как всегда); пересборку старых колод ради `reproduces` — для них работает запасной путь.

## 6. Проверка

Backend, тест на каждое изменение (сначала падает): `reproduces` у карточки и что критерий, который сценарий не
наблюдает, туда не попадает; история по сценарию, прогону и типу клиента с критериями ошибки, без идущих разговоров и
прогонов другой проверки; запасной путь старой колоды; контроль; нет колоды. Frontend: `bin/check.sh` и экраны на
подменённых данных — список, сценарий с ошибкой в последнем прогоне, контроль, который ещё не играли, телефон 390 px.
