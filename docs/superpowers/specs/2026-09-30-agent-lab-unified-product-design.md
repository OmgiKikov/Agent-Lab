# Agent Lab — единый продукт: спека дизайна

Дата: 30 сентября 2026. Статус: на ревью у владельца. Заменяет как основу для работы `docs/frontend/AGENT_LAB_DIRECTION.md`,
`docs/frontend/agent-lab-concept.html` и `docs/DESIGN.md` из ночных коммитов (5ddcebf…bd2a7de).

## 1. Зачем и для кого

**Что делаем.** Переделываем весь фронтенд — Raindrop Workshop и Agent Lab — в один продукт с одной логикой, одной навигацией и
одним визуальным языком. Не перекраска: меняется то, вокруг чего построен продукт.

**Кто смотрит.** Руководство и заказчики в банке: им продукт показывают вживую, и он должен объяснять себя сам.
Разработчик агента: работает в нём каждый день. Уровень исполнения — как у Raindrop и Braintrust. Стадия — MVP.

**Одна фраза продукта:**

> Agent Lab читает правила агента из его собственного кода и находит в разговорах места, где агент их нарушил, —
> с цитатой из кода и цитатой из разговора.

**Что продукт говорит:** какие правила агент нарушает, как часто, чем это доказано, насколько можно верить судье, откуда
взялась каждая цифра. **Чего не говорит:** что агент исправлен или стал лучше, можно ли выпускать версию, насколько ошибка
опасна для бизнеса. Агента сейчас не исправляем, поэтому в продукте нет сравнения версий, «исправлено» и вердикта релиза.

**Готово, когда:**

1. Человек, ни разу не видевший продукт, за минуту отвечает: что агент чаще всего делает не так, какое правило из его кода это
   запрещает, какими словами агента это доказано, согласен ли второй судья.
2. Экран 1440×900 без прокрутки показывает: итог одной фразой, цепочку этапов, список проблем и разбор первой из них вместе с
   доказательством.
3. От проблемы до цитаты в промпте — один клик; цитата агента видна без кликов.
4. Весь русский текст набран шрифтами продукта: ни одного глифа в запасном системном шрифте.
5. Всё, что умеет Workshop, доступно: список трейсов, поиск, сохранённые, Replay, заметки, скачивание, чат, настройки.
6. Все шесть этапов конвейера запускаются из интерфейса; прогресс и ошибка видны с любого экрана.
7. Каждое число на экране совпадает с ответом сервиса и ведёт к диалогам, из которых оно сложено.

## 2. Парадигма

**Цикл Raindrop.** Raindrop описывает работу с агентом так: Trace → Detect → Investigate → Simulate → Verify. Открытый Workshop
делает только Trace. Agent Lab добавляет Detect (судья находит нарушения в логах) и Investigate (нарушение с доказательствами),
а симулятор служит вторым источником диалогов: он находит нарушения в ситуациях, которых в логах нет. Verify появится,
когда начнём исправлять агента.

**Главный объект — проблема.** Как Issue в Raindrop: правило агента, которое нарушается в одном или многих диалогах, со
счётом и доказательствами. Продукт открывается проблемами, а не метрикой.

**Атом доверия — две цитаты.** «Промпт требует: …» (дословно из кода, файл:строка) и «Агент ответил: …» (дословно из
разговора, проверено сервисом). Между ними — объяснение судьи и мнение второго судьи. Вся композиция разбора подчинена этой паре.

**Хребет — конвейер.** Шесть этапов сервиса — не настройка, а цепочка, на которой держится каждая цифра: код → правила → логи →
оценка → сценарии → симуляция. Цепочка видна всегда (верхняя полоса), по ней продукт рассказывает о себе при показе, по ней же
проходит первый запуск.

**Принципы:**

1. **Ответ, потом доказательство, потом происхождение.** Экран сначала говорит вывод фразой, ниже — из чего он сложен,
   глубже — откуда взялись исходные данные.
2. **Каждое утверждение проверяемо в один клик.** Число ведёт к диалогам, правило — к промпту, вердикт — к разговору и трейсу.
3. **Инструмент, не дашборд.** Чёрный холст, волосяные линии, моноширинные метки капсом, табличные цифры. Без карточек в
   карточках, без декоративных графиков, без пустых графиков «на будущее».
4. **Тихо, когда хорошо; громко — только проблема.** Цвет — только смысл, и всегда вместе со знаком и словом.
5. **Неизвестное — полноценное состояние.** «Не оценён», «судьи расходятся», «нет сценариев» — с причиной и следующим шагом.
6. **Числа — только сервиса.** Интерфейс не придумывает уровней, порогов, «критично», процентов доверия. Он показывает счёты
   «N из M» с понятным знаменателем.
7. **Клавиатура везде.** Любое действие разбора доступно без мыши, и в русской раскладке тоже.
8. **Одна вещь — одно слово** (словарь ниже), и во всём продукте, включая бывшие экраны Workshop.

## 3. Словарь

| Говорим | Что это | Не говорим |
|---|---|---|
| правило | что агент обязан делать; взято из его кода дословной цитатой | критерий, контракт, rule |
| проблема | правило, которое нарушено хотя бы в одном диалоге | паттерн, issue, finding |
| нарушение | правило нарушено в одном диалоге | FAIL, провал |
| диалог | разговор клиента с агентом: из логов или из симуляции | трейс (в интерфейсе), conversation |
| логи | настоящие разговоры агента из выгрузки чата | прод, выгрузка (кроме этапа «Логи») |
| симуляция | диалог, сыгранный синтетическим клиентом с агентом | прогон как синоним диалога |
| прогон | один запуск симуляции | run, эксперимент |
| сценарий | ситуация для симулятора, собранная из диалога логов | карточка, card |
| тип клиента | манера синтетического клиента: нетерпеливый, растерянный… | персона |
| судья, второй судья | модели, выносящие вердикт по правилам | LLM-judge |
| оценка | вердикты судьи по диалогам логов | аудит, discover |
| без обнаруженных нарушений | судья нашёл выполнение и ни одного нарушения | пройден, pass, accuracy |
| не оценён | у судьи нет доказательств ни выполнения, ни нарушения | не измерено, UNMEASURED |
| верно / неверно | решение человека о вердикте судьи | review, разметка |
| трейс | технический след диалога (дерево вызовов) — только во вкладке «Трейс» | — |
| конвейер, этап | шесть шагов сервиса | подготовка, пайплайн |

**Рейка** (64 px, на всех экранах): вверху знак-капля Raindrop (ведёт на «Проблемы»), затем четыре раздела — значок и подпись
под ним, как в боковой панели Slack: подпись нужна зрителю на показе, рейка при этом узкая. Внизу — «Настройки».
Метки на пунктах: у «Проблемы» — число проблем; у «Конвейер» — кольцо прогресса, пока идёт этап, красная точка при ошибке.
Иконки lucide: `TriangleAlert`, `MessagesSquare`, `Scale`, `Workflow`, `Settings`.

**Верхняя полоса** (44 px, на всех экранах):

- слева — агент: «Агент эквайринга · СберБизнес» (имя из сервиса). Место под переключатель агентов оставлено, переключателя
  в MVP нет — агент один;
- в центре — **цепочка**: шесть звеньев конвейера со счётом результата. Звено — ссылка на свой этап. Готово — счёт; идёт —
  анимированный счёт и прогресс «42/150»; ошибка — красный знак; не начат — приглушено, а следующий шаг подсвечен словом
  («→ Загрузить логи»). Уже 1280 px звенья сжимаются до значков со счётом, уже 1024 px — в одну метку «Конвейер 6/6»;
- справа — «Найти ⌘K», «Спросить» (открывает ассистента, раздел 5.8) и точка здоровья: сервис Lab и Workshop на связи.

**Маршруты:**

| Путь | Экран |
|---|---|
| `/` | → `/problems` |
| `/problems`, `/problems/:problemId` | Проблемы, выбранная проблема (`?example=N` — пример доказательства) |
| `/dialogs`, `/dialogs/:dialogId[/rules\|/trace\|/details]` | Диалоги и выбранный диалог (без суффикса — вкладка «Разговор»); `?source=log\|sim\|traces&verdict=…&topic=…&run=…&rule=…` |
| `/dialogs/saved[/:folder]`, `/dialogs/search` | Режимы списка: сохранённые папки Workshop, поиск по трейсам |
| `/judge`, `/judge/review?queue=disputed\|all` | Судья и сверка |
| `/pipeline/:stage` | Конвейер: `agent`, `code`, `logs`, `assessment`, `scenarios`, `simulation` |
| `/settings` | Настройки |

Старые адреса перенаправляются: `/lab/*` — на новые разделы, `/runs/:id…` → `/dialogs/:id…`, `/search…` →
`/dialogs/search…`, `/saved…` → `/dialogs/saved…`. Всё состояние экрана — в адресе: ссылкой на проблему или пример можно
поделиться.

**Клавиатура.** Сочетания определяются по физической клавише (`KeyboardEvent.code`), поэтому работают в русской раскладке.

| Клавиши | Действие |
|---|---|
| ⌘K | переход и команды: разделы, проблемы, диалоги по тексту, этапы, «Оценить логи», «Сыграть сценарии» |
| ⌘J | ассистент |
| J / K, ↑ / ↓ | соседняя строка списка |
| Enter, Esc | открыть, вернуться |
| ← / → | соседний пример доказательства, соседний диалог в сверке |
| V / N | «верно» / «неверно» по вердикту на экране |
| O | открыть диалог примера целиком |
| C | скопировать разбор проблемы |
| ? | шпаргалка клавиш |

**Ширина.** ≥ 1280: рейка, список, деталь. 1024–1279: список 320 px, цепочка сжатая. < 1024: список или деталь (деталь
открывается поверх списка, «← назад»). < 640: рейка становится нижней панелью из пяти пунктов.

## 5. Экраны

### 5.1 Проблемы (главная)

Шапка на всю ширину, под ней список слева (400 px) и разбор справа. При открытии выбрана первая проблема списка, так что
доказательство видно сразу.

```text
Агент нарушает 6 из 18 своих правил                                            [Скачать отчёт]
Логи: оценено 128 из 150 диалогов · нарушения в 78 · без оценки 22    Симуляция: прогон 28.09 · 50 диалогов ▾
─────────────────────────────────────────────────────────────────────────────────────────────
[Все] [Логи] [Симуляция]   ⌕            │  разбор выбранной проблемы (5.2)
                                         │
Отправляет клиента к оператору       18  │
вместо инструкции                  из 49 │
«Не отправляй клиента в отделение…»      │
в логах 18 · в симуляции 4 · 3 темы      │
─────────────────────────────────────    │
…                                        │
```

- **Фраза-итог** собирается из данных сервиса: «Агент нарушает K из R своих правил». Если нарушений нет: «Судья не нашёл
  нарушений ни одного из R правил в 128 диалогах» — это хороший результат, а не пустой экран.
- **Строка измерения**: логи и симуляция — раздельно, со знаменателями. Симуляция — последний завершённый прогон; меню
  «▾» выбирает другой. Логи и симуляция никогда не складываются.
- **Строка проблемы**: заголовок человеческими словами (2 строки максимум); цитата правила из кода (одна строка, приглушённо);
  счёт «в логах 18 · в симуляции 4 · 3 темы». Справа крупно — число диалогов логов с нарушением, под ним «из 49» (сколько
  диалогов, где правило удалось проверить). Проблема, найденная только симулятором, стоит после проблем из логов с меткой
  «только в симуляции». Проблема из одного диалога помечена «один случай».
- **Порядок** — по числу диалогов логов с нарушением, затем по симуляции. Частота — не тяжесть: меток «критично» нет.
- **Фильтры**: Все · Логи · Симуляция; поиск по заголовку, правилу, теме.
- **Отчёт** — markdown для письма или тикета: фраза-итог, строка измерения, каждая проблема с правилом, цитатой из кода,
  счётом, одним примером и ссылкой.

### 5.2 Проблема (разбор)

Одна колонка шириной до 760 px, читается сверху вниз как аргумент: вывод → требование → доказательство → что неизвестно → что
дальше.

```text
Отправляет клиента к оператору вместо инструкции          [Воспроизвести] [Скопировать] [Спросить]
Темы: Оборудование и терминалы · Возвраты · Подключение СБП

В ЛОГАХ       В СИМУЛЯЦИИ     ВТОРОЙ СУДЬЯ             ЛЮДИ
18 из 49      4 из 12         согласен в 17 из 20      верно 2 · неверно 1

ПРОМПТ ТРЕБУЕТ                                    src/aigw_service/chain/main_idp.py:212  ↗
┃ «Не отправляй клиента в отделение, не проси звонить в банк и не перенаправляй в поддержку —
┃  всё решается либо через инструкцию, либо уточнением»
  Когда применяется: …   Что допустимо: …

ДОКАЗАТЕЛЬСТВО  1 из 22        [Логи 18] [Симуляция 4]                         ‹  ›
Лог · тема «Оборудование и терминалы» · оба судьи согласны              Открыть диалог ↗
  ┌──────────────────────────────────────────────────────────────────────────┐
  │                            Как составить заявку на возврат терминала? ▐ │
  │ Для этого ⟦обратитесь к вашему персональному менеджеру⟧① — он поможет …  │
  └──────────────────────────────────────────────────────────────────────────┘
  ① Судья: агент перенаправил клиента к менеджеру вместо инструкции по заявке.
    Второй судья (openai/gpt-5.2): согласен.
    Вердикт верный?   [✓ Верно  V]   [✕ Неверно  N]

НЕ ИЗВЕСТНО
  В 9 диалогах этих тем правило не проверено: судья не нашёл доказательств ни выполнения, ни нарушения.

ВОСПРОИЗВЕСТИ
  Из этих диалогов собрано 2 сценария симулятора.       [Сыграть на агенте: Агент на ИФТ ▾]
```

- **Заголовок** — самый частый короткий заголовок нарушения, который судья дал в этих диалогах; под ним темы.
- **Факты** — метки капсом над значениями, одной строкой. Каждый факт — ссылка: «18 из 49» открывает «Диалоги» с фильтром
  по этому правилу и источнику.
- **Промпт требует** — дословная цитата правила и путь «файл:строка». Клик открывает боковую панель с текстом источника,
  цитата в нём подсвечена и прокручена в центр. Это главный момент доверия при показе: правило не придумано, оно в коде
  агента. Ниже мелко — формулировка правила судьёй, «когда применяется», «что допустимо».
- **Доказательство** — пример за примером, как «Recommended / First / Latest» в Raindrop, только порядок по надёжности:
  подтверждено человеком → оба судьи согласны → второго судьи нет → судьи расходятся → человек сказал «неверно». У примера
  метка надёжности словами. Переключатель источника: логи или симуляция (для симуляции видны тип клиента и повтор).
  Разговор целиком, реплики до нарушения свёрнуты («ещё 3 реплики выше»), слова агента, которые процитировал судья,
  подсвечены маркером с номером ①; объяснение судьи под разговором с тем же номером. Наведение на цитату промпта
  подсвечивает цитату агента, и наоборот.
- **Вердикт верный?** — «верно» / «неверно» по этому правилу в этом диалоге; сохраняется сразу, отменяется повторным нажатием.
- **Не известно** — сколько диалогов этих тем не дали доказательств по правилу. Если таких нет, блок не показывается.
- **Воспроизвести** — сценарии симулятора, собранные из диалогов этой проблемы; кнопка запускает их на выбранном агенте
  (существующий `/api/runs` с `cardIds`), прогресс идёт в цепочке, новые диалоги появляются в доказательствах. Если
  сценариев нет — «Сценарии из этих диалогов не собраны» и ссылка на этап «Сценарии». Если нет готового агента — ссылка на
  этап «Агент».
- **Скопировать** — разбор одной проблемы в markdown: заголовок, цитата из кода с путём, счёт, пример с цитатой агента и
  объяснением судьи, ссылка на проблему.

### 5.3 Диалоги

Список слева, диалог справа. Один список для всего: диалоги логов, диалоги симуляции и любые другие трейсы Workshop.

- **Режимы списка** (переключатель над ним): «Все» · «Сохранённые» (папки Workshop, выбор папки) · «Поиск по трейсам»
  (поиск Workshop по содержимому спанов, его логика без изменений).
- **Фильтры** в режиме «Все»: источник (Логи · Симуляция · Другие трейсы), вердикт (нарушение · без обнаруженных нарушений ·
  не оценён · судьи расходятся), тема, прогон, правило; поиск по тексту первой реплики и заголовкам нарушений.
- **Строка**: знак вердикта, первая реплика клиента, под ней тема и заголовки нарушений; справа источник и дата. Для
  симуляции — тип клиента и номер повтора.
- **Диалог**: шапка — первая реплика как заголовок, метки (источник, тема, агент и версия для симуляции, тип клиента,
  дата), вердикт словом и знаком; кнопки Workshop: «Сохранить», «Повторить» (Replay), «Заметка», «Скачать», «Спросить».
  Вкладки:
  - **Разговор** — реплики с подсвеченными цитатами агента, номер у каждой цитаты;
  - **Правила** — все правила диалога: статус, объяснение, цитата, мнение второго судьи, «верно / неверно»;
  - **Трейс** — дерево вызовов и шкала времени Workshop;
  - **Детали** — метаданные и JSON.
  У трейса без Agent Lab — «Разговор» (как в Workshop), «Трейс», «Детали».
- Синяя плашка-заметка судьи, которая сейчас висит над трейсом дампом текста, уходит: её содержимое показывают вкладки
  «Разговор» и «Правила». Заметки Workshop на других трейсах остаются.

### 5.4 Судья

Страница без списка: можно ли верить оценкам.

```text
Второй судья согласен с первым в 87 из 100 диалогов логов и в 39 из 50 диалогов симуляции.
Люди проверили 3 вердикта: согласны с судьёй в 2.                              [Проверять вердикты]

СУДЬИ РАСХОДЯТСЯ  13             → список диалогов; «Проверить эти» открывает сверку по ним
ЧЕЛОВЕК НЕ СОГЛАСЕН  1           → список
ПРАВИЛА, ГДЕ СУДЬИ РАСХОДЯТСЯ ЧАЩЕ  → правило · расходятся в k из n
КТО ОЦЕНИВАЛ                    судья z-ai/glm-5.3 · второй судья openai/gpt-5.2 · клиент z-ai/glm-5.3
```

Никаких уровней доверия, порогов и «оценка предварительная»: только счёты сервиса.

**Сверка** (`/judge/review`): прогресс сверху («4 из 13 спорных»), слева разговор с подсветкой, справа правило, вердикт,
объяснение, мнение второго судьи и три действия — «Верно V», «Неверно N», «Пропустить →»; Esc — выйти. Очередь: сначала
спорные (второй судья вынес другой вердикт), потом нарушения без проверки, потом «без нарушений». Работает для логов и
симуляции одинаково.

### 5.5 Конвейер

Слева шесть этапов по порядку, справа выбранный этап. У этапа в списке: номер, название, статус знаком и словом, одна строка
результата («18 правил из 5 источников · 28.09, 04:33»), при блокировке — чего не хватает («нужны код агента и логи»).

Каждый этап справа устроен одинаково: **название и одна фраза, что он делает → вход (что берёт у предыдущих, ссылками) →
настройки → результат → главная кнопка** в правом верхнем углу («Прочитать код», «Оценить логи»…), рядом прогресс и
«Остановить», пока этап идёт. Ошибка — под шапкой: текст сервиса и «Повторить».

| # | Этап | Настройки | Результат | Кнопка |
|---|---|---|---|---|
| 1 | **Агент** — где живёт агент | адрес на ИФТ, ЕПК клиентов, путь к коду; три способа подключения (ИФТ, локальный, из исходников) | у каждого способа — «Проверить связь»: вопрос, ответ агента, время, версия | «Сохранить» |
| 2 | **Код агента** — что агент знает о себе | — | источники: промпты (файл:строка, объём) и инструменты; у каждого — сколько правил из него взято; клик открывает текст с подсвеченными цитатами правил | «Прочитать код» |
| 3 | **Логи** — настоящие разговоры | загрузка выгрузки чата (xlsx или jsonl) перетаскиванием | число диалогов, файл, дата, пять первых диалогов для проверки | «Загрузить выгрузку» |
| 4 | **Оценка логов** — судья читает разговоры | сколько диалогов оценить (5–300); «Извлечь правила заново» (иначе правила зафиксированы) | правила по источникам с цитатами и датой фиксации; темы с числом диалогов; оценено / без оценки; второй судья; ссылка «Открыть проблемы» | «Оценить логи» |
| 5 | **Сценарии** — ситуации для симулятора | — | список по темам: название, откуда («ошибка из лога» / «покрытие темы»), правил; клик — ситуация, первая реплика, правила, тестовые данные | «Собрать сценарии» |
| 6 | **Симуляция** — синтетический клиент с агентом | агент, какие сценарии (все / из ошибок / выбранные), типы клиентов, повторы 1–3 | идущий прогон: диалоги появляются по мере готовности; история прогонов, каждый открывает «Диалоги» с фильтром по нему | «Сыграть» |

Модели судьи и клиента настраиваются в «Настройках»; этапы 4–6 показывают в шапке, какой моделью работают, и ссылку туда.

### 5.6 Настройки

Разделы одной страницей: **Модели** (судья, второй судья, клиент; «Проверить модели»), **Ключи** (секреты Workshop),
**Ассистент** (Claude Code или Codex для «Спросить»), **О продукте** (адреса сервисов, версия сборки, где лежат данные).

### 5.7 Состояния

- **Первый запуск.** Пока проблем нет, «Проблемы» показывают объяснение одной фразой («Agent Lab читает правила агента из
  его кода и находит, где он нарушает их в разговорах») и шесть этапов крупно, со следующим шагом-кнопкой. С появлением
  первых проблем этот вид больше не показывается.
- **Этап идёт.** Звено цепочки анимируется (пиксельная капля Raindrop), счёт растёт; по окончании — тихое уведомление
  («Оценка готова: 6 проблем») со ссылкой.
- **Загрузка.** Скелеты по форме содержимого, без спиннеров на весь экран.
- **Сервис Lab не отвечает.** Экран с одной строкой, как запустить: `sh bin/start.sh`. Workshop не отвечает — недоступны
  только вкладки «Трейс»; остальное работает.
- **Нет данных у правила / у диалога** — «не оценён» и причина словами сервиса.

### 5.8 Ассистент

Чат Workshop («Спросить») — боковая панель справа, открывается кнопкой в верхней полосе, ⌘J или «Спросить» в разборе и
диалоге; в контекст уходит текущий диалог или пример. Плавающая плашка в углу, закрывающая содержимое, убирается. Если
на компьютере нет Claude Code или Codex, кнопка неактивна, а подсказка говорит почему.

## 6. Визуальная система

**Шрифты — с кириллицей и внутри сборки** (без сети на рабочем компьютере): Inter Variable (оптические размеры) — интерфейс и
чтение; Geist Mono Variable — метки капсом, счёты, пути, модели, JSON. Barlow, Space Mono и AlphaLyrae уходят: в них нет
кириллицы (AlphaLyrae остаётся только в латинском знаке «raindrop»). Цифры везде табличные.

**Шкала** (именованные размеры, без `text-[Npx]`):

| Имя | Размер / строка | Где |
|---|---|---|
| label | 11 / 16, моноширинный, капс, разрядка 0.08em | метки над значениями, заголовки блоков |
| meta | 12 / 16 | даты, источники, подписи |
| small | 13 / 18 | вторичный текст списков |
| body | 14 / 20 | интерфейс |
| read | 15 / 24 | реплики диалога, цитаты, объяснения судьи |
| title | 18 / 24 | заголовок проблемы в списке-детали, этапа |
| page | 22 / 28 | фраза-итог, заголовок разбора |
| count | 20 / 24, моноширинный | счёт в строке проблемы |

**Цвет.** Холст #000; поверхности по высоте: #0A0A0A (колонки списков), #111 (блоки), #18191A (наведение, всплывающее),
#212325 (выбранное). Линии — белый 6 / 10 / 16 %. Текст — холодная сталь Raindrop в пяти ступенях (#F2F5F7 заголовки и
числа … #5A6A72 самое тихое). Смысл: нарушение #F26B6B, без нарушений #60E36D, неуверенность (не оценён, судьи расходятся)
#F0AD4E, фокус и то, что идёт сейчас, #5B8DEF. Цитата судьи в словах агента — жёлтый маркер (фон 18 %, подчёркивание) с
номером. Реплика клиента — бирюзовый пузырь Raindrop #0D3442. Статус никогда не передаётся только цветом.

**Детали Raindrop, которые делают продукт узнаваемым:** моноширинные метки капсом над значениями; тонкие линии вместо рамок;
пиксельная капля и точечное поле — только в пустых состояниях, первом запуске и во время работы этапа; пузырь клиента;
вызовы инструментов — «таблетками», а не JSON; кнопки как в шапке трейса — мелкие, с обводкой, значок и слово; одна светлая
кнопка на экран — главное действие.

**Движение:** 120–160 мс, ease-out; смена содержимого детали — короткое проявление; счёты меняются анимацией цифр
(`@number-flow/react`); строки списка при пересортировке сдвигаются, а не прыгают. `prefers-reduced-motion` отключает всё,
кроме смены состояния.

**Компоненты** — один набор для всего продукта, включая экраны Workshop: `Button`, `IconButton`, `Segmented`, `Chip`,
`VerdictMark` (знак + слово), `Facts` (метки над значениями), `Quote` (цитата с источником), `Conversation` (реплики,
подсветка, номера), `Split` (список + деталь), `ListRow`, `Drawer`, `Kbd`, `Skeleton`, `EmptyState`, `Toast`, `Tip`.

## 7. Честность чисел

1. Итог — фразой со знаменателем: «нарушения в 78 из 128 оценённых». Процент — только вторично и только рядом со счётом.
2. Логи и симуляция никогда не складываются: разные выборки, разный смысл.
3. «Без обнаруженных нарушений» вместо «пройден»: сервис ставит PASS, если есть хотя бы одно выполненное правило и нет
   нарушений, даже когда остальные правила не проверены.
4. «Не оценён» — отдельное состояние с причиной; такие диалоги не входят в знаменатель и всегда названы числом.
5. Знаменатель у проблемы — диалоги, где правило удалось проверить (выполнено или нарушено), а не все диалоги.
6. Ни «исправлено», ни сравнения версий, ни «лучше / хуже»: сервис этого не считает, агента сейчас не исправляем.
7. Никаких меток тяжести, уровней доверия и порогов, которых нет в сервисе.
8. Любое число открывает диалоги, из которых оно сложено.

## 8. Данные и сервис

Судья, правила и метрика не меняются. Сервис получает четыре дополнения, чтобы интерфейсу не пришлось собирать
доказательства самому.

1. **`GET /api/problems?run=<id>`** (новый модуль `lab/problems.py`). Собирает проблемы из `discover.json`, выбранного
   прогона (по умолчанию последний завершённый) и `cards.json`. Проблема — одна нормализованная цитата правила
   (как в `discover.summarize`):

   ```json
   {
     "log": {"sampled": 150, "assessed": 128, "withViolations": 78, "unassessed": 22, "finishedAt": "…"},
     "sim": {"runId": "…", "target": "Агент из исходников", "version": "14704e1", "dialogs": 50, "withViolations": 21, "finishedAt": "…"},
     "rules": 18,
     "problems": [{
       "id": "p-3f9a1c2d0b",
       "title": "Отправляет клиента к оператору вместо инструкции",
       "rule": {"text": "…", "quote": "…", "sourceId": "s3", "origin": "src/…/main_idp.py:212", "kind": "prompt",
                "condition": "…", "acceptable": "…"},
       "topics": ["…"],
       "log": {"failed": 18, "checked": 49, "unknown": 9, "examples": ["Example…"]},
       "sim": {"failed": 4, "checked": 12, "examples": ["Example…"]},
       "secondJudge": {"checked": 20, "agree": 17},
       "human": {"agree": 2, "disagree": 1},
       "scenarioIds": ["…"]
     }]
   }
   ```

   `Example`: `source` (`log` | `sim`), `dialogueId` или `runId` + `index`, `traceId`, `opening`, `agentQuote`, `reason`,
   `second` (`agree` | `disagree` | `null`), `review`, для симуляции `persona` и `attempt`; порядок — по надёжности (5.2).
   Счёты: `failed` — диалоги, где правило нарушено; `checked` — диалоги, где правило выполнено или нарушено (для симуляции —
   в выбранном прогоне); `unknown` — диалоги тем проблемы, где по правилу нет доказательств; `secondJudge` — среди нарушений
   проблемы, у скольких второй судья проверил это правило (`checked`) и тоже счёл его нарушенным (`agree`); `human` —
   решения людей по нарушениям этого правила.
   `title` — самый частый непустой заголовок нарушения этой цитаты (сначала логи, потом симуляция), иначе текст правила.
   `id` — первые 10 знаков sha1 нормализованной цитаты: стабилен между оценками, пока правила зафиксированы.
   Правило симуляции сопоставляется с цитатой через `criteria` сценария (`ruleId` → `quote`). `scenarioIds` — сценарии,
   чей `sourceDialogueId` входит в диалоги проблемы.
2. **`GET /api/dialogues/{id}`** — диалог логов целиком: реплики из `logs.jsonl`, его вердикты по правилам, тема, второй
   судья, `traceId`. Сейчас интерфейс видит только первую реплику.
3. **`GET /api/sources/{id}`** — текст источника (`kind`, `origin`, `sha256`, `content`) для панели «Промпт требует».
4. **`POST /api/review`** — решение человека по одному правилу в одном диалоге, для логов и для симуляции:
   `{"source": "log", "dialogueId", "ruleId", "decision"}` или `{"source": "sim", "run", "index", "ruleId", "decision"}`;
   `decision` — `agree` | `disagree` | `null`. Хранится в строке правила (`review`). Старое тело `{run, index, decision}`
   (решение по диалогу целиком) продолжает приниматься и учитываться в `metric.human`.

В `GET /api/state` добавляется `logs.updatedAt` и `logs.file` (время и имя последней загруженной выгрузки).

Статусы этапов считает интерфейс из `/api/state`: `job.kind` (`sources` → 2, `discover` → 4, `cards` → 5, `run` → 6,
`rejudge` → «Судья»), наличие источников, логов, оценки, сценариев и прогонов.

## 10. Проверка

Тестов в MVP нет по решению владельца; каждый этап работ проверяется наблюдаемым поведением:

- `cd workshop/app && bun x tsc --noEmit`; `ruff check lab && ruff format --check lab`;
- сборка `sh bin/build-workshop.sh`, перезапуск, `curl` новых маршрутов сервиса на настоящих данных `data/`;
- снимки Playwright всех экранов при 1440×900, 1280×800, 1024×768 и 390×844; ошибок в консоли нет;
- шрифты: `document.fonts.check` для Inter и Geist Mono на кириллице и вычисленный шрифт текстов — без запасных;
- числа: фраза-итог и счёты проблем совпадают с `/api/problems` и `/api/state`;
- проход по сценарию показа: «Проблемы» → первая проблема → «Промпт требует» (панель с кодом) → доказательство → «Верно» →
  «Воспроизвести» (прогон идёт в цепочке, новые диалоги появляются) → «Судья» → сверка трёх вердиктов клавишами → «Конвейер»
  → «Диалоги» → трейс → поиск и сохранённые;
- клавиатура в русской раскладке: J/K, ←/→, V/N, ⌘K.

## 11. Вне рамок

Исправление агента, сравнение версий, «исправлено», вердикт релиза; несколько агентов (только место под переключатель);
статусы проблем (решена, скрыта), тревоги, динамика во времени; новая логика судьи; светлая тема; идеальная работа на
телефоне (только пригодная).

## 12. Порядок работ

1. База ветки (раздел 9) и проверка, что никакая другая сессия не пишет в ветку.
2. Сервис: `problems.py`, `/api/dialogues`, `/api/sources`, решение по правилу, поля логов.
