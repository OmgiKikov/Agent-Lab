# Agent Lab: как проверен учебный путь

Техническая запись на 24 сентября 2026 (база — коммит `fd07c33`). Она говорит, что именно проверено и как это повторить из новой копии. Это не сертификат качества модели, не измерение агента владельца и не заявление об удобстве для владельца: тесты, запуски на настоящей модели и приёмка владельцем учитываются раздельно.

## Повторить из новой копии

```sh
npm ci
npm test
npm run typecheck
npm pack --dry-run
node examples/scenario-lab-demo.mjs --verify
```

`npm test` и `npm run build` пересоздают `dist/`. Открытую сессию Pi это не ломает: расширение читает `src/` напрямую, а `dist/` нужен только бинарю `agent-lab` и этому примеру. CI (`.github/workflows/check.yml`) выполняет те же команды, кроме `--verify`, и прогоняет сохранённый набор `examples/regression-suite.json` на SQLite-агенте без ключей модели.

## Что проверяет `--verify`

Учебный путь целиком, через публичные API Lab, настоящий цикл прогона и внешнего агента-модуль в дочернем процессе ([`examples/scenario-lab-target.mjs`](../../examples/scenario-lab-target.mjs)):

1. Два вымышленных разговора о возврате оплаты импортируются как логи.
2. Из них получаются две ситуации: одна **✓ готова**, у другой **? нужен ваш ответ** — знал ли клиент номер терминала до разговора.
3. Ответ владельца записывается типизированной командой с разрешением хоста и квитанцией владельца.
4. Готовые ситуации утверждаются, их определения запечатываются хешами.
5. Прогон на намеренно сломанном агенте: он переспрашивает номер, который клиент уже назвал. Итог — 1 из 2.
6. Повтор утверждённого набора на исправленной версии агента. Итог — 2 из 2.
7. Байты исходного прогона, импорта и адаптера, а также хеш утверждённой библиотеки остаются прежними.

Результат 24 сентября, чистая копия `fd07c33`, около 2 секунд:

```json
{
  "evidenceKind": "deterministic-integration",
  "library": { "dialogues": 2, "situations": 2 },
  "ownerReceipt": true,
  "sourceUnchanged": true,
  "baseline": { "passed": 1, "decided": 2 },
  "fixed": { "passed": 2, "decided": 2 },
  "persistedLinksResolve": true
}
```

Все модельные роли примера — подготовка, карта тем, клиент и судья — детерминированные заготовки из `src/demo.ts`. Пример доказывает механику пути, а не качество модели.

Тот же пример из командной строки: `agent-lab demo` проходит его целиком и печатает итог в JSON, `agent-lab summary --id RUN` показывает его экраном: «Точность агента: 50% — справился в 1 из 2 ситуаций», строка доверия «Вероятно, от 9% до 91% (95%) · мало данных · судью ещё не проверяли» и единственная ошибка — ожидание, ответ агента и правило. Код выхода 1: зарегистрирована ошибка агента.

`node examples/scenario-lab-demo.mjs` без `--verify` создаёт новую приватную папку во временном каталоге, готовит там учебный черновик (одна ситуация готова, одна ждёт ответа) и печатает команду, которая открывает его в Pi. Рабочая `.agent-lab` проекта не затрагивается. Переменные `AGENT_LAB_PROVIDER` и `AGENT_LAB_MODEL` задают модель для той части, что идёт в Pi.

## Автоматическая проверка

На `fd07c33`: строгая проверка типов `src/` и `extensions/` чистая; 803 теста из 67 файлов, все зелёные. Тесты работают на вымышленных данных и замороженных записях прошлых форматов (`test/fixtures/`). Что именно они доказывают про доверие к числу, по инвариантам расписано в [ревью кода](../code-review-2026-09-23.md#инварианты-доверия-и-чем-они-доказаны).

Проверка типов не охватывает `test/`: tsx только транспилирует тесты. Строгий `tsc` по `test/` сейчас находит 91 ошибку типов в тестовом коде.

## Проверки на настоящей модели

Они платные, работают на вымышленных данных и запускаются только явно:

| Скрипт | Что проверяет | Статус |
|---|---|---|
| `npx tsx test/live/product-eval.ts --run [--model provider/model]` | 10 фраз владельца в свежих проектах: нужный ли инструмент вызвала модель и какое состояние осталось | На настоящей модели ещё не запускался. В CI проверяется только согласованность случаев (`test/product-eval.test.ts`). |
| `npx tsx test/live/scenario-lab.ts --run` | Путь ситуаций на настоящих ролях модели с детерминированным агентом; до 40 вызовов и 10 минут | Результатов после перехода на ситуации нет. |
| `npx tsx test/live/rag-evidence.ts --run --max-calls 13` | Разделение свидетельств RAG для судьи на заданных ответах | Последний записанный запуск — 22.09, [отчёт](../rag-evidence-audit-2026-09-22.md). |
| `node --import tsx test/live/simulator-stop.ts PROVIDER MODEL` | Остановка симулятора и его оценка; 16 вызовов, без агента | Результатов после чистки нет. |

## Чего эта запись не доказывает

- Качество модели, которая готовит ситуации, играет клиента и судит. Этому служат проверки выше и согласие владельца с судьёй в каждом прогоне.
- Точность агента владельца. Базовый прогон на его настоящем агенте и логах ещё впереди; такие данные хранятся только локально и в репозиторий не попадают.
- Удобство для владельца. Его оценивает сам владелец, а не тесты и не суррогатный участник.
