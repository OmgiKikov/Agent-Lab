# Agent Lab: проверка библиотеки сценариев

Запись технических доказательств на 20 сентября 2026. Это не сертификация генератора/оценщика и не заявление о субъективном удобстве для владельца. Тесты, реальные модельные вызовы, native Pi и пользовательская приёмка учитываются отдельно.

## Воспроизводимая проверка из новой копии

```sh
npm ci
npm test
npm run typecheck
npm pack --dry-run
node examples/scenario-lab-demo.mjs --verify
```

Сборка удаляет `dist`; если им пользуется текущий Pi, выполняйте команды в отдельной копии (команда в README). Во время этой разработки все сборки/тесты/pack запускались через локальный `snapshot.mjs` и не меняли живой `dist`. Сам локальный координатор не входит в пакет; команды выше воспроизводимы из новой копии без его файлов.

`examples/scenario-lab-demo.mjs --verify` вызывает публичные API, настоящий runner и внешний модуль в дочернем процессе. Он проверяет два вымышленных диалога → одну бизнес-группу/два варианта → цитаты → явную учебную правку владельца с квитанцией → смысловую перепроверку → принятие → четыре попытки → постоянную проблему → повтор с четырьмя ссылками на исходные оценки → две пары диагностики → отдельного кандидата → заранее сохранённую ResolutionPolicy → reproducer и регрессии → сохранённый отчёт генератора. Читаются сохранённые ссылки; байты исходного импорта, исходного прогона, адаптера и хеш принятой библиотеки остаются прежними. Итог: supports, оба решения по кандидату true. Все ответы и оценки этого примера детерминированные; модельное качество им не измерено.

`node examples/scenario-lab-demo.mjs` создаёт отдельную приватную папку и печатает Pi-команду для учебного черновика: один ready и один needs_review. Запуск проверен также через symlink пути. Данные не берутся из рабочего `.agent-lab`. Для осознанного короткого модельного прогона предусмотрен `npx tsx test/live/scenario-lab.ts --run`: 40 вызовов/10 минут, реальные настроенные роли модели, вымышленный корпус, детерминированный внешний target. Неготовые предложения остаются в черновике. Этот smoke не заменяет полный детерминированный процесс или нижеприведённые фактические модельные эксперименты.

## Native и пользовательская проверка

До финального прохода реально проверены в Pi: четыре раздела, исходные цитаты, выбор, редактирование/отмена, принятие без запуска, отмена подтверждения запуска, целевой missing_fact; stale-CAS с безопасным отказом и успешным повтором по свежей ревизии; постоянная проблема и парная диагностика; отдельный кандидат и обе оценки. Узкие 72×30 окна в светлой и тёмной темах проверялись для диагностики/кандидатов. Эти действия не были заменены рендер-тестами.

Изначальный процесс native Task 5 случайно получил слово `trust` после булевого `--approve` как prompt; сессия остановлена, расход не скрыт (экранная оценка 45k input/622 output/$0.263). Это не считается штатным проходом. Используйте `--approve` без следующего слова только при осознанном разрешении.

В финальной интеграции автоматизированно проверены native-клавиши, соответствие Enter реальному действию, блокировка запуска при изменённом выборе и реальное добавление факта через редактор с owner receipt. Независимый проход первого пути и финальное native-ревью фиксируются контроллером отдельно. Субъективное удобство владельца не объявляется проверенным по суррогатному участнику или автотестам.

## Решения, ограничения и хранение доказательств

- No-log использует существующее curated происхождение, отсутствующий batchId и imports:[]; новая фиктивная разновидность источника не вводилась. Случай без фактов полезен для правил, не требующих личных данных; новые личные значения добавляет владелец. Цена решения: некоторые сложные no-log случаи потребуют его ввода и перепроверки.
- Новые quality/admission/compiler используют реальные инварианты контроллера; сохранённая схема остаётся читаемой. Цена: ранее принятый неисполняемый набор нужно исправить в новой ревизии, его ошибочная трасса остаётся историей.
- CAS, единый writer-lock и журнал публикации сохранены. Импорты, library snapshots, issue assessments и generator reports не переписывают прошлые результаты. Чтение не получает второй writer.
- Набор может быть частичным; ограничение входа модельного задания 64 000 байт и выхода 12 000 сохраняет отклонённые источники с причинами. Unknown, invalid и неполные планы не становятся успехом.
- Корпус размечен разработчиком; качество модели, эксперта и production-популяции не следует из зелёных тестов. Синта и диагностика не маскируются под production выборку. Оптимизация — ограниченный поиск текста, не обучение весов.
- Точные отчёты, квитанции вызовов, логи gate и полный упорядоченный журнал решений хранятся контроллером локально в `.superpowers/evidence/2026-09-20-scenario-lab` (игнорируемый каталог, не часть git/пакета). Эта переносимая запись и включённый учебный harness нужны для проверки в свежем clone; приватные данные/секреты в документацию не включены.
- SQLite `ExperimentalWarning` в Node 22 относится к существующему `DatabaseSync` учебного примера, не подавлялся и не считался ошибкой.
