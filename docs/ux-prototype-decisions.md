# Что взяли из прототипа и почему

## Коротко для продукта

Сохраняем основную логику прототипа: агент → датасет → правила судьи → способы проверки → результат. Все три способа доступны в одном запуске: оценить сохранённые ответы, задать исходные вопросы живому агенту, провести симуляции клиента.

В рабочем продукте уже был сильный разбор результатов: конкретная цитата, нарушенный критерий, ответ человека, серьёзность ошибки и сценарий повторной проверки. Этот слой сохранён. Вместо замены его упрощённым отчётом прототипа добавлены недостающие возможности подготовки и запуска.

## Что доработано

- **Датасеты — отдельные объекты.** Новый файл не уничтожает предыдущий. Можно назвать, выбрать, просмотреть и убрать датасет в архив. История продолжает открывать исходные данные.
- **Правила — версионируемые наборы.** Встроенный набор можно скопировать, пользовательский — изменить. Правка создаёт новую версию. Старый запуск продолжает показывать прежние критерии.
- **Критерии редактируются до проверки.** Название, требование, условия, допустимые ответы. Можно добавить или удалить критерий и скачать точную версию правил.
- **Запуск собирается на одном экране.** Видны датасет, правила, версия/метка агента, объём и режимы. Настройки сохраняются как черновик при переходе к подключению.
- **Живые вопросы отделены от симуляций.** В первом случае повторяются реплики клиента из выгрузки. Во втором новые реплики пишет синтетический клиент. Эти способы отвечают на разные вопросы о качестве агента.
- **Ошибки выполнения отделены от ошибок агента.** Сбой соединения или отсутствие источников не превращаются в успешную оценку. Частичный результат сохраняется, остановленный запуск можно продолжить.

## Что из master оставлено сильнее прототипа

| Решение | Причина |
| --- | --- |
| Короткое создание агента: имя и описание | Endpoint, инструменты и IDP не должны мешать первой проверке готовых разговоров. |
| Отдельные критерии Tone of voice и точности | Это разные требования и разные основания оценки. |
| Нарушения с числом проверенных разговоров | Видно, на каком объёме получен результат и что не удалось оценить. |
| Отдельный итог каждого режима | Среднее старых диалогов и новых симуляций может скрыть ухудшение одного режима. |
| Цитаты, исходные диалоги, ответы людей | Результат можно проверить и оспорить. |
| История с сохранёнными доказательствами | Правки правил и новые файлы не переписывают прошлое. |
| Сценарии из ошибок, повторы и типы клиентов | Позволяют проверить исправление и устойчивость поведения. |
| Текущие Onest, светлые поверхности и общие компоненты | Новые возможности остаются частью существующего продукта. |

## Осознанные отличия

Встроенные версии правил содержат реальные требования; фиктивные номера исторических версий из демо не создавались. Новый набор можно версионировать и выбирать любую сохранённую версию.

Удаление датасета сделано архивированием с восстановлением. Это защищает связанные результаты и позволяет исправить ошибочный выбор.

Сравнение не объявляет улучшение, если поменялись критерии, судья, контекст или доказательства из базы знаний. На разных выборках результат описывает различие данных, а не автоматически улучшение агента.

Переключатель «MVP 0.1» и очистка демо не нужны в обычной работе с реальными агентами.

## Повторная проверка объединения с master

Проверка после переноса функциональности показала, что первая версия ещё оставляла конкурирующие входы в проверку и несколько собственных представлений поверх существующего интерфейса. Исправления сделаны в той же ветке на базе `93603dd7`, без замены истории и наработок master.

| Найденное расхождение | Итоговое решение |
| --- | --- |
| «Начать» из разных мест открывало разные сценарии | Обычные входы из обзора, датасетов, результатов и поиска ведут в общий запуск. |
| Семь равноправных вкладок перегружали раздел | Пять рабочих вкладок; «Новая проверка» — действие. Внутри «Критериев» разделены разбор оценок и правила для следующего запуска. |
| Смена датасета выглядела как фильтр на экране доказательств | Изменять данные можно в подготовке и библиотеке. Итоги и история показывают сохранённые данные. |
| Отчёт запуска жил отдельно от проверки | Отчёты находятся внутри Tone of voice / Точности. Старые ссылки перенаправляются; актуальный результат открывает существующий подробный разбор, прошлый — сохранённый снимок. |
| Отчёт показывал только количество ошибок | Используется существующий `StageResult`: ошибки, проверенный объём и неоценённые разговоры. |
| Каждая версия правил занимала отдельную карточку | Один блок на набор, выбор просматриваемой версии внутри него. Просмотр другой версии сам по себе не меняет правила запуска. |
| Редактор терял несохранённые изменения | Черновик сохраняется локально отдельно для агента, проверки и исходной версии; после успешного сохранения очищается. |
| Запуск обходил предложение серьёзности ошибок | Подключён существующий механизм `severity`; подтверждение человеком остаётся приоритетным. Остановка на этом этапе не запускает оставшиеся режимы. |
| Новые поля имели разрозненные стили | Общие `Input`, `Select`, `Textarea` используют токены продукта. Они применены также к существующей настройке подключения агента. |
| Панели теряли клавиатурный фокус | Общие Sheet/Modal возвращают фокус на открывшую кнопку, с сохранением специальных обработчиков. |
| Переключатели не работали стрелками | Общий Segmented поддерживает стрелки, Home/End, пропуск отключённых вариантов и одну точку входа Tab. |
| Архив показывал посторонний предпросмотр активного датасета | Архив показывает только архив; пустое состояние объясняет, что здесь будет. Предпросмотр выбранного файла расположен под рабочей библиотекой. |

Сохранены специальные инструменты master: пошаговая сборка правил из документа, проверка выбранных критериев, повторное извлечение критериев из кода, настройка повторов и типов клиентов в симуляциях. Это дополнительные сценарии с явными ссылками, а не обязательные шаги общего запуска. Короткий экран HTML не заменяет возможности подробного анализа.

### Компонентный контракт

Новые поля — нативные HTML-контролы с обычными label/aria-label, без дополнительной библиотеки форм. Цвета берутся из `design/tokens.css`, геометрия и шрифт — из текущей системы Agent Lab. Состояния: hover, focus-visible, disabled, aria-invalid. Ошибки и загрузка используют существующие LoadFailed/Skeleton; статусы — Tag. Визуальный стиль master (Onest, светлые поверхности, чёрная основная кнопка) сохранён.

### Проверка

- Полный backend: 468 тестов, включая предложение серьёзности и остановку до следующих режимов.
- Ruff, ESLint, Prettier, TypeScript и production-сборка.
- Браузер: общий запуск всех трёх режимов → существующий разбор → критерии и предложение серьёзности; старые ссылки; версии правил; восстановление черновика; возврат фокуса; переключение архива стрелками.
- Десктоп и ширина 375 px: запуск, правила, отчёт, библиотека; горизонтального переполнения нет.
- Для сквозной проверки использованы синтетические диалоги, агент и судья. Это проверка интерфейса и связности сценариев, не измерение качества реального агента. Реальный IDP/банковский стенд не проверялись.
