# Ревью кода Agent Lab и итоги чистки

Ревью и чистка — 22–24 сентября 2026. Исходная точка — снимок рабочего дерева до чистки: коммит `1e9bd6b` (ссылка `refs/snapshots/pre-cleanup-2026-09-22`). Тот же снимок лёг в историю ветки WIP-коммитом `819b776` с тем же деревом. Итог описан на `fd07c33`, последнем слиянии перед этим документом. Цифры «до» и «после» измерены одним способом на обоих деревьях. Где есть только оценка ревью, это сказано явно.

## Вердикт ревью

**Работающий MVP, который нельзя сопровождать и которому нельзя верить на слово.** Внутри продукта выросло несколько других продуктов. Главного — одного числа точности, которому можно верить, — не было: итог считался в трёх моделях результата и примерно в двадцати местах, каждое со своими правилами. Модель в чате на каждом ходу получала 30 инструментов (84,8 КБ определений) и 9 КБ инструкций, а навык Lab занимал ещё 41 КБ. Живой Pi не мог загрузить Lab. Владелец поставил задачу так: в конце должна быть метрика точности, а сейчас её нет.

**Снимок как коммит — `819b776`.** Незакоммиченное рабочее дерево закоммичено без изменений, чтобы каждый этап чистки лёг отдельным коммитом.

Исправлены три ошибки разбора текста: перевод замечаний проверки заменял части слов, реплика клиента обрезалась при удалении значения, проверка «не» ловила чужие слова.

## Что осталось

1. **Живой базовый прогон на агенте владельца.** Настоящий агент и настоящие логи, только локально. Перед прогоном владелец подтверждает, что считать базовой версией: агент как в проде, без локальных исправлений поведения, запущенный из отдельной копии, чтобы не трогать рабочую. Потом он объявляет версию агента в логах, чтобы сверка с продом была калибровкой. Какие разговоры оценивать, выбирается через `agent-lab import --where`. Это первое число, которому владелец должен поверить, и относительно него потом сравниваются улучшения.
2. **Продуктовая проверка на настоящей модели.** `test/live/product-eval.ts` (10 фраз владельца → нужный инструмент и состояние) ещё ни разу не запускался на модели. После чистки не перезапускались и `test/live/scenario-lab.ts` и `test/live/simulator-stop.ts`.
3. **Чанк G1** (идёт после этого документа, строка в таблице выше). Разделение `ExperimentLab` на модули (запись, исполнитель операций с событиями вместо опроса раз в 750 мс, библиотека, прогон, разбор) с типизированной таблицей фаз; хранилище только для хранения; CLI как таблица команд; сортировка ключей в `canonical()` без зависимости от локали — сейчас смешанные кириллица и латиница в колонках таблицы дают разные хеши на разных машинах; расчётный потолок подготовки вместо `settings.maxCalls` — согласие сейчас обещает «не больше 385 вызовов» и для 5 ситуаций; `ARCHITECTURE.md` и `STRUCTURE.md`.
4. **Незакрытое из журнала чанков.**
   - Отметки владельца на вердиктах по записанным разговорам (сверка) пока негде поставить.
   - Набор для CI не переносит объявленную версию логов.
   - Отбор разговоров по колонке есть только в командной строке, чат его не задаёт.
5. **Найдено при подготовке этого документа.**
   - Около 15 регулярок всё ещё читают человеческий или модельный текст. Совпадение заголовков статей со словами вопроса по стоп-списку (`src/scenario-sources.ts`). Цитаты «…» из обоснования судьи (`src/explain.ts`). Ссылки `#N` в заметке разбора (`src/contracts.ts`, `src/experiment.ts`). Токены значений (`VALUE_TOKEN`) и поиск скрытых значений в репликах симулятора (`src/simulator.ts`). Признак обезличивания при импорте. Старый детектор машинного формата — только для записей без `observable`. Ещё четыре — в детерминированном учебном рантайме `src/demo.ts`.
   - Тестовый код не проверяется на типы: строгий `tsc` по `test/` находит 91 ошибку, из них 41 — в `test/workflow.test.ts`.
   - Новые записи получают по умолчанию английские строки `limitations` (`src/experiment.ts`); на экраны они не выходят, но попадают в JSON-снимок.

   - Согласование в строке «Ошибок нет…: проверено 1 ситуация» (`src/result-text.ts`, `src/report.ts`).
   - Открытые технические риски — повисший дочерний процесс хука выпуска, посторонний вывод в stdout адаптера, нет общего ограничителя запросов к судье, суждение по разговору «всё или ничего», провал через отсутствие действия не фиксируется — описаны в `.planning/codebase/CONCERNS.md`.
