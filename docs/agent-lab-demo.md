# Agent Lab — шпаргалка к демо

Запуск: `sh lab/start.sh`, затем http://127.0.0.1:5899 — раздел **agent lab** в левом меню Workshop.
Судья и симулятор клиента — GLM-5.3 (z-ai), второй судья — gpt-5.2. Копия данных: `lab/data/backup-demo/`.

## Два блока

1. **Оценка логов.** Есть агент и его логи. Агент не запускается: судья читает записанные разговоры
   и проверяет их по правилам.
2. **Оценка агента.** Агент — ручка по HTTP (прод, локальный сервис) или код, который Lab запускает сам.
   Симулятор клиента разговаривает с агентом, судья проверяет разговор по критериям сценария.

## Откуда правила

`python -m lab sources --repo ~/Desktop/aigw-local` собирает источники из кода агента:
все промпты (12 штук: промпт ответа и промпты классификаторов, с путём, строкой и хэшем) и каталог
инструментов систем банка (9, из config.py и .env). Документы владельца добавляются `--file путь:prompt`
или `--file путь:knowledge` — это единственный вариант для агента, доступного только по HTTP.
Из источников выделяются правила: сейчас 18 в 7 темах, у каждого цитата. Правила фиксируются:
повторная оценка идёт по тем же правилам и темам. Новые правила — только явной кнопкой «новые правила».

Правила про инструменты («на вопрос о своей ставке агент запрашивает тариф через getLkkTariff»)
проверяются по реальным вызовам систем в разговоре. Вызовы видны на маке (заглушки их записывают);
на проде их не видно, там такие правила получают «нет данных».

## Цифры

- **Логи:** 100 разговоров, нарушения в 39%, нет данных — 21. Второй судья согласен с итогом в 87 из 100.
  Частые нарушения: перенаправление к оператору вместо ответа (19 и 15 разговоров).
- **Сценарии:** 25, у каждого свой клиент и данные в системах банка.
- **Локальный агент:** 21% (10 из 48 разговоров, 25 сценариев × 2). **Из исходников:** 20% (10 из 49).
  Код один и тот же, цифры совпали. На 50 разговорах сравнимы версии, которые отличаются больше чем
  на 10 пунктов.
- Второй судья согласен в 39 из 49–50. Спорные разговоры: фильтр «только спор судей» в прогоне.

## Проверка по базе знаний

Судья сверяет инструкции агента с тем, на что агент мог опираться: статьи базы знаний, которые он
запросил в этом разговоре (их записывает заглушка на маке), и тексты из его кода — готовые ответы
(`texts/`) и служебные сообщения (`exception/`). Провал засчитывается только за конкретное расхождение
или выдуманный шаг, раздел, срок, сумму. Если процитированные слова агента нашлись где-то в базе знаний
или в коде, вывод «выдумано» не засчитывается (стоит «нет данных» с указанием, где нашлось).
На проде запрошенные статьи не видны — там этот критерий получает «нет данных».

## Что нашли в агенте

- Передаёт разговор оператору вместо ответа (статусы 202), часто не вызвав ни одной системы.
- На вопрос о своей ставке не запрашивает тариф клиента, хотя инструмент есть (половина случаев).
- Отвечает не на тот вопрос: про термоленту на вопрос о тарифе, инструкцию покупателя на просьбу
  продавца создать QR.
- Расходится с базой знаний: говорит «нужна заявка», когда в статье есть шаги; называет «поле Все»,
  которого нет в статье (11 из 49 разговоров, в двух это единственная причина провала).
- Выдаёт клиенту внутренние инструкции для сотрудников («В ЕРМ перейди…», «сообщи размеры…»).
  Оговорка: на маке база знаний — наш поиск по тем же документам, на проде статьи могут быть другие.

## Если спросят про доверие к оценке

- Каждый вердикт подтверждён цитатой из ответа агента или названием вызванного инструмента;
  цитату проверяет код, без неё вердикт не засчитывается.
- Второй судья другого вендора проверяет каждый разговор; расхождения видны и отбираются фильтром.
- Я вручную проверил 10 разговоров: с основным судьёй согласен в 7, ещё 3 — пограничные, где судьи
  расходятся (агент сначала ответил не туда, потом исправился). Критерий «по существу» теперь
  проверяется по каждому ответу агента, а не только по последнему.
- Переоценка без запуска агента: `python -m lab rejudge` (после смены судьи или критериев).

## Не делать на демо

- Не оценивать логи заново на 100 разговорах (минут 5). Вживую — 20.
- Не нажимать «новые правила» и «собрать заново»: сломается сравнение с прошлыми прогонами.
- Workshop — наша сборка из `workshop/` (`workshop/build/raindrop`), обновляется только из репозитория.

## Если что-то сломалось

- `sh lab/start.sh` ещё раз — поднимает только то, что не работает.
- Локальный агент не отвечает: `cd ~/Desktop/aigw-local && ./local/pg.sh start`, затем
  `./local/run-mocks.sh &` и `./local/run-app.sh &`.
- Вернуть данные демо: `cp -R lab/data/backup-demo/* lab/data/`.
- Пересобрать Workshop после правок в `workshop/`: `sh lab/workshop/build.sh` (сам перезапустит сервер).

## Рабочий компьютер (прод)

`lab/.venv/bin/python -m lab bundle` → `lab/data/agent-lab-work-kit.zip`, инструкция внутри
(`lab/WORK-COMPUTER.md`): шлюз моделей по рабочим сертификатам (`~/.agent-lab/gateway.json`, как в
старом Agent Lab), `lab ping --target prod`, прогон, перенос файла на мак и «импорт прогона».
