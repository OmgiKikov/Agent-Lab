# Agent Lab — шпаргалка к демо

Запуск: `sh lab/start.sh`, затем http://127.0.0.1:5899 — раздел **agent lab** в левом меню Workshop.
Данные уже посчитаны. Копия на случай поломки: `lab/data/backup-demo/`.

## Порядок показа

**Логи.** 100 разговоров из логов, нарушения в 24%. Правила взяты из системного промпта агента,
у каждого есть цитата. Частые нарушения: агент передаёт разговор оператору вместо ответа про тариф (11)
и вместо инструкции по подключению (9). «Открыть разговор» показывает переписку в Workshop и вердикт
судьи с цитатами.

**Сценарии.** 28 сценариев: сначала разговоры с нарушениями, затем остальные темы. В каждом: первая
реплика клиента из лога, ситуация клиента, данные в системах банка (у каждого сценария свой клиент,
терминалы, тариф, операции), критерии с цитатами из промпта.

**Прогон.** Три агента: продовый (ручка ИФТ, с рабочего компьютера), локальный (сервис на этом маке,
GigaChat настоящий, системы банка на заглушках), из исходников (запускается на время прогона).
Вживую: «Локальный агент» → «прогнать 28 сценариев», 1 раз — около двух минут. Слева статусы по ходу,
любой разговор открывается в Workshop: реплики, вызовы систем банка и базы знаний, нажатые кнопки,
вердикт судьи.

**Точность.** Локальный агент: 24% (13 из 54 разговоров, 28 сценариев × 2). Из исходников: 22%
(12 из 54). Код один и тот же — разница в один разговор, цифра воспроизводится.

## Что нашли

- Агент передаёт разговор оператору (служебные статусы 202-1, 202-2), часто даже не вызвав ни одной
  системы банка. То же видно в логах прода.
- После выбора терминала кнопкой агент теряет исходный вопрос: вместо ставки отвечает
  «После оплаты терминал печатает чек».
- Отвечает не на тот вопрос: на вопрос про МСС — инструкция по разблокировке учётной записи.
- Отдаёт клиенту внутренние инструкции для сотрудников («В ЕРМ перейди в раздел…»). Оговорка:
  на маке база знаний — наш поиск по тем же документам, на проде поиск может вернуть другие статьи.

## Почему цифре можно доверять

- **Второй судья** на модели другого вендора (gpt-5.2) проверяет каждый разговор: согласен в 48 из 56
  (локальный агент) и в 50 из 56 (из исходников). Спорные разговоры помечены «спор судей».
- **Повторы:** у 23–24 из 28 сценариев одинаковый итог в обоих прогонах.
- **Цитаты:** вердикт засчитывается, только если судья привёл цитату из ответа агента и она найдена
  в тексте; иначе «нет данных».
- **Правила зафиксированы:** повторная оценка логов идёт по тем же правилам и тем же темам
  (проверено: 29 из 30 вердиктов совпали).
- **Человек:** кнопки «верно / неверно» в прогоне, итог виден на экране точности.
- Передача оператору считается нарушением правила промпта «не перенаправляй в поддержку».
  «Не измерено» (нет ответа агента или оснований для вывода) в цифру не входит.

## Не делать на демо

- Не оценивать логи заново на 100 разговорах (минут 5). Вживую — 20.
- Не нажимать «новые правила» и «собрать заново»: сломается сравнение с прошлыми прогонами.
- Не обновлять raindrop до демо: раздел встроен в интерфейс версии 0.1.21.

## Если что-то сломалось

- `sh lab/start.sh` ещё раз — поднимает только то, что не работает.
- Локальный агент не отвечает: `cd ~/Desktop/aigw-local && ./local/pg.sh start`, затем
  `./local/run-mocks.sh &` и `./local/run-app.sh &`.
- Вернуть данные демо: `cp -R lab/data/backup-demo/* lab/data/`.
- Вернуть обычный Workshop: `sh lab/workshop/restore.sh`; раздел обратно: `sh lab/workshop/build.sh`.

## Рабочий компьютер (прод)

`lab/.venv/bin/python -m lab bundle` → `lab/data/agent-lab-work-kit.zip`. Внутри инструкция
(`lab/WORK-COMPUTER.md`): установка, шлюз моделей по рабочим сертификатам (тот же
`~/.agent-lab/gateway.json`, что в старом Agent Lab), проверка ручки `lab ping --target prod`,
прогон, перенос файла на мак и «импорт прогона».
