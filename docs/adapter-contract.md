# Контракт адаптера Agent Lab

Адаптер — это тонкая прослойка между Agent Lab и вашим агентом. Lab отправляет реплику пользователя, адаптер
вызывает агента и возвращает ответ **вместе с тем, что агент при этом сделал**. Lab верит только тому, что
адаптер показал. Слова агента («я проверил», «я нашёл статью») — не событие: такое действие не засчитывается,
пока его нет в ответе адаптера.

Образцы:

- `examples/agent-oc-adapter.py` — настоящий агент (Agent OS), максимальная детализация;
- `examples/adapter-reference.mjs` и `examples/agent_lab_adapter.py` — минимальные референсы уровня 2 на TS и Python;
- `examples/echo-agent.py` — самый простой command-адаптер.

Писать адаптер к новому агенту удобно по готовому промпту `examples/ADAPTER-BUILDER-PROMPT.md`.

## Протокол

### `command`: процесс на диалог, JSON-строки

Lab запускает команду из подключения один раз на диалог и обменивается с ней строками JSON:

```
stdin  → {"type": "respond", "sessionId", "scenarioId", "initialState", "messages", "message", "choice"?}
stdout ← ответ (см. ниже), одна строка на один запрос
stdin  → {"type": "close", "sessionId"}, после чего stdin закрывается
```

- `message` — текущая реплика пользователя, `messages` — вся история диалога.
- `choice` — есть, только когда клиент нажал кнопку прошлого ответа агента: `{"index", "text", "value"?}`. `message` тогда
  равен тексту кнопки, а `value` — то значение, которое адаптер сам дал этой кнопке. Module-адаптер получает его третьим
  аргументом: `respond(message, messages, choice)`.
- `initialState` — исходное состояние карточки: `records` (скалярные поля записей), `writableFields`,
  необязательный `external` (данные тестового окружения). Применяйте его перед первым ответом.
- Ответ, не пришедший вовремя (`timeoutMs`, по умолчанию 120 с), убивает процесс. Досрочный выход
  показывается с кодом и хвостом stderr.
- После каждой строки ответа сбрасывайте буфер stdout (`flush`).

### `http`: POST на каждую реплику

Lab шлёт `POST url` с телом `{"sessionId", "scenarioId", "initialState", "messages", "message", "choice"?}`
и заголовками из `headersEnv` (значения берутся из переменных окружения и никогда не сохраняются в записи).
Ответ — тот же JSON, что у command, не больше 200 000 байт, по умолчанию за 60 с.

## Ответ

Самый простой ответ — строка: это только текст ответа, уровень 0. Полный ответ — объект:

| Поле | Тип и лимит | Что значит |
|---|---|---|
| `reply` | строка ≤ 20 000 | текст, который увидел пользователь |
| `outcome` | `reply` · `handoff` · `no_reply` | что получил клиент за этот ход: ответ (по умолчанию), передачу разговора человеку или ничего |
| `status` | строка ≤ 200 | собственный статус хода у агента («202-7»): хранится в записи, судья его не видит |
| `buttons` | ≤ 20 × `{text, value?}` | кнопки, показанные клиенту вместе с ответом; клиент нажимает кнопку, написав её текст |
| `events` | ≤ 50 × `{tool, args?, result?}` | вызовы инструментов за этот ход, в порядке выполнения |
| `eventsComplete` | bool | в `events` все вызовы хода, ни один не пропущен |
| `eventScope` | ≤ 50 имён или масок `prefix*` | полнота гарантирована только для этих инструментов |
| `retrievals` | ≤ 20 × `{source, chunkId?, content, score?}`, суммарно ≤ 60 000 символов | фрагменты базы знаний, переданные модели для этого ответа |
| `retrievalsComplete` | bool | в `retrievals` весь найденный контекст этого ответа |
| `records` | ≤ 30 записей × скалярные поля | итоговое состояние, которое агент изменил или прочитал |
| `resetConfirmed` | bool | адаптер действительно применил `initialState` к новой сессии |
| `version` | строка ≤ 200 | версия агента: сборка, коммит, хэш промпта |
| `usage` | `{calls, inputTokens, outputTokens, costUsd}` | расход модели агента за ход |
| `measurementError` | строка ≤ 2000 | ход не измерен: адаптер не смог получить нужные данные |
| `turn`, `sessionId` | число, строка | для сверки порядка ходов |

## Уровни наблюдаемости

Каждый уровень открывает свои проверки. То, что адаптер не показал, Lab не засчитывает ни как успех, ни как провал:
такая проверка не измеряется.

| Уровень | Адаптер отдаёт | Становится измеримым |
|---|---|---|
| 0 | `reply` | фразы в ответе (`answer_*`), значения эталона, рубрика «Совпадение с эталоном» |
| 1 | + `events`, `eventsComplete`, `eventScope` | вызовы инструментов (`tool_called`, `tool_not_called`, `tool_count`, `fresh_read_before_update`) |
| 2 | + `retrievals` со стабильным `source`, `retrievalsComplete` | найдена ли эталонная статья (`source_retrieved`), RAG-рубрики |
| 3 | + `records`, `resetConfirmed` | итоговое состояние (`state_equals`) |

Уровень определяет `agent_lab_connection` с `action: check`: поле `observability` в результате показывает
уровень и отдельно каждый канал (`reply`, `tools`, `retrievals`, `state`). Считается по реальным пробным
диалогам, а не по заявлению адаптера.

## Правила

1. **Флаг полноты — только когда полнота доказана кодом.** `eventsComplete`, `retrievalsComplete` и
   `resetConfirmed` ставятся, если адаптер читает полный журнал хода (лог вызовов, трейс, таблицу), а не
   «скорее всего всё». Сомневаетесь — не ставьте: Lab честно не измерит проверку, и это лучше ложного pass.
2. **`source` — стабильный id статьи**, тот же, которым асессоры размечают диалоги (`expected[].doc`).
   Не URL, не заголовок, не номер в выдаче. `chunkId` — id фрагмента внутри статьи, если он есть.
3. **Всё найденное в базе знаний — в `retrievals`**, даже если агент получил это через инструмент.
   Сам вызов инструмента поиска при этом тоже идёт в `events`.
4. **Все фрагменты хода**, а не только последнего поиска. Если их больше 20 или они не влезают в 60 000
   символов, отдайте самые релевантные и **не ставьте** `retrievalsComplete`.
5. **Новая изолированная сессия на каждый диалог.** Состояние предыдущего диалога не должно протекать в следующий.
6. **Служебный ответ — не ответ клиенту.** Если клиент за ход ничего не увидел (служебный статус, сбой генерации,
   внутренняя ошибка), отдайте `outcome: "no_reply"` и `status`, а диагностику — в `reply`. Lab сохранит её в записи,
   но клиенту не передаст: разговор завершится как «агент не дал ответа клиенту». Это показатель работоспособности
   агента, а не ошибка Lab и не провал обязанности. Передачу разговора человеку отдавайте как `outcome: "handoff"`:
   разговор завершится и будет оценён как есть.
7. **Никаких секретов и персональных данных** в `records`, `events`, `retrievals`: запись хранится в `.agent-lab`
   и попадает в отчёт.

## Типичные ошибки

| Ошибка | Последствие |
|---|---|
| `eventsComplete: true` без журнала вызовов | пропущенный вызов превращается в ложный провал `tool_called` или ложный успех `tool_not_called` |
| `source` = заголовок статьи | эталон асессора с id статьи никогда не совпадёт, проверка статьи всегда падает |
| только фрагменты последнего поиска | статья из первого поиска считается ненайденной |
| `resetConfirmed: true` без применения `initialState` | проверки состояния сравнивают с чужим состоянием |
| текст ответа вместо `reply` пишется в `records` | судья и проверки видят не то, что видел пользователь |
| служебный статус отдаётся как обычный `reply` | синтетический клиент принимает диагностику за реплику агента, судья оценивает её как ответ клиенту |
| кнопки вклеиваются в текст `reply` вместо `buttons` | нажатие кнопки не отличить от свободного текста: агент может не узнать выбор |
