# Обвязки агентов

Здесь лежит всё, что знает про конкретного проверяемого агента: как его запустить, как прочитать
его выгрузки и какие у него переменные окружения. Ядро Agent Lab (`src/`, `extensions/`) не
импортирует отсюда ничего и ни одного агента не называет. Если обвязки нет, Lab работает как
раньше: только импорт `.xlsx` скажет, что конвертера нет.

| Каталог | Агент |
|---|---|
| [acquiring](acquiring/) | агент эквайринга (aigw-local) |
| [agent-oc](agent-oc/) | SkillAgent из `agent_oc` |

## Что может быть в обвязке

**Адаптер** — процесс, который говорит с Lab по протоколу `kind: "command"`: одна JSON-строка
запроса на stdin, одна строка ответа на stdout. Эталон — [examples/echo-agent.py](../examples/echo-agent.py).
Lab запускает его по файлу подключения (`connection.json`), так что имя и место адаптера любые.

**Конвертеры выгрузок `.xlsx`** — их Lab находит сам по имени файла, когда владелец просит
в разговоре прочитать выгрузку:

- `import-dialogues.py --input X.xlsx --output Y.jsonl [--limit N] [--multi-turn-only] [--sheet S]…`
  пишет диалоги в схеме `dialogueSchema` (`src/contracts.ts`), по одному JSON в строке.
- `import-cases.py --input X.xlsx --output task.json --golden-output golden.json [--limit N] [--passing] [--sheet S]…`
  пишет задание и те же карточки массивом golden-кейсов.

Оба запускаются через `python3` из окружения, в котором запущен Lab. Код выхода не 0 означает
отказ: последняя строка stderr показывается владельцу. Если конвертеры одного вида есть у двух
обвязок, Lab спросит, чья это выгрузка.

## Что сюда класть нельзя

Репозиторий публичный. Ни адресов внутренних систем, ни сертификатов, ни идентификаторов
клиентов (ЕПК, номера договоров), ни прод-диалогов — только код и плейсхолдеры. Боевые значения
приходят из окружения агента во время запуска.
