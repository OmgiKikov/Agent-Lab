# Промпт: адаптер Agent Lab для нового агента

Скопируйте текст ниже coding-агенту (Claude Code, Pi), открытому в репозитории вашего агента.
Замените `<AGENT_LAB>` на путь к checkout Agent Lab.

---

Ты пишешь адаптер, через который Agent Lab прогоняет этого агента на тестовых диалогах и видит всё,
что агент сделал за каждый ход. Lab верит только тому, что показал адаптер: действие, о котором агент
только сказал, не засчитывается.

Прочитай полностью, прежде чем писать код:

1. `<AGENT_LAB>/docs/adapter-contract.md` — протокол, поля ответа, уровни наблюдаемости, правила полноты.
2. `<AGENT_LAB>/examples/agent-oc-adapter.py` — образец адаптера к настоящему агенту с максимальной детализацией.
3. `<AGENT_LAB>/examples/agent_lab_adapter.py` — Python-хелпер протокола. Можно импортировать его или
   скопировать: тогда пишешь только функцию `ask(session_id, request) -> Reply`.

## Порядок работы

1. **Точка входа.** Найди публичную функцию или эндпоинт, который обрабатывает одну реплику пользователя в сессии.
   Код агента не меняй: адаптер живёт отдельно, только вызывает и читает. Если без правки агента
   нужные данные не достать — остановись и опиши, что именно нужно открыть и почему.
2. **Что агент фиксирует за ход.** Найди, где в результате вызова, логах, трейсе или базе оказываются:
   - вызовы инструментов: имя, аргументы, результат;
   - найденные фрагменты базы знаний: стабильный id статьи, id фрагмента, текст, score;
   - итоговое состояние, которое агент прочитал или изменил;
   - версия агента (коммит, сборка, хэш промпта) и расход модели.
   Для каждого пункта запиши, откуда он берётся (файл и функция) и гарантированно ли там **всё** за этот ход.
3. **Отображение в контракт.** Инструменты → `events`. Фрагменты базы знаний → `retrievals`, даже если агент
   получил их через инструмент. Состояние → `records`. Каждый диалог — новая изолированная сессия
   с применённым `initialState`.
4. **Флаги полноты.** `eventsComplete`, `retrievalsComplete`, `resetConfirmed` ставь `true` только там,
   где из шага 2 следует, что показано всё. Не уверен — не ставь и объясни это в отчёте.
5. **`source` = стабильный id статьи**, тот же, которым асессоры размечают диалоги. Не заголовок и не URL.

## Чек-лист максимальной детализации

- [ ] каждый вызов инструмента за ход — с `args` и `result`, в порядке выполнения
- [ ] каждый найденный фрагмент — с `source`, `chunkId`, `content`, `score`
- [ ] `version` меняется при смене кода, промпта или модели агента
- [ ] `usage` модели агента, если он доступен
- [ ] новая сессия на диалог, `initialState` применён, `resetConfirmed` честный
- [ ] ни одного секрета или персонального значения в `records`, `events`, `retrievals`
- [ ] ошибки агента не глотаются: либо `measurementError`, либо ненулевой выход процесса с понятным stderr

## Проверка

1. Файл подключения для Lab: `{"target": {"kind": "command", "command": "python3", "args": ["<путь к адаптеру>", ...]}, "probe": {...}}`
   (формат `probe` — в `<AGENT_LAB>/examples/connection.json`).
2. В Pi: `agent_lab_connection` с `action: check`.
3. В результате поле `observability.level` должно быть ожидаемым: для RAG-агента не ниже 2
   (`retrievals: true`), для агента с действиями не ниже 1.

В отчёте владельцу укажи: откуда берётся каждое поле, какие флаги полноты стоят и почему,
какой уровень показала проверка и чего адаптер не видит.
